## 4. 真跑暴露的契约/实现问题

### A. §1.1 的符号约定自相矛盾（已实现层绕过，契约未改）

契约同时写：

- 两轮 hinge 轴均 `+y`；
- “输出列统一「前进为正」——`wheel_*_speed_radps = -qvel`、`wheel_*_torque_nm = -actuator_force`”。

在 +x 前向、+y 左向、+z 向上的右手系里，轮轴 `+y` 的正角速度让轮心向 +x 前进
（`v = ω_y R x̂`）。因此 **`qvel` 为正才是前进**，`-qvel` 是后退。两者不能同时成立。

本轮处理：`timeseries.csv` 按“前进为正”落列，取 `+qvel` / `+actuator_force`；代码里
留有注释。若按契约字面取 `-qvel`，flat 工况会以 -0.1 m/s 输出，judge 的 `slip` 与
`recover` 判据会把正常前进判成打滑/未恢复。**契约需要二选一：改轴为 `-y`，或改公式为 `+qvel`。**

证据：`scripts/run_cases.py` 的 `sample_row`；`outputs/oomwoo_s24_final/flat_r1/timeseries.csv`
中 `wheel_L_speed_radps` 与 `vel_x_mps` 同号。

### B. pair friction 的分量数写错（S24 归因更正，v1.8.3）

**上一版归因错误，已撤回。** `<pair friction>` 是生效的；真因是**分量数**：

```
<geom friction="slide spin roll">                → 3 分量
<pair friction="slide1 slide2 spin roll1 roll2"> → 5 分量
```

上一版把 geom 的 3 分量写法抄进 pair：`friction="0.8 0.005 0.0001"` 被解析成
`slide1=0.8, slide2=0.005, spin=0.0001`，滑动方向之一只有 0.005，所以切向力近乎 0。
现象（轮子只滑不滚）测得对，归因错；不是 MuJoCo 的 pair 摩擦失效。

**S24 返工（契约 v1.8.3）**：

- `scripts/obstacle.py` 撤销“摩擦下沉到 geom”的绕法；`<pair>` 保留 `friction`，并且
  必须给满 5 分量 `[slide1, slide2, spin, roll1, roll2]`；`environment.pairs[].friction`
  在 case JSON 里也按 5 分量给。
- 禁止单值/4 分量：`load_case` 与注入器都 `raise`；单值会让其余分量回落默认
  （`slide2=1.0`），看着 0.8、实际 `(0.8, 1.0)`。
- 三条断言逐接触执行：`d.contact[i].dim == 期望 condim`；
  `friction[0] == friction[1]`；`friction[0]` 等于按规则算出的期望值（有 pair 用
  `slide1`，无 pair 用两侧 geom 逐分量最大）。**真值只读 `d.contact[i].friction`**，
  不用 `model.geom_friction` 或 `model.pair_friction` 当断言依据。
- 轮-地 μ 与轮-台阶 μ 仍是两个独立 pair 值，二维扫描没有被合并。

证据：`scripts/obstacle.py`、`scripts/run_cases.py`（`build_contact_spec` /
`assert_contact_friction`）、`docs/干跑/证据/s24_assertions.txt`（基线通过；篡改
`d.contact[0].friction[0]` 后立即 raise；4 分量与非各向同性配置均被拒绝）。

### C. 20 mm 台阶是“底盘先触”，不是“轮-台阶接触”（契约触发条件缺口）

URDF 几何：轮轴在 x=0，筒身半径 0.172 m、离地 0.0125 m。20 mm 台阶高于离地间隙，
底盘前缘（x=+0.172）先于车轮接触台阶：

- 车轮-台阶 `active` 行数：**0**；
- 底盘-台阶首次接触：**t=12.648 s**，最大法向力 **25.37 N**；
- 车头前缘最终 x=0.6725 m，台阶前缘 x=0.6720 m；
- judge 因“从未轮-台阶接触”返回 `invalid / no_contact`，而不是 `bottom_out`。

这不是模型跑错，是契约把 `t_trigger` 定义成“首次轮-台阶接触”。当障碍低于离地间隙时
轮先触，高于离地间隙时底盘先触；后者在当前 judge 里永远不会进入判定窗口，`bottom_out`
形同虚设。**建议契约把 `t_trigger` 定义为“首次任一机器-台阶接触”，并保留轮触/底盘触
两个诊断标记。** 证据：`docs/干跑/证据/step_contact.txt`。

### D. 多 case 批次与 `run.json` 的单数键冲突

任务要求 `--cases cases/flat.json cases/step.json` 一个批次两个工况；契约 §3 的
`config{path,sha256}`、`scenario_xml_sha256` 是单数。本轮实现：

- `config.path` 写逗号连接的两个路径，`config.sha256` 写按顺序的连接串哈希，并加
  `config.items[]` 逐 case 明细；
- 顶层 `scenario_xml_sha256` 写两个场景哈希的连接串哈希，并加
  `scenario_xml_sha256_scope` 说明；逐 case 值在 `cases[].scenario_xml_sha256`。

这**不是契约原文**，是契约没定义多 case 批次时的最小扩展。验收若要严格单数键，需要
把批次拆成两次运行，或给契约加 `cases[]` 级别的键。证据：`run_json_keys.txt`、`run.json`。

### E. `--repeat 2` 的“逐位一致”与 `summary.csv` 的 `repeat`/`output_dir` 列冲突

契约要求同配置 `--repeat 2` 逐位一致；但 `summary.csv` 冻结列里有 `repeat` 和
`output_dir`，两行必然不同。本轮按“判定 + 关键量 + timeseries 逐位一致”执行，
并额外跑了两个独立批次证明 `summary.csv` 逐字节一致（`output_dir` 改成批次内相对路径，
否则批次 id 会让两批不同）。建议契约把这条改写成“除 `repeat`/`output_dir` 外逐位一致”。

### F. 固定 0 行程悬挂仍报 `suspension_bottom`（诊断标记噪声）

`susp_L/R` 行程设为 ±0.1 mm 的固定滑移（契约允许首版 0 行程），求解器在接触冲击下
仍出现约 3.1 mm 的瞬时越界，`suspension_bottom` 被置位。它不在 `fail_on` 默认集合里，
不影响 `passed`，但作为诊断标记已经失真。建议：0 行程固定铰时不要用
`travel >= 0.999*range` 判底，或把该标记改成“仅对真实弹簧行程有效”。

### G. `slip` 诊断在低速起步段必超 0.3

flat 的 `slip_max_L/R=0.992`：起步瞬间轮速先建立、车身尚未跟上，`|v_wheel-v_body|/v_wheel`
接近 1。它不在 `fail_on` 默认集合，故 flat 仍 `passed=1`；但若验收把 `slip` 加进
`fail_on`，所有低速工况都会“打滑失败”。这不是模型缺陷，是判据没有排除起步瞬态。

### 5.1 公开值之间的冲突（未裁决）

- **轮径 0.068 m（URDF）vs 0.0715 m（部件实测笔记）**：差 5.1%，对 20 mm 台阶是 3% 容差
  同量级。本轮按 URDF 0.068 m 建模，未擅自取 71.5 mm。
- **轮宽 0.012 m（URDF）vs 0.014 m（BOM 轮胎）**。
- **整机质量 2.9 kg 是分项加和**，没有整机称重；`lower_cylinder_mass` 是否含风机/主刷/
  线束未逐项说明。
- **z_cg 缺失**：模型用 0.04575 m 几何中心占位，台账标【缺失】；结论封顶 `mechanism`。

### 5.2 为什么没有【图纸推算】

没有可信 STEP 输入，也没有把 xacro 解析成受控输入 + 尺寸表 + 输入 sha256，因此按
v1.7.7 把公式换算值**降为【工程假设】**。A1–A3 的 `mass.assembly`/`com_B_m`/`inertia_B`
是由同一模型反算的**自洽目标**，只能证明脚本没有搬移错位，**不能证明质量属性真实**。
这一点是本次干跑最大的未覆盖面：契约 A1–A3 原本要抓 CAD 搬移错误，但没有独立
CAD/实测基线时，它退化成恒真式。
