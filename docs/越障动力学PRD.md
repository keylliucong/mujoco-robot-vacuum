# 越障动力学通用工具 PRD

**输入机型包 → 跑越障仿真 → 按适用判据逐条判定达标或不达标 → 给出最值得调整的设计变量及调整量级。**

## 用户与使用场景

| 用户 | 什么时候用 | 得到什么 |
| --- | --- | --- |
| 结构工程师、机型负责人 | 新机型首次评估。每轮改壳体、轮径、重心布置、支撑或悬挂时复算。 | 一张高度与入射角边界图、受阻机理、可比较的改型量级和优先补测项。 |
| 仿真工程师 | 首次接入机型、模型或判据变更时复跑。 | 与机型版本绑定的输入、工况、数值设置及可复现报告。 |
| 试验与评审人员 | 标定、独立验证和方案评审时使用。 | 逐条判据的依据、判定状态、适用范围、实测误差和证据等级。 |

换机型时，由提交方导出新 URDF、填写本机数据和来源，选定目标工况与判据。建模方确认拓扑受支持、坐标和单位正确、接触几何足以覆盖目标机理，再沿同一流程运行。改型时从同一基线复制出独立的配置并保留差异。几何、质量、惯量和载荷随实体设计同步更新。

工具适用于能建立有效地面接触与驱动模型的机型，接口允许不同机构和拓扑逐步接入。首轮证据来自简单轮式底盘与硬质单级门槛。扫地机结构强度、疲劳寿命、导航决策和强化学习控制各有独立验证体系。越障结果用于方案比较、补测和适用条件下的达标判断。

## 输入

**R1 · 机型与证据。** 唯一必选的 3D 主入口是一个完整装配的 URDF。用 `params.json` 提交结构引用、参数及其来源，用 `sources.md` 记录资料血缘。STEP 可选，用于补充更精确的质量属性。无 STEP 时，用 URDF 与参数表中有依据的数据。接入流程须将机型特有名称映射到运行契约，并记录用于计算的几何简化和参数。校验脚本负责第一步的格式、范围与引用检查。见[机型包规范](机型包规范.md)和 [G2 契约](契约/G2-接口契约.md)。

**R2 · 工况与判据。** 单次运行的场景与判据独立于机型包，至少记录障碍几何、高度、带符号的入射角、地面及障碍材质、接近条件、载荷配置和数值设置。首轮覆盖平地对照、正向硬质单级门槛和左右斜向门槛。台架几何、速度和判定窗口从选用的来源取得，保留生效配置。

| 判据来源 | 接入要求 |
| --- | --- |
| 标准或法规条文 | 记录文件及版本、条文定位、原文依据、适用对象与试验条件、测量量和限值。GB/T 38834.1-2020 已购买，正文尚未提供给项目，**判据来源待接入**。条文与限值待补。见[标准与法规清单](标准与法规清单.md)。 |
| 用户给出的条件 | 记录条件编号或确认记录、适用工况、观测量、单位、比较方式和限值。无法唯一解释时，将缺项列为待补，判定保留 `N-A`。 |
| 仓库已有的工程判据 | 原型回归按该次运行所引用的 G2 契约、工况和 judge 配置执行。正式试验判定使用已签署的验收限，记录版本与冻限状态。当前仓库的验收限为未冻结骨架。见 [G2 契约 §2–3](契约/G2-接口契约.md)和[试验验收限骨架][acceptance]。 |

IEC 台架资料只能在项目记录的适用条件下作为工程参考。方法有效性、产品性能和标准符合性分别按各自引用的依据报告。出处待补的判据允许保留仿真观察。见[标准与法规清单](标准与法规清单.md)和[试验验收限骨架 §3][acceptance]。

## 输出

| 需求 | 交付给使用者 |
| --- | --- |
| R3 · 判定和失败机理 | 按工况逐条列出判据编号、有效来源及版本、观测量与单位、生效限值或容差、报告中的判据状态 `criterion_status`、理由和时程证据。仅在适用条件与有效性检查满足且所需数据齐备时给 `pass` 或 `fail`。`N-A` 填原因（如无此自由度、输入缺失、超出模型适用范围、验收限未冻结）。运行层保留原始状态及原因，有效批次的受阻机理按已有规则记录，例如托底、打滑、悬挂触底、限扭失速或退回。诊断事件是否判退由所选判据决定。 |
| R4 · 可复查输出 | 保留契约的 `run.json`、`summary.csv`、`timeseries.csv` 及运行目录，附输入及产物哈希、版本、参数来源、时间步、求解器、摩擦锥、坐标系和单位。接触力从 `mj_contactForce` 读取。机器可读量沿用契约列名和单位，报告中的逐条判定可回找运行和时程。见 [G2 契约 §3–4](契约/G2-接口契约.md)和[读数校验](接触力读数校验.md)。 |
| R5 · 边界图 | 按带符号的入射角分组，标出台阶高度和每个已跑点的判定或可用的机理观察。标清通过、失败、不可判、无效和未覆盖区，注明障碍形状、速度、材料、载荷、样本和时步。机理图按 `cleared`、`blocked`、`invalid` 呈现，排版见试验骨架的分图规则。有效观察与无效批次分别计数。只有适用范围内的有效点夹出边界时才标区间，保留通过与失败端点。见[试验验收限骨架 §5.2][acceptance]。 |
| R6 · 可信度和验证 | 逐结论标 `mechanism`（机理）、`sensitivity`（敏感性）或 `quantitative`（定量），同时附生效参数来源与需要的容差。定量按契约的实测、逐行校核和不确定度规则放行。另记是否已用独立留出集验证、覆盖了哪些工况及实际误差。只有实机独立验证覆盖的范围可用于对应机型的实机性能结论。见 [G2 契约 §4、§6](契约/G2-接口契约.md)和[试验验收限骨架 §1–2][acceptance]。 |
| 优化建议 | 给按收益排序的候选变量、当前值、建议调整量、边界预计变化与不确定度、适用工况及待做的复核。参数不足或影响无法分辨时，给出需要补测或建模的变量。 |

| 术语 | 字段与取值 |
| --- | --- |
| 运行有效性 | `summary.csv.status` 只取契约的 `ok`、`invalid`、`diverged`。`invalid` 只沿用生效契约已有的原因枚举，附属试验原因记录在报告或契约允许的诊断位置。 |
| 判据状态 | 报告中的 `criterion_status` 逐条取 `pass`、`fail`、`N-A`，理由另写。判据状态不得写入 `summary.csv.status`。`summary.csv.passed` 沿用契约的原有语义。 |

运行观察、逐条判定和结论等级各自保留。比如仿真观察到越过、但标准条文待接入时，可报告 `cleared` 及其条件，标准判定为 `N-A`。模型越界或运行无效时，图中标明原因，原始记录继续可查。通过率分母沿用契约。整批达标结论的汇总规则由所选判据来源提供。见 [G2 契约 §3](契约/G2-接口契约.md)和[试验验收限骨架 §1][acceptance]。

报告的数值列记录数值和单位，单位沿用契约，例如高度用 `height_m`、角度用 `heading_deg`。边界分别存通过端和失败端数值，缺端点留空并附原因。逐条判定与优化建议通过 `case_id` 和配置标识引用原始输出，图面可用 mm 显示高度及改型收益。

## 范围边界

本 PRD 将准静态方法有效性条件编号为 `T-A1` 至 `T-A4`，依次对应[试验验收限骨架 §5][acceptance]的 A1 至 A4。模型自检沿用 [G2 契约 §1.1](契约/G2-接口契约.md)的 A1 至 A5。编号映射供引用，阈值和适用条件以各自的来源文件为准。

| 情形 | 本轮可用范围和理由 |
| --- | --- |
| OOMWOO 简化试跑模型的 `h > 12.5 mm` | 该模型的壳体前下缘倒角、保险杠柔性和从动支撑抬升未建模，高台阶先碰壳体或从动支撑。相关数据仅说明缺失机理的位置，不能支持该机型的通过或失败判定。12.5 mm 是此次模型覆盖边界。见[全流程试跑 §4.3、§10][pilot]。 |
| 无悬挂机型的 `T-A2` | `T-A2` 检查悬挂准静态条件。无此自由度时判据状态为 `N-A`，原因记「无此自由度」。有悬挂但行程或位移不可测时，判据状态为 `N-A`，试验批次按验收限骨架判无效，原因记「不可测」。见 [ADR-013](契约/ADR/ADR-013-能力声明-机型可以不具有某自由度.md)和[试验验收限骨架 §5][acceptance]。 |
| 刚性配重复现带载 | 配重复现质量与质心，真实尘水的附加惯量本轮未复现。配重数据只在相应准静态条件下作下界观察。冲击峰值、接触力时程和翻越瞬态缺少有效的惯量依据。见[试验验收限骨架 §4][acceptance]和[决策记录 D-02、D-07][decisions]。 |
| 未标定接触或步长变化会翻转结果 | 静置接触力读数校验覆盖两种摩擦锥，整机冲击需要另外验证。基线原型已有时步改变后结果翻转的记录。瞬态峰值用于同配置观测，临界结果注明数值敏感性。见[读数校验 §7](接触力读数校验.md)和 [G2 运行记录 §6、§9][g2]。 |
| 超出已建模的机构、场景与物理 | 软地毯、多级台阶、主动抬升控制或斜面静置需要专门场景和控制、接触或材料模型，当前回归证据覆盖平地与单级硬质门槛。结构强度、疲劳寿命需要材料模型和独立验证。见[实施计划](superpowers/plans/2026-11-21-obstacle-dynamics.md)、[基准工况](基准工况与数据缺口.md)和[全流程试跑 §7][pilot]。 |
| 证据待补 | GB/T 38834.1-2020 正文、机型实测输入、不确定度刻度和独立验证数据按各自工况待补。现有 OOMWOO 试跑为机理级，不能把公开参考和工程假设外推为本机能力。见[全流程试跑 §10][pilot]和[试验验收限骨架 §1][acceptance]。 |

## 优化回路的接口

本轮定义输入与输出。后续按已运行且有效的扫描结果生成建议。

1. **给定基线。** 输入 `machine_id`、`payload_state`、`config_id`、模型和参数版本、判据来源、目标工况或目标边界。每个候选变量以生效参数台账的 `param_id` 标识，带基线值、单位、可制造区间、候选点、区间来源及其牵连的几何或质量参数。改型配置的行按其自身分组登记，报告引用基线及改型的台账行。对照同一载荷、障碍、接近条件和数值设置。
2. **先扫工况，再扫设计。** 高度和带符号的入射角构成边界网格。按现有扫描设计优先检查地面和门槛摩擦、轮端限扭、质心高度，并按机型逐步比较轮半径、支撑位置、轮距、质量及适用的悬挂行程、刚度和阻尼。质心前后位置、底壳外形和最低点可以作为改型输入，取试跑暴露的接触机理和本机可制造区间确定档位，涉及质心、轮轴或外形的变化同步重算牵连的几何和质量属性。速度、摩擦和载荷用作工况分层或稳健性对照。优先单因素定位，对已有证据显示交互的组合再复核。见[扫描设计 §2–3][scan]和[全流程试跑 §4.3、§7][pilot]。
3. **输出可比较的敏感度。** 每行带变量的 `param_id` 及单位、低/高点、基线与候选值、带符号入射角、`h_pass` 两端边界区间、`Δh_pass,range = h_pass(高点) − h_pass(低点)`（mm）、是否翻转、工况与结果引用、等级及可用性原因。只有有效工况支持边界定位时给该差值。机理级探索的计算边界只用于同模型、同工况对比，报告沿用适用的试验措辞。出现未夹住、结果非单调、数值翻转或超出模型范围时，保留采样点及原因，差值待补。见[扫描设计 §3–6][scan]。
4. **排序并形成建议。** 对变化单位相同的变量，在相同工况和载荷下按 `Δh_pass,range / (x_hi − x_lo)` 排序，注明复合单位，保留正负方向。区间宽度须大于零。对不同单位的变量，只有在相对基线采用相同的可制造变动档位、且基线非零时才联合排序，此时按 `Δh_pass,range / ((x_hi − x_lo) / |x_base|)` 排序。条件不足时分组呈现。绝对 `Δh_pass,range` 留作参考列。建议以基线到候选的边界增量除以变动幅度（取正的绝对幅度），在同一可比组内比较收益。允许在试过的方向上减小变量。报告注明目标工况、建议改变量、预计收益及区间、等级、牵连部件和复核项目。分辨率或不确定度无法区分时标为待复核。OOMWOO 冻结扫描稿记录当时的区间差排序，本 PRD 的通用建议采用上述排序键。见[扫描设计 §4][scan]。
5. **复算改型。** 示例句式为「在［载荷、材料、角度和速度］下，把轮径从 71.6 mm 增到 76 mm，计算的 `h_pass` 提升［X］mm（［区间］，等级［等级］）。复核［边界两侧工况］。」轮径数字是句式示例，X 待扫描。将候选配置重新提交，复跑目标、相邻及可能退化的工况，留下基线与改型的差异。实机用途按 G4–G6 对应证据放行。

扫描表与敏感度表作为报告产物交付，通过 `case_id`、`config_id` 和 `param_id` 引用既有证据。两张表的字段不得进入 `summary.csv` 或成为运行契约输出。
