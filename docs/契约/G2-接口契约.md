## 0. 一句话分工

MJCF 说「机器长什么样」，case JSON 说「这次跑什么」，入口脚本说「怎么跑、怎么判、怎么记」。三者只通过两张表通信：**名称表**（§1）和**字段表**（§2–§3）。

## 1. 三类契约的归属

| 契约 | 拥有什么 | 冻结（改名=破坏契约） | 允许改动 |
|---|---|---|---|
| `models/baseline.xml` | 机器人本体：几何、质量/惯量、关节、执行器、接触参数、`solref`/`solimp` | 下表全部名称；`gear=1`（执行器力即轮端 N·m） | 数值（须有溯源台账行）；新增 body/geom（前缀规则） |
| `cases/*.json` | 单次运行的场景、数值、判定阈值 | `schema_version`、字段名、单位 | 数值；新增 `.json` 文件 |
| `scripts/run_cases.py`（+`judge.py`、`obstacle.py`） | 流程、台阶注入、判定、落盘 | CLI 参数、输出文件名与列名 | 内部实现 |

**名称表**（runner 只准 `mj_name2id` 按名字取，禁止整数索引）：

| 类别 | 名字 | 语义 |
|---|---|---|
| body | `chassis` | 机身；整机位姿从 `mjData.xpos/xquat[chassis]` 取 |
| body | `wheel_L` / `wheel_R` | 左右驱动轮（轮体，含轮胎几何） |
| joint | `wheel_L_spin` / `wheel_R_spin` | 驱动轮转轴，`hinge`，轴 `+y`（正方向换算见 §1.1） |
| joint | `susp_L` / `susp_R` | 被动悬挂铰/滑移（首版可为 0 行程的固定铰） |
| actuator | `wheel_L` / `wheel_R` | 力矩执行器，`gear=1`，`forcerange=-T..+T`（N·m，轮端） |
| geom 前缀 | `chassis_*` | 机身几何（托底与最低点按此前缀统计） |
| geom 前缀 | `wheel_L_*` / `wheel_R_*` | 轮胎几何 |
| material | `floor` / `step` | 接触对材质名（见 §2 `environment.pairs`） |

### 1.1 机体系 B 与模型基准系（v1.1 新增）

- **B 的正式定义**：原点 O = 左右驱动轮轴心连线中点在地面上的投影（地面 = B 的 `z=0` 平面）；`+x` 前向（车头）、`+y` 左向、`+z` 向上，右手系。
- **B 就是 MJCF 的 world 与 `chassis` 局部系**：`chassis` 在 world 中恒为 `pos="0 0 0" quat="1 0 0 0"`；world 与 B 在 `t=0` 重合。台阶注入、位姿输出、接触力分量全在这一个系里，不引入第四套系，也不靠 body 初值偏移「摆正」。
- **CAD 全局系只用于推导一次**：`cad_to_B = {yaw_deg, origin_B_m}` 落成台账三行（`frame.cad_to_B.*`，label=`图纸推算`）；XML 里每个 `<body>`/`<geom>`/`<inertial>` 的位置已经是 B 中的值，**XML 内不出现 CAD 全局系**。
- **必须报在 B 中的量**：所有 body/geom 的 pos/quat 与尺寸；`chassis/inertial` 的 pos 与 `fullinertia`（关于质心，主轴按 B）；总质量（标量）；CoM 在 B 的位置（台账 `com_B_m`，运行记录 `com_offset_B_m`）；台阶前缘位置与 heading ψ（B 的 xy 平面）。
- **正方向一次定死**：两轮 hinge 轴均 `+y`（右手系约定，便于与 CAD 对照）；因前进 `+x` 对应绕 `+y` 的负角速度，输出列统一「前进为正」——`wheel_*_speed_radps = -qvel`、`wheel_*_torque_nm = -actuator_force`。`susp_*_travel_m` 压缩为正（轮心相对机身沿 `+z_B` 位移）；接触力分量按 geom1→geom2 为正。
- **模型自检断言（违反即失败，S16）**：

| 断言 | 内容 | 容差 |
|---|---|---|
| A1 | 各 body 质量之和 = 台账 `mass_assembly`（含未建模余量行） | ≤1% |
| A2 | 由 geom/body 算出的整机 CoM = 台账 `com_B_m` | ≤1 mm |
| A3 | 各 body 惯量平行轴搬移到 B 原点后 = 台账 `inertia_B` | ≤2% |
| A4 | 两轮轴心 `(x,y)` 关于 O 对称、`z=R` | ≤1 mm |
| A5 | `chassis` 的 world 位姿恒为单位位姿 | 精确 |

A1–A3 是「CAD 搬移错位」唯一能自动抓住的地方：偏 20 mm 的质心或漏掉电池质量，外观和步态都正常，只有累计接触力与通过高度会静默偏掉。

**单一来源**：每个数字只有一个家。机器属性→XML；场景、数值、阈值→JSON；脚本里不出现物理常数（`9.81` 从 `model.opt.gravity` 取）。**台阶几何不写进 XML**，由 runner 按 `scenario.obstacle` 规范化注入 worldbody，并把注入后的 XML 哈希记进 `run.json`（`scenario_xml_sha256`）。

**判定字段归属**：阈值在 JSON 的 `judge`（可改），观测定义在 XML（名称表），判定逻辑只在 `judge.py`（唯一写 `passed` / `failure_*` 的地方）。配置里**不得出现期望结果**；回归用 `regression_expect`，`judge` 禁读该键。

## 2. 配置 schema（`cases/baseline.json`）

| 字段 | 单位 | 约束 |
|---|---|---|
| `schema_version` | — | 必填，`"1.0"` |
| `case_id` | — | 必填，`[a-z0-9_]+`，同批次唯一；输出目录名 |
| `model.path` / `model.sha256` | — | 必填；sha256 不符即失败（防跑错模型） |
| `scenario.kind` | — | `flat` \| `step`（枚举，v1 只此二值） |
| `scenario.obstacle.shape` | — | `box` \| `cylinder`；`box` 支持 `edge_radius_m>0`（用圆柱实现顶棱，几何名 `step`/`step_edge` 对判定透明） |
| `scenario.obstacle.height_m` | m | `>0`，`flat` 时禁止出现 obstacle 块 |
| `scenario.obstacle.edge_radius_m` | m | `>=0`；`0` 表示尖棱 |
| `scenario.obstacle.top_width_m` | m | 矩形门槛顶宽（IEC：0.040），仅 `box` |
| `scenario.heading_deg` | ° | `0`=正对；正角=左轮先触（B 系 xy 平面内绕 +z 逆时针）；范围 ±60，带符号（左/右斜向不等价，别取绝对值） |
| `scenario.approach.speed_mps` | m/s | 轮心线速度指令（非电机转速），`>0` |
| `scenario.approach.start_distance_m` | m | 初始车头到台阶前缘距离，`>=0.3`（保证触发前已稳态） |
| `scenario.approach.settle_s` | s | 加速/稳压段，`>=0.5` |
| `scenario.approach.settle_tol_mps` | m/s | 触发前末 0.2 s 速度偏差上限，默认 `0.02`；超限 → `invalid:not_settled` |
| `environment.pairs` | — | 按材质对的表：`"wheel_L--floor"`、`"wheel_L--step"`…；每项 `{friction:[μ_s,μ_t,μ_r,μ_roll], condim}`。缺项=用 XML 默认，`run.json` 记 `source=model` |
| `drive.channels.wheel_L/R.torque_limit_nm` | N·m | 轮端上限；缺省=用 XML `forcerange`，覆盖则记 `overrides[]` |
| `numerics.timestep_s` | s | 必填；唯一来源。runner 强制 `model.opt.timestep` 并回读断言；XML 不得另写 timestep |
| `numerics.integrator` / `solver` / `cone` / `iterations` | — | 必填：`implicitfast` / `Newton` / `pyramidal`(默认) 或 `elliptic` / `100` |
| `judge.window_s` | s | 判定窗口，从 `t_trigger`（首次轮-台阶接触）起算，`>= 3×` 预计爬升耗时；默认 `8.0` |
| `judge.fail_on` | — | 子集，取自 §3 失败类别枚举；不在表里的类别只是诊断标记。默认 `["topple","retreat","timeout","stall"]` |
| `judge.min_advance_body_lengths` | 倍车身 | 通过需前移距离，默认 `1.0`（车身长从 `chassis` geom 包围盒取） |
| `judge.recover_speed_ratio` / `recover_hold_s` | —/s | 恢复前进判据：`v >= ratio×speed` 且持续 `hold_s`；默认 `0.8` / `0.3` |
| `judge.stall.speed_mps` / `.duration_s` | m/s, s | 失速：指令存在而 `v < speed` 持续 `duration`；默认 `0.01` / `1.0` |
| `judge.tilt.pitch_deg` / `.roll_deg` | ° | 倾覆阈值；默认 `25` / `15` |
| `judge.slip_ratio` | — | 打滑诊断阈值：`|v_wheel−v_body|/max(v_wheel,ε)`；默认 `0.3` |
| `judge.contact_normal_min_n` | N | 接地判据：法向力低于此值视为离地；默认 `0.5` |
| `seed` | — | 必填整数（v1 未使用 → `run.json: seed_used=false`） |
| `regression_expect` | — | 可选，`{"passed":bool,"failure_primary":str}`，仅回归断言用，**judge 禁读** |
| `notes` | — | 自由文本，不参与计算 |

v1 baseline 值（`timestep 0.002`、`speed 0.15`、`heading 0`、`height 0.02`、`window 8`）全部按【工程假设】进台账，改值不改契约。

## 3. 输出契约

目录：`outputs/<batch_id>/run.json`、`summary.csv`、`<case_id>[_r<k>]/timeseries.csv`（+`stdout.log`）。**同配置 `--repeat 2` 必须逐位一致**；不一致按缺陷处理，不得用「复现误差」掩盖。后者只用于时步/平台对照。

时间基准：`t=0` 为第一次 `mj_step` 之前，`t` 为仿真时间（s），所有时程与事件共用；不用墙钟。

单位：全部 SI（m、s、N、N·m、kg、rad）。列名必须带单位后缀（`_m _s _n _nm _rad _mps _radps _deg`）或为 `flag`/`count`/`_ratio`。

**`timeseries.csv` 必备列**（冻结集合；行=每个仿真步，可降采样但 `t` 单调且步长恒定）：

| 组 | 列 |
|---|---|
| 时间 | `t_s` |
| 机身 | `pos_x_m pos_y_m pos_z_m quat_w quat_x quat_y quat_z pitch_rad roll_rad yaw_rad vel_x_mps vel_y_mps vel_z_mps`（四元数 body→world，欧拉 ZYX，仅作阅读辅助） |
| 轮系 | `wheel_L_speed_radps wheel_R_speed_radps wheel_L_torque_nm wheel_R_torque_nm`（力矩=执行器力，轮端） |
| 悬挂 | `susp_L_travel_m susp_R_travel_m` |
| 接触 | 每对 `contact_<pair>_active`(0/1) `contact_<pair>_normal_n` `contact_<pair>_tangent_n` `contact_<pair>_count` |
| 底盘 | `chassis_min_z_m`（`chassis_*` 几何包围球下界，近似值） |

接触力一律 `mj_contactForce`：第 0 分量为法向，**正=压缩，方向 geom1→geom2**；`efc_force`（金字塔锥下是棱边系数）只许出现在诊断日志，不得进输出。切向力取其余分量模长。

**`summary.csv`**（一行 = 一个 case × 一次重复）：`case_id repeat status passed failure_primary failure_flags t_trigger_s t_climb_s t_recover_s advance_m v_recover_mps pitch_max_deg roll_max_deg slip_max_L slip_max_R torque_max_L_nm torque_max_R_nm susp_travel_max_L_m susp_travel_max_R_m contact_normal_max_n timestep_s integrator cone seed model_sha256 config_sha256 conclusion_level output_dir`

- `status`：`ok` | `invalid`（`not_settled`/`never_contacted`/`data_invalid`）| `diverged`。**`invalid`/`diverged` 不进通过率分母**，单独计数。
- `passed`：`0`/`1`，`status!=ok` 时留空。
- `failure_primary` 取一枚举；`failure_flags` 为 `;` 分隔的全部命中项。枚举冻结：`topple retreat timeout stall bottom_out suspension_bottom slip torque_limit no_contact data_invalid`。

**`run.json`** 必备键：`contract_version schema_version batch_id git{commit,branch,dirty} model{path,sha256} config{path,sha256} scenario_xml_sha256 com_offset_B_m frame{cad_to_B} python mujoco numpy os platform numerics{生效值} overrides[] seed seed_used params[{id,label,verified_by}] param_labels{计数} conclusion_level repeat{consistent,key_metrics_tol} started_utc finished_utc cases[] columns{col:{unit,missing}} data_quality`。

**「无接触 vs 真实零值」**（R4 明确点名的坑）——三条同时成立才算合规：

1. CSV 中**空字段 = 无数据/无接触**，`0.0` = 有接触且实测合力为零。数值一律不加引号、不用 `NaN` 字面量，`na_rep=""`。
2. 每个 `contact_*` 力列必须有同对 `*_active` 列：`active=0` ⇒ 力列必须为空；`active=1` ⇒ 必须非空（可为 0.0）。双向断言，违反即失败。
3. `_count` 是计数，`0` 是真实值，不表示缺失。

## 4. 版本与可复现

- 参数来源标签唯一台账：`docs/参数溯源.csv`（`param_id, xpath, value, unit, label, ref, verified_by, verified_delta, verified_tol`），`label` 六值枚举：`本机实测`、`图纸推算`、`公开参考`、`工程假设`、`缺失`、`待标定`。XML 中进入判定或结论的每个数值必须有台账行且值一致；缺行/不一致即失败。`run.json.params` 抄下实际用到的行，报告只引用它。**不确定度分量不进这张表**，另立 `docs/不确定度预算.csv`（§6.4）——两张表回答的是两个问题：数值从哪来、这个数值有多可信。
- `conclusion_level` 由标签集合计算，不许手写（三档不变）：决定性参数全为【本机实测】→`quantitative`；含【图纸推算】/【公开参考】/【工程假设】→`sensitivity`；含【缺失】/【待标定】→`mechanism`。
- **等级不承载精度（v1.5）**：`conclusion_level` 只回答「来源有多硬」，不回答「数字有多准」。引用 `quantitative` 的报告**必须同时给出该参数的 `verified_tol` 数值**；容差大到让结论在用途上失去意义的，结论在**用途**上不成立（写进未覆盖项或用途限制），不要在等级上打折，也不要把等级当精度用。
- **【图纸推算】的放行条件（v1.1）**：它默认只到 `sensitivity`。要进 `quantitative`，该台账行必须 `verified_by` 指向一次已完成的实测交叉校核，且 `|verified_delta| ≤ verified_tol`（容差口径按 §6 R-UNC-1，v1.2 起不再是纯重复性 3σ）。超限则该行追加 `cross_check_failed`，等级不得高于 `sensitivity`。**不做「图纸推算 ≈ 实测」的整体等价**：CAD 的几何可信度高、质量与惯量可信度低（漏件、胶水、电池、线束），只能逐行放行。
- 每次运行必记：契约版本、git commit/branch/dirty、模型与配置 sha256、注入后场景 XML sha256、Python/MuJoCo/NumPy 版本、生效数值设置、所有覆盖项、seed。缺任一项不产出 `summary.csv`。
- **载荷状态成套（v1.3，v1.4 加分组键）**：同一载荷状态（空载/满载）的 `m`、`com`、`inertia` 必须**成套有台账行**，值可以是【缺失】但要成行——「没这一行」不是表达缺失的方式，它会让结论等级推导看不见这个洞。载荷附加的质量属性（尘、水的附加惯量）必须独立成行，不得借用空载或整机惯量行顶替；缺任一行，该载荷状态不得出定量结论。
  - **分组键 =（`payload_state`, `config_id`）**，不是 `payload_state` 单独一项。`sealed_full_water` 与 `equiv_ballast` 是**不同的物理量**（一个摊开、一个集中），必须各自成行、各有自己的 `param_id`，不得共用一个 `param_id` 存两套值；`config_id` 走 `ref`（台账 9 列不新增列）。
  - **模型与本批次配置必须同 ID**：`chassis/inertial` 只能对上一套配置，`run.json.params` 抄下的行必须与本 case 的 `config_id` 一致；不一致即失败——不许一边用尘水测的附加惯量、一边跑配重批次。
  - **惯量行必须声明参考点与坐标系**（`ref` 内写 `ref_point=body_CoM|B_origin; axes=B`）。惯量是张量，脱离参考点的三个数不比 `m`、`com` 更可复核。
  - **主行由消费者定，不由测法定**（v1.5）：`chassis/inertial.fullinertia` 读的是关于**质心**、沿 body 轴的张量，所以 `ref_point=body_CoM` 是主行（`role=primary`）；`ref_point=B_origin` 的行只作互校（`role=check`），**不得被模型或 judge 引用**。同一量的不同参考点值是**两个值**，各占一个 `param_id`，不共用一个。
  - **换算行不作校核证据**（v1.5，v1.6 分清两个词）：互校只在**独立测量**（不同工装、不同方法、不同原始文件各测一次）时成立。由换算得到的行必须写 `derived_from=<源行 param_id...>`，标 `role=derived`，**不得计入 cross-check 通过**。
  - **复算 ≠ 互校（v1.6）**：同一次测量换参考点得到的第二行，唯一能验的是**换算算术有没有写错**，标 `role=derived`、写 `derived_from` 与 `original_file=<原始文件路径>`；它是**复算**，不许被称为互校、不许计入 cross-check。真互校（`role=check`）不得有 `derived_from`，必须有自己的 `original_file`。两个动作混用一个词，迟早有人拿复算当互校汇报。
  - **换算输入只引用、不抄数**（v1.5，S02 单一来源的延伸）：平行轴项用的 `m_b`、`r_to_ref` 一律通过 `derived_from` 指向已有的 `m`/`com` 行；把数值抄进 `ref` 等于给同一个数字造第二个家，两处迟早不一致。
  - **引用必须同分组（v1.6）**：`derived_from` 指向的行要与本源行同属一个（`payload_state`, `config_id`）。日期相同、文件相同、只是批次不同，`r` 就取自另一次称重——这类错误肉眼完全看不出，只能靠分组键查。
  - **派生比值不建行（v1.6）**：`I_xy/I_zz` 这类无量纲比值是好指标（对称性偏差的物理量，不随整机缩放），但它是两行的派生量，不占台账行——给它开一行就是造第二个家，换个 `I_zz` 就不同步。
- 批次目录已存在即**拒绝覆盖**并退出；新批次用新 `batch_id`。

## 6. 测量容差与不确定度（R-UNC-1，v1.2 新增）

台账 `verified_tol` 只有一种定义。**纯重复性 3σ 不是判定容差**，它只是过程能力诊断。

### 6.1 定义

| 量 | 口径 | 用途 |
|---|---|---|
| `s_r` | 同人同装夹连续重复的样本标准差（贝塞尔 n−1）；几何量 n≥10、质量/质心 n≥5 | A 类输入 |
| `s_f` | ≥3 组按真实过程重新装夹的合并标准差 | A 类输入 |
| `s_day` | ≥3 个不同日/批、同一参考件的复测合并标准差 | A 类输入，**不可省** |
| `u_A` | `√(s_r²+s_f²+s_day²)` | A 类（可采样散布） |
| `u_B` | 不可采样系统项的标准不确定度方和根（仪器校准、分辨力、温度未修正残差、装夹/轮胎压缩的模型假设误差等） | B 类 |
| `u_c` | `√(u_A²+u_B²)` | 合成标准不确定度 |
| `verified_tol` | `k·u_c`，`k` 默认 `2`（≈95%）；`ν_eff<10` 时取 `t_{0.975,ν_eff}`（Welch–Satterthwaite） | **判定容差，唯一合法用途** |
| `diag_3sigma_A` | `3·√(s_r²+s_f²)` | 过程能力诊断，**不进判定分支、不进 `summary.csv`** |

配套三条：系统项**先修正后合成**（可修正项残差进 `s_r`/`s_day`，不可修正项进 `u_B`）；同一分量不得同时进 A 与 B；判定限 = 规格限 ∓ `verified_tol`（guard band），不把容差并进规格限——规格限是产品属性，`verified_tol` 是测量属性。

### 6.1.1 容差的表达方式（v1.6）

- **`verified_tol` 一律绝对量，单位与同行 `value` 相同。** 百分比只允许出现在验收限的**目标值**里，不进台账——台账里一个 3% 和一个 3 g 长得一样，读的人分不清，脚本也没法比。
- **相对容差只准用于「真值远离 0、有明确非零量级」的量。** 接近 0 的量（惯量积 `Ixy/Ixz/Iyz`、横向质心偏置等）一律绝对口径：分母趋零时百分比没有信息量，写它等于强制一个算不出来的精度。判据是可机械执行的：该量的典型量级必须 ≥ 10× 其 `verified_tol`，否则不许用相对口径。
- **「按对称性设为 0」不是测量。** 这类行标【工程假设】，写明理由（如左右近似对称），并按 G5 扫描其影响；不得标【本机实测】，否则等级推导会把它当成测过的数。
- **参考点定位不确定度 `u_ref` 是 B 类分量的必填项**（`component=ref_point`）。平行轴项的相对影响约 `2·u_r/r`，是惯量不确定度的主要来源之一，省略它等于把最大的那一项当成 0。
- **`u_ref` 是各段位移不确定度的合成，不是工装对齐一项**（v1.7）：换算链有几步就累几步，**每段的距离由所选转轴决定，不是一个固定的 50 mm**（v1.7.1 澄清）。3% 能否达到，取决于闸门落在下面哪一支：
  1. **过质心测法（首选）**：三线摆/扭摆测的是绕某一根轴的惯量。把轴做成**过质心**（竖直轴测 `Izz`、水平轴测 `Ixx`/`Iyy`），测得的就是关于质心的惯量，模型 `inertial.fullinertia` 直接可用。用实测 `com`（±1 mm）定位可调工装、把轴与质心距离压到 `d ≤ 5 mm` 即可：平行轴项 `m·d²/I_c ≈ 1%`，它的相对误差即使 100% 也只贡献 ≈2%，仍在 3% 内。**`u_com = 1 mm` 在这一支里只是让 `d` 有 1 mm 偏差，量级无关，已交的 `com` 数据不用动。**
  2. **固定参考点测后换算**：换算距离 ≈50 mm 时 `2·u_d/d ≈ 4%`，这一支要 3% 就必须 `u_com ≤ 0.75 mm`，等于重测质心并污染已交数据。
  - 判据因此是**二选一而非一句绝对值**：能做「轴过质心、`d ≤ 5 mm`」就做，做不到再接受换算并把 `u_com` 收紧。缺省走第 1 支——多半天装配标定，比为 3% 重测质心便宜。
  - 无论走哪一支，`u_ref` 都要按实际换算链合成（含 `u_fixture` 与该段位移不确定度），不许只记工装对齐一项。
- **自洽优先于目标值**：若预算算出的 `verified_tol` 与验收限写下的目标值不自洽（例如目标 3% 而 `u_ref` 单独就占 4%），**以预算为准并改目标值**，不许挑小的那个写下来。可核的配对式：要求对角相对 `ε` 时须 `u_r ≤ ε·r/2`（`r≈50 mm` ⇒ `ε=3%` 要 `u_r≤0.75 mm`、`ε=5%` 要 `u_r≤1.25 mm`）。**契约只给这个配对式，不给 `ε` 的取值**——取值是验收限的事。

### 6.2 为什么不是纯重复性，为什么 `k=2`

判定门必须宽于流程自身的复现性。纯 `s_r` 在同人同装夹下可以极小，门随之收窄到接近 0，等于把「温度、零点、装夹、批次都没变」这个没写下来的前提藏进容差；换天复测即判超限，门比尺子还窄。`k=2` 而非 3σ：假超差可复测（成本低），假合格会把错模型放进下游（成本高）。安全相关或不可复测的参数可**逐参数**改 `k=3`，须在预算表写理由，**不设全局例外**。

### 6.3 A/B 归类唯一判据：能否按真实过程重复采样

- **装夹**：能按真实过程重复执行、可采样 → 进 `s_f`（A 类）。**仅当装夹无法按真实过程重复**（必须外挂、必须拆解、改变受力路径）时，改用 `u_B,mounting` 评估，与 `s_f` **互斥**，同一 `param_id` 只准出现一个，且在预算表 `note` 写明取哪个与原因。
- **轮胎压缩**：空载/满载两态分别测时，**各态 `s_r` 独立计算，两态之差不得并进 `s_r`**——那是口径差异不是重复性。只有两态覆盖不到的真实载荷谱差异，才进 `u_B,tire`。
- 通用判据只有一条：**能按真实过程采样 → A 类；采不到只能评估 → B 类**。「是否系统项」不是归类依据（装夹差异是系统性的，但它能采样，所以归 A）。

### 6.4 落盘：新增一张表，不加列

`docs/不确定度预算.csv`（每行一个分量）：

`unc_id, param_id, kind, component, dist, value, unit, nu, status, source, method, condition, invalidate, ref, note`

- `kind`=`A`|`B`；`source`=`meas`|`sim`；`component` 用固定枚举：`s_r s_f s_day instrument calibration resolution temp_residual mounting tire_compression sim_timestep sim_contact sim_geometry`；`dist`=`normal`|`rect`|`triangular`|`t`。
- **`status` 只三值**（v1.7.2，与三档结论等级同构）：`evaluated`（已评估）/ `assumed`（有值但依据是假设或经验）/ `pending`（未评估）。**六值 label 只用在参数行上**——把参数标签套到分量上会让「有一份别人的证书」和「本机实测」混成一个词，标签就失去了它唯一的用处。
- `method`（取值方法）所有行必填。`source=sim` 的行 `method / condition / invalidate` **三项全必填**：仿真侧不确定度是从设置推出来的而非测出来的，脱离条件与方法、失效判据的标量会被下游当通用容差引用。
- **参数有效等级** = 先由参数行 `label` 定基档，再看该参数全部 `kind=B` 分量的 `status`，取最差封顶：有 `pending` → 封顶 `mechanism`；有 `assumed` → 封顶 `sensitivity`；全 `evaluated` → 不降档。
- **`evaluated` 的门槛三条同时成立**（v1.7.2）：① 证书/规程在有效期内；② **量程覆盖该参数的测量范围**；③ **适用条件覆盖本次测量**（温区、载荷、点位）。只有证书而量程不覆盖 → 不是 `assumed` 而是 `pending`：此时证书对该项不构成溯源，手上只有一个估计值，估计值不能因为旁边有张证书就升档。
- **失效即回退**（v1.7.2）：换秤、换点位、超量程、证书过期等 `invalidate` 条件一旦触发，该行 `status` 回退为 `pending`，并在 `note` 记 `invalidated_at=` 与原因。「评估过一次就永远有效」比没评估更危险——它会让一个过期的溯源一路带到报告里。有效期与量程覆盖写进 `ref`（如 `cert=…; valid_until=…; range=…`），脚本可对「`valid_until` 早于测量日期而 `status=evaluated`」做粗检，精确的适用条件覆盖仍靠评审。
- `verified_tol` 仍在 `docs/参数溯源.csv`（**9 列不变**）：非空者必在预算表有行，且值可由预算表重算一致；两表对不上即失败。

为什么不并成一张表：两类行的主键、生命周期、消费者都不同——参数行答「这个数从哪来」（绑 `xpath`），分量行答「这个数有多可信」（不绑 XML）。混表会让 `xpath` 大批为空，§4 的 XML↔台账比对随之失效。

### 6.5 比对容差双向合成

判 `|实测 − 仿真|` 时 `u_c = √(u_meas² + u_sim²)`。`u_sim` 最低项集固定三项：**时间步长、接触参数、几何简化**，每项按五要素齐备（项 / 方法 / 条件 / 数值 / 失效判据，即预算表 `component / method / condition / value / invalidate`）。**口径与最低项集归本契约，数值归仿真侧在 G5 出**，以 `kind=B, source=sim` 行登记进同一张预算表。缺任一项或缺任一要素，该参数比对行不出 `verified_tol`、不得出定量结论。只取测量侧会系统性过严或过松，等于让模型好坏由测量精度决定。

### 6.6 `k` 放在哪

不进 `cases/*.json`：G2 的 case 跑算不需要 `k`，`verified_tol` 是台账列不是仿真参数，不为此开配置字段。`k` 记在预算表 meta 行与 `docs/试验/验收限冻结-<日期>.md`。**v1.2 的配置 schema 与输出列均未变。**
