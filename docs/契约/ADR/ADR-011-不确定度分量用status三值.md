# ADR-011：不确定度分量用 status 三值，不套参数标签

- 状态：已采纳（契约 v1.7.2，开版触发①）
- 背景：v1.2 把参数来源标签的六值枚举套到了不确定度预算表的每个分量上，并规定「参数有效等级 = 参数行 label 与其全部 B 类分量 label 中最差者」。实现时立刻撞墙：一份仪器校准证书在六值里没有位置——标【公开参考】会让一张台秤证书把所有实测参数压到 `sensitivity`；标【本机实测】则拆掉该标签最常用的判断（「这行到底测没测」）。两个方向都错，说明不是填法问题，是词汇表用错了地方。
- 选项：① 新增第 7 个标签（「外部溯源」）；② 允许证书标【本机实测】；③ 分量改用独立的三值 `status`。
- 选择：③。`status = evaluated | assumed | pending`，与三档结论等级同构：`pending` → 封顶 `mechanism`，`assumed` → 封顶 `sensitivity`，`evaluated` → 不降档。六值 label 只留在参数行，各答各的问题：参数行答「这个数从哪来」，分量行答「这一项评没评过、依据有多硬」。
- 代价：① 预算表的 `label` 列改名 `status`（列数不变，仍是 15）；② 引入两条配套约束——`evaluated` 须同时满足有效期、量程覆盖、适用条件覆盖；`invalidate` 触发后回退 `pending` 并记日期。这两条不是补充说明，是 `status` 能被机器判定的前提。
- 代价：这是冻结期里唯一一次判据变更，走的是开版触发①（原判据不可实现）。它提示一件事：**为「将来可能有用」引入的枚举，会在第一次接触真实数据时付账。**
- 翻案条件：若将来出现「分量之间也有来源强弱差异」的需求（例如同一分量有实测与文献两个版本），那要的是给分量加版本行，不是把六值标签搬回来。
- 关联：契约 §6.4、§4 等级推导、S19；ADR-004（A/B 归类）、ADR-008（等级不承载精度）。

## 一条可迁移的经验

**等级与精度是两个问题，分量状态与参数来源也是两个问题。** 每当想把一个词表复用到第二个位置，先问一句：这两个位置的问题是否相同？不同就必须各配一套词表，共用一套的结果必然是其中一边被拉伸到失效。
