# ADR-005：载荷状态成套与配置分组键

- 状态：已采纳（契约 v1.3 `f92f0e9` + v1.4 `a7bae86`）
- 背景：`conclusion_level` 由台账标签推导。若配重法只交了 `m_full` 与 `x_cg/z_cg`，而模型里**根本没有"载荷附加惯量"这一行**（不是标【缺失】，是没写），等级推导扫不到它，满载通过高度会照样推出 `quantitative`。这与「把没接触读成零力」是同一类错误：用"不写"表达"没有"，下游读成"没问题"。
- 选项：① 靠评审记得补；② 成套性做成硬规则。
- 选择：②。同一（`payload_state`, `config_id`）的 `m / com / inertia` 必须成套有行，值可为【缺失】但必须成行；载荷附加惯量独立成行，不得借用空载或整机行。`sealed_full_water` 与 `equiv_ballast` 是**不同物理量**，各占 `param_id`、不共用；`config_id` 走 `ref`。模型 `chassis/inertial` 必须与本 case 的 `config_id` 一致。惯量行必须声明 `ref_point`/`axes`（缺则整行无效）。
- 代价：台账行数增加；每次换载荷口径要新行而非改值。
- 翻案条件：若将来载荷状态变成连续参数（可调配重），分组键需换成区间；那时要重写这一条。
- 关联：契约 §4、S21、抽查 12/13。
