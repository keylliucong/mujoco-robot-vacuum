# ADR-013：能力声明——机型可以不具有某自由度

- 状态：已采纳（契约 v1.8.0，开版触发①）
- 背景：全流程试跑的机型 oomwoo **没有悬挂**，而名称表要求 `susp_*` 必须存在。实现方为过检查造了一个不承载的假铰，并把 `susp_range_m` 置 **1 m**——一个明显不成立的值。这不是实现方偷懒，是契约没给它合法出口。
- 更严重的一层（决定这条必须开版的理由）：契约原文写着「首版可为 0 行程的固定铰」，看起来是个出口，其实是**诱饵**——0 行程会让验收判据 `悬挂偏差 < min(0.5 mm, 5%·travel)` 退化成**0 容差**，数值上永远失败。于是实现方只剩一条路：编一个行程值，让 `5%·travel` 变成足够宽的阈值，判据永远通过。两种写法都不是判据在判，而是**阈值在演**。
- 选项：① 在 case JSON 加 `susp: {rigid: true}`；② 名称表豁免无悬挂机型；③ 在**模型侧**加能力声明，名称表条件化。
- 选择：③。
  - **不选 ①**：拓扑是模型属性，工况是 case 属性（§0 的分工）。放 case 会让同一台机器在不同批次里出现两种真相，且 runner 要读拓扑才能知道怎么取数，依赖方向反了。
  - **不选 ②**：豁免等于"名称表不是必须成套"，与 S21 的精神相反，还会让"真的漏了悬挂"和"本来没有悬挂"长得一样。
  - ③ 的做法：`<custom><numeric name="has_suspension" data="0|1"/></custom>`（`mjModel.numeric` 可读、可机检）；`has_suspension=0` 时 `susp_*` 不得存在、输出整列为空（**非 0**）、不进 `failure_flags`；`=1` 时必须齐备且行程 > 0。新增 S22 与抽查 16。
- 代价：模型文件多一个 `<custom>` 块；每新增一种可选自由度要同时改名称表、能力清单、输出列的空值断言。
- 代价：删掉了「0 行程固定铰」这个旧措辞——它对"运输锁定"这类场景仍有意义，但那是 `has_suspension=1` 下的建模细节，不是"没有悬挂"的表达方式。混用会把两种语义压成一个 0。
- 翻案条件：若出现"可配置悬挂"（同一机型两种选装），能力声明要升级为能力**取值**而不只是布尔；那时本节重写。
- 关联：契约 §1 名称表、§1.2、§3 空值语义、S22、抽查 16。

## 可迁移的两条

1. **契约里"必须有"的东西，一旦某机型天然没有，实现方一定会编值**。编出来的值不会报错，只会让判据判在一个不存在的自由度上——比缺规则更难查。
2. **一个看起来像出口的旧措辞（0 行程）可以是陷阱**：它满足"字段齐全"，却让下游的百分比阈值失效。判断"某个表达方式能不能用"，要看它的消费者，不只看它填不填得上。
