# ADR-012：两处等级——参数行看来源，结论看刻度

- 状态：已采纳（契约 v1.7.3，同日修正 v1.7.2）
- 背景：v1.7.2 把分量 `status` 接进了**参数等级**（有 `pending` → 参数封顶 `mechanism`）。落到真表上立刻出问题：本轮多数参数的 `u_B` 是 `pending`（证书温区不覆盖、残差未测），于是"整机质量、质心"这些**明明用台秤与三点秤实测过**的参数全被标成 `mechanism`。对外读起来像"没测"，实际是"没刻度"。
- 冲突点：ADR-008 定的是**等级不承载精度**。v1.7.2 让容差评估进度去压低等级，正是把两件事又粘回一起——同一个错误，只是换了个入口。
- 选项：① 保留 v1.7.2 的封顶（保守但语义错位）；② 完全不管容差，等级只看标签（干净但会放出"有等级没刻度"的定量结论）；③ 把两处等级分开，各用各自输入。
- 选择：③。
  - **参数行等级**（台账、`run.json.params`）**只看 `label`**，回答「这个数从哪来」。实测就是实测，不因容差未算而降档。
  - **结论等级**（通过高度这类派生结论）**= 参数标签 且 容差刻度**：参数全【本机实测】**且**该比对所需的 `verified_tol` 齐备，才允许 `quantitative`；有 `pending` 分量 → 结论封顶 `mechanism`；有 `assumed` 分量 → 封顶 `sensitivity`。
  - 配套可检项（S19）：有 `pending` 分量的参数，`verified_tol` **必须为空**——容差没刻度就不许填数，不许用 0 或估计值占位。
- 代价：报告里会出现"参数 `quantitative`、结论 `mechanism`"这种组合，需要在报告里加一句话解释（**来源硬不等于能定量**）。这句话本身有价值：它把"我测了"和"我能断言多远"分开了。
- 代价：`status` 与 `verified_tol` 的联动多了一条校验，填表时 `pending` 的行不能顺手写容差。
- 翻案条件：若将来引入"分级容差"（例如给出容差区间而不是单值），`pending` 的语义要重定为"区间未闭合"，那时本条需重写。
- 关联：契约 §4（两处等级）、§6.4、S19；ADR-008（等级不承载精度）、ADR-011（status 三值）。

## 一句可迁移的经验

**一个数字能被引用几次，决定了它需要几个等级。** 参数被引用时问的是"来源硬不硬"，结论被引用时问的是"这句话能说到多远"。用同一个等级同时回答两个问题，必然有一方被压扁——这跟把一个词表复用到两处（ADR-011）是同一个毛病。

## 排版层：两列并列，不只报结论（v1.7.4）

拆开两处等级只在定义上解决了一半问题；评审时最容易发生的是：报告写「结论 `mechanism`」，读者顺手以为参数也没测过；反过来参数表写【本机实测】，读者就以为结论能定量。**只在正文里说清楚不够，要落到排版**：

- 报告与图注**并列两列**：`参数等级`（从 `run.json.params[].label` 读）与 `结论等级`（`summary.csv: conclusion_level`），表头各自注明读法。
- `summary.csv` 只放结论等级；参数等级不入该表——一张表放一个等级，避免"到底是哪个"这种问题从文件层就长出来。

## 一条自检启发式（由试验标定提出，我采纳为设计侧规则）

**一刀切下去，绝大多数行落到同一个降档状态，多半是规则写错了，不是数据太差。**

v1.7.2 就是这么被发现的：30 行分量一填，几乎全部参数封顶 `mechanism`——那不是"本轮数据太差"，是"规则把容差进度当成了来源强弱"。行数在这里充当了检查手段：规则的作用面越大，写错时被放大的倍数越大，也就越容易被看见。

反过来也成立：**一条规则若只能在一两行上生效，它既难被验证，也几乎没有价值。**
