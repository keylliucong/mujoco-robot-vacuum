# 架构决策记录（ADR）

ADR（Architecture Decision Record，架构决策记录）把契约裁定从个人记忆搬进仓库：每条记录一次决定的状态、背景、备选项、选择、代价与翻案条件，供实现者与后续裁定人直接查证。

裁定与契约版本的对应关系：ADR-001/002 属 v1.1 首次定形；ADR-003/004 属 v1.2 不确定度口径；ADR-005 覆盖 v1.3 成套性与 v1.4 分组键；ADR-006/008 属 v1.5 惯量主行与等级语义；ADR-007 跨 v1.6/v1.7/v1.7.1 的容差表达；ADR-009 为多轮裁定归纳的归属边界；ADR-010 记录 2026-11-21 冻结于 v1.7 判据集、澄清至 v1.7.1；ADR-011 为冻结期内第一次判据变更（v1.7.2，开版触发①），ADR-012 当日修正其把容差进度接进参数等级的错误（v1.7.3）。契约正文（[G2 接口契约](../G2-接口契约.md)、[结构规则](../G2-结构规则-违反即失败.md)）与 ADR 冲突时以契约正文为准；1.7.x 只收澄清与删规则，新裁定须按 ADR-010 的开版触发条件另立 ADR。

## 记账与冲突裁决（2026-11-22 补，记账层，不改判据）

下游文档（验收限、不确定度预算、口径台账、报告）引用契约时用**双锚点**：规则 ID + 提交 SHA，例如 `S19 @ eeee939 / ADR-011`。单锚点抄错就是死结——SHA 错时靠 ID 定位，ID 错时靠 SHA 定位，两者同时写错才会失效。

冲突裁决只有三条，按顺序适用：

1. **ADR 与契约正文冲突 → 以正文为准**（ADR 记录的是"当时为什么这么定"，正文才是判据）。
2. **下游文档的 SHA 与契约变更记录不一致 → 判为下游文档缺陷**，按缺陷修，不当争议处理。锚点错误不能演变成"双方各说各的"，必须有一方默认错——默认错的是**离契约最远的那份**。
3. **两份下游文档互相冲突 → 各自回契约找依据**，找不到依据的就是那份文档缺锚点，先补锚点再谈谁对。

同一段文字在契约、ADR、下游文档三处各有一份，是**显式重复**，不是冗余：它们回答的问题不同（判据 / 理由 / 执行）。显式重复可以核对，隐式约定不能。
