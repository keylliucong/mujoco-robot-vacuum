# ADR-018：单帧与几何边界不该当判据

- 状态：已采纳（契约 v1.10.0，开版触发①：G3 首批实测证明判据不可靠）
- 背景：G3 第一批跑出来两处，机理不同、病根相同——**让一个边界替我们做决定**。
  - **单帧判末态**：h=15 mm 案例里，末帧前一帧两轮短暂失接触，末帧两轮都在台面上，`crossed` 被一帧噪声翻成 `false`（`cross_fail / not_ended_on_platform`）。判据问的是"最后有没有停在平台上"，而这个问题的答案本来就是一个持续量；用一帧回答，等于让采样时刻决定结论。
  - **几何限制被记成能力失败**：±15° 在 h=20 mm 都 `within_width=false`，被记进 `cross_fail` 桶。查下来两层原因叠在一起：① 判据拿 `obstacle.top_width_m`（IEC 矩形门槛**顶面沿前进方向的宽度** 40 mm）当横向半宽用，而台阶的横向范围其实是 `obstacle_half_width_m`（1.2 m）——**同一个字段被当成两个轴**；② 就算参照对了，横向越界也主要是"机器人爬斜了、离开障碍侧边"，属于试验条件退出，不是"越障能力不足"。
- 选项：① 保持单帧，靠"典型工况"绕开；② 把窗口做成可调的 case 参数，默认单帧；③ 窗口占空比 + 灰带；④ 横向越界改判 `invalid` 或继续算失败。
- 选择：③ + `invalid`。
  - **不选 ①**：判据不该有"别跑接近边界的工况"这种前置条件；边界工况恰恰是最需要的。
  - **不选 ②**：默认单帧等于保留病灶；可调窗口会让"窗口多长"变成调结论的旋钮。
  - ③ 的落地：末 `end_hold_s`（50 ms）内 `both_wheels_on_top` 帧占比 `end_duty`；≥0.80 算在平台、<0.50 不算、`[0.50,0.80)` 判 **`invalid:end_state_ambiguous`**。**灰带必须留着**：用 0.80 这一个点替代单帧，只是把翻转挪个位置；灰带是判据承认"这次判不了"，比让阈值猜一侧诚实。
  - ④ 取 `invalid`，并拆两层：**前置 fail-fast**（所需横向半宽 `|tan(heading)|×(min_advance+车身长)+车身半宽` 超过台架半宽 → 整批非 0 退出、不产 `summary.csv`）+ **运行时兜底**（`invalid:lateral_exit_step_width`）。前者是配置不成立，跑之前就知道；后者说明现场与配置不一致。
  - **`invalid` 不是失败类别**：不得进 `failure_primary`/`failure_flags`，不进分母、不参与等级。这一条比字段名重要——一旦 invalid 混进失败枚举，通过率就把"没测成"和"过不去"算成一个数。
- 代价：`summary.csv` 用 `invalid:<reason>` 承载原因（列冻结，不能加列），读者要认后缀；窗口长度与两个阈值进 `_runner.json`，多四个台账行；`obstacle.top_width_m` 的语义被写死为"前进方向的顶面宽度"，任何拿它当横向范围的旧代码都是缺陷。
- 翻案条件：若台阶几何升级为"有限宽的凸台"（真三维台阶块，横向也会结束），横向越界就要回到能力判据里，`within_width` 需要以正确参照重建，本节重写。
- 关联：契约 §2（`top_width_m` 语义）、§3（`status` 格式与词表）、§3.1（四条件 + 窗口 + 灰带 + 两层兜底）、S25 补充、S26、抽查 20、ADR-016（同一"边界决定结论"的病根）。

## 可迁移的三条

1. **末态不是一帧，是一个停留**。凡是"结束时如何"的判据（在平台上、静止、离地、接触），都要用窗口占空比；只要允许单帧，采样时刻就会替你签字。
2. **灰带不是软弱，是判据的诚实**。两个阈值之间判"这次判不了"，比让一个阈值猜一侧便宜：猜错的那次不会报错，只会变成一个看起来正常的结论。
3. **"没测成"和"过不去"必须分家**。混在一起的通过率，会在某个季度把台架改造的功劳记到机构设计头上；反过来也一样。

## 补记（v1.10.1）：标签要指观测，不指原因

G3 重判把 ±15° 那批从"横向出界"翻出来看：前置校验 `need = 0.332 m`，台架实际半宽 `0.6 m`——**台架根本不窄**；而末态横向位移 1.4–3.6 m、前进只有 1.0–1.15 m，漂移是前进距离的 1.5–3 倍。原来挂的 `lateral_exit_step_width` 会被读成"加宽台架就能跑"，把人引到错误的方向上。所以新增 `lateral_drift_untrusted`，并把两个标签的语义分开：

- `lateral_exit_step_width`：**几何真的结束了**（末态横向出了台阶范围）。它只说这个事实，不许用来解释"台架太窄"。
- `lateral_drift_untrusted`：几何没出去，但**横向行为不是这个机型该有的**——先扣掉航向本身的几何横向分量再判：`(|end_lat| − advance·tan|ψ|) / max(advance, min_advance) ≥ 0.5`。扣这一步是必须的：30° 斜向爬升本来就有 0.58×前进距离的横移，不扣会把正常斜向全判成异常。

为什么不叫 `heading_control_untrusted`：**标签指观测，不指原因**。横向漂移是测得到的，原因可能是航向控制不足、也可能是轮-地各向异性摩擦没标定（或两者叠加）。用原因命名，等修好控制却发现摩擦才是主因时，历史数据上的标签就成了假证据。原因写进 `note` 与 G3 报告，不写进 reason。

版本上按补丁（v1.10.1）：`passed` 判据、失败枚举、输出列、等级推导一条没动，只是词表多一项、多一处说明——这不是判据集变更，不该开大版本。
