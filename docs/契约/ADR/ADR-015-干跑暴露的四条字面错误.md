# ADR-015：干跑暴露的四条字面错误——符号、触发条件、批次指纹、逐位一致

- 状态：已采纳（契约 v1.8.2，开版触发①：干跑实测证明条文不可实现或自相矛盾）
- 背景：用 oomwoo 真数据跑一遍（PR #27），四处条文立刻现形，且**四处都不报错**——它们全部表现为"运行正常、输出合理、结论错了"。
- 四条：
  1. **符号写反**：`+y` 轴、`+x` 前向时，接触点 `r_c = -R ẑ`，`v_body = -ω × r_c = ω_y R x̂`，故 `qvel > 0` 即前进。v1.1 却写 `-qvel`。照字面实现，flat 以 -0.1 m/s 输出，`slip`/`recover` 把正常前进判成打滑/未恢复。→ 改为 `+qvel` / `+actuator_force`。
  2. **触发条件缺一半**：`t_trigger` 原定义"首次**轮**-台阶接触"。台阶高于离地间隙时，底盘前缘先触、轮子全程不接触 → 判定窗口不启动，`bottom_out` 永不触发，输出 `invalid/no_contact`。→ 改为"首次**任一**机体-台阶接触"（轮或底盘），首触来源记进 `run.json.cases[].trigger_source` 作诊断，`summary.csv` 不加列。
  3. **单数键没有多 case 语义**：`config{path,sha256}`、`scenario_xml_sha256` 都是单数，而一个批次可含多个 case。实现方只能自造。→ 定义为**批次指纹**（按 `case_id` 字典序排序后连接哈希），`cases[]` 逐 case 明细必填。
  4. **逐位一致与冻结列冲突**：`summary.csv` 自带 `repeat` 与 `output_dir`，两行按定义必然不同，"逐位一致"字面不可能通过。→ 排除这两列，其余（判定、关键量、timeseries）仍必须逐位相同。
  5. **摩擦静默为 0**（新增 S24）：MuJoCo 4.0.1 下 `<pair friction>` 实测不产生切向力，而契约把摩擦写在 `environment.pairs`。设 0.8 得到 0，且无任何报错。→ 要求 runner **回读生效摩擦**并与配置比对，不一致即失败，落点记 `overrides[]`。这条不断言内核行为（那是仿真侧的事），只断言"配置与生效值必须一致，不一致不许静默"。
- 代价：`t_trigger` 改动会改变已跑批次的 `t_trigger_s` 语义，历史批次需标注；S24 要求实现多一步回读。
- 翻案条件：若某版本 MuJoCo 修好了 pair 级摩擦，S24 仍应保留——它断言的是"配置=生效"，与内核具体行为无关。
- 关联：契约 §1.1、§2 `judge.window_s`、§3、S24、抽查 18；干跑 PR #27 §4。

## 可迁移的一条

**干跑的价值不在"跑通"，在"跑通之后仍然错了的地方"。** 这四条全部是"能跑、有输出、不报错"的错误——它们只有拿真数据走一遍才会现形，评审和单测都抓不到：单测用的是同一个被写错的公式。

## 更正（2026-11-22，第 5 条归因错误）

本节原写"MuJoCo 4.0.1 下 `<pair friction>` 实测不产生切向力"——**归因错了，现象是真的**。仿真专家复核：pair 摩擦是生效的，真因是**分量数**——`<pair friction>` 取 **5 分量**（`slide1 slide2 spin roll1 roll2`），而 `<geom friction>` 是 **3 分量**（`slide spin roll`）。干跑把 geom 的写法 `"0.8 0.005 0.0001"` 抄进 pair，被解析成 `slide1=0.8, slide2=0.005, spin=0.0001`，那个滑动方向的摩擦只有 0.005，于是"切向力恒为 0"。

S24 因此重写为三条断言（condim / 各向同性 / 期望值），真值一律读 `d.contact[i].friction`；并加一条**禁止把 pair 摩擦下沉到 geom 规避**——那会让轮-地 μ 与轮-台阶 μ 这两个独立的一阶扫描变量静默合并成一个。

**教训（这条比结论有用）**：**现象对，不等于归因对。** 干跑报告写了现象与最小复现，但把"切向力为 0"直接归到内核行为；如果没有仿真专家复核，我们会把一条正确的功能写进契约当成坏掉的东西，还会连带把 μ 二维扫描压成一维而没人发现。
