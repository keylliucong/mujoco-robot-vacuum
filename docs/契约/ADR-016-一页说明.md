# ADR-016 一页说明：台账键形改三段

> 合并 #41 前读条文用。只陈述改动、理由、影响、后果，不评价好坏。

## 1. 这条改了什么

`param_id` 从两段 `<machine>.<量名>` 改为三段 `<machine>.<config_id>.<量名>`，全表唯一。
第二段 `config_id` 取装配配置（`unloaded` / `sealed_full_water` / `equiv_ballast` …），必须与该行 `ref` 里的 `config_id=` 逐字相同（可机检），且不得含 `.`（含点即失败）。
`machine` 仍限 `own` / `prototype` / `oomwoo`；量名形状按有无真实 `xpath` 决定（路径式 / 语义式）。
`run.json.params[].param_id`、预算表、报告表头统一用三段键。

## 2. 为什么要这段

核心：同一载荷可以有两种实体配置（`sealed_full_water` / `equiv_ballast`），只放载荷态会撞键——S21 分组键是（`payload_state`, `config_id`），`payload_state` 只有空载/满载两值，装不下第二种配置。

反例（满载 `com_x`）：
- 旧两段键：`own.com_x`（水密封满载）与 `own.com_x`（等效配重满载）——一个键要存两套值，撞键；台账现靠把配置编进量名规避：`own.com_full_x` / `own.com_ballast`。
- 三段后：`own.sealed_full_water.com_x` 与 `own.equiv_ballast.com_x`。

## 4. 合并它会怎样

1. 契约与实现对齐（#44 已合，现在合 #41 不会破 S23）。
2. 不自洽风险：以后任何新机型/新配置都必须给 `config_id`，否则 S23 红。
3. 不进任何数值、`label`、`status`、`verified_tol`。
