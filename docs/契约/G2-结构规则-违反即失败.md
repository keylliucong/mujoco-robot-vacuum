# G2 结构规则：违反即失败

配套：[G2 接口契约](G2-接口契约.md)（v1.1）。每条都是**硬约束**：违反即失败，不做「先通过、后补」；无法自动检查的由评审按此逐条问。

| ID | 规则 | 违反后果 | 检查方式 |
|---|---|---|---|
| S01 | **名称取用**：runner 只用 `mj_name2id`（或名称表里的字符串）访问实体；出现整数索引（`qpos[0]`、`geom id`、`actuator id` 直接写字面量）即失败 | 模型改结构即静默错位，输出看起来正常但物理是别人的 | 脚本：grep `\.(qpos|qvel|actuator_force|geom_xpos)\[\d`；评审抽读 |
| S02 | **单一来源**：每个数字只有一个家（机器→XML，场景/数值/阈值→JSON）；脚本里除 `0/1` 外无物理字面量；timestep 只在 JSON | 两处各写一份，改一处漏一处，比对失效 | 脚本：扫描 `.py` 浮点字面量白名单；评审 |
| S03 | **台阶只由注入器产生**：`models/*.xml` 里不得出现 `step` 几何（`floor` 材质模板除外） | 为每个高度复制 XML，配置与模型开始互相污染 | 脚本：解析 XML，检查 geom name/material |
| S04 | **判定与仿真解耦**：`judge.py` 只吃时程 + 阈值，不 `import mujoco`、不读模型/配置对象 | 判定无法脱离仿真复核，也无法与实机数据对齐 | 脚本：import 图 + 源码禁用词 |
| S05 | **输出列冻结**：CSV 头必须等于契约列集合；每列带单位后缀或为 `flag`/`count`/`_ratio` | 下游脚本与报告静默错位 | 脚本：比对表头集合 + 后缀正则 |
| S06 | **缺失≠零**：每个 `contact_*` 力列有同对 `*_active`；`active=0`⇒力列为空，`active=1`⇒非空 | R4 点名的坑：把「没接触」读成「零力」，接触时序全错 | 脚本：逐行双向断言 |
| S07 | **接触力口径**：只用 `mj_contactForce`；`efc_force` 不进任何输出文件 | 金字塔锥下 `efc_force` 是棱边系数，量纲都不是力 | 脚本：grep 输出写入路径的 `efc_force` |
| S08 | **单位与坐标**：力矩只以轮端 N·m（`gear=1`）；角度 rad；力 N；时间 s；世界系右手、+x 前进、+z 上 | 电机端/轮端混用是这类项目最常见的静默错误 | 评审 + 脚本：列名后缀 |
| S09 | **判定不可被配置绕过**：`judge.fail_on` 只取枚举；配置出现 `expected/passed/result` 等键即失败；judge 禁读 `regression_expect` | 配置自证通过，判定退化成断言 | 脚本：schema 白名单 + judge 源码禁用词 |
| S10 | **参数溯源**：进入判定/结论的每个数值在 `docs/参数溯源.csv` 有一行且值一致；标签只能是六值之一（含【图纸推算】） | 结论等级无法由证据推出，报告变成形容词 | 脚本：XML↔台账比对，缺行即失败 |
| S11 | **可复现记录**：`run.json` 缺 SHA/版本/生效数值/配置哈希/`scenario_xml_sha256` 任一项，不产出 `summary.csv` | 「跑过的那个结果」无法重建 | 脚本：必填键断言 |
| S12 | **不覆盖**：批次目录已存在即退出；不静默合并、不追加写 | 结果被悄悄替换，回归结论失真 | 脚本 |
| S13 | **目录所有权**：`models/` 只放 XML 与台账引用；`cases/` 只放 JSON；`scripts/` 不含 MJCF 字符串（`verify_env.py` 的内联冒烟 XML 例外，且不得被 `run_cases.py` 引用） | 模型散落脚本里，版本管理失去意义 | 脚本 |
| S14 | **契约版本一致**：脚本顶部 `CONTRACT_VERSION` == 契约文档版本 == `run.json.contract_version` | 契约与实现各说各话 | 脚本 |
| S15 | **无静默降级**：覆盖未生效、字段缺省、`apply` 失败一律 `raise`；不得用默认值继续跑 | 最贵的 bug 是「跑完了，但参数没进去」 | 评审 + 脚本：覆盖后回读比对 |
| S16 | **机体系单一**：`chassis` 的 world 位姿恒为单位位姿；XML 内无 CAD 全局系、无靠初值偏移摆正的 body；A1–A5 断言（质量/CoM/惯量/轮心/基准位姿）全过，且 `run.json` 有 `com_offset_B_m` 与 `frame.cad_to_B` | CAD 搬移错位不会立刻暴露，只让通过高度和接触力静默偏掉 | 脚本：质量与惯量求和、轮心几何、基准位姿断言 |
| S17 | **图纸推算逐行放行**：`label=图纸推算` 的行默认不得计入 `quantitative`；要计入必须同时有 `verified_by`、`verified_tol`、`|verified_delta|≤tol`，否则结论等级不得高于 `sensitivity` | CAD 值被当成实测，定量结论建立在没称过的质量上 | 脚本：台账列校验 + 等级推导复核 |

## G2 交付时我按这些抽查

1. 名称表逐项对上：模型里有没有这些名字，runner 是不是按名字取。
2. 拿一个 `flat` 工况把 `obstacle` 块塞进配置，应报错而不是忽略。
3. 拿一个含 `expected: true` 的配置，应报错。
4. 把 `contact_*_active` 全置 0（或无接触工况），力列必须为空而不是 0。
5. 同一配置 `--repeat 2`，两次 `summary.csv` 判定一致、关键量逐位一致。
6. 改 `judge.fail_on` 加 `bottom_out`，判定结论应随之改变——证明判据只有一处。
7. `run.json` 里 SHA、时间步、锥型、seed、`scenario_xml_sha256`、参数标签齐全。
8. 把台阶高度改 0.04 再跑，只允许配置变化，模型与脚本零改动。
9. 把 `chassis` 或某个 body 的 `inertial` 平移 20 mm、或漏掉一块质量，A1–A3 必须报警；把两轮任一轮心挪 2 mm，A4 必须报警。

任一项不过，G2 不算交付；我出结构评审意见（必须改/建议改/可接受三档），不排期、不派工。
