# G2 结构规则：违反即失败

配套：[G2 接口契约](G2-接口契约.md)（v1.10.1）。每条都是**硬约束**：违反即失败，不做「先通过、后补」；无法自动检查的由评审按此逐条问。

| ID | 规则 | 违反后果 | 检查方式 |
|---|---|---|---|
| S01 | **名称取用**：runner 只用 `mj_name2id`（或名称表里的字符串）访问实体；出现整数索引（`qpos[0]`、`geom id`、`actuator id` 直接写字面量）即失败 | 模型改结构即静默错位，输出看起来正常但物理是别人的 | 脚本：grep `\.(qpos|qvel|actuator_force|geom_xpos)\[\d`；评审抽读 |
| S02 | **单一来源**：每个数字只有一个家（机器→XML，场景/数值/阈值→JSON）；脚本里除 `0/1` 外无物理字面量；timestep 只在 JSON | 两处各写一份，改一处漏一处，比对失效 | 脚本：扫描 `.py` 浮点字面量白名单；评审 |
| S03 | **台阶只由注入器产生**：`models/*.xml` 里不得出现 `step` 几何（`floor` 材质模板除外） | 为每个高度复制 XML，配置与模型开始互相污染 | 脚本：解析 XML，检查 geom name/material |
| S04 | **判定与仿真解耦**：`judge.py` 只吃时程 + 阈值，不 `import mujoco`、不读模型/配置对象 | 判定无法脱离仿真复核，也无法与实机数据对齐 | 脚本：import 图 + 源码禁用词 |
| S05 | **输出列冻结**：CSV 头必须等于契约列集合；每列带单位后缀或为 `flag`/`count`/`_ratio` | 下游脚本与报告静默错位 | 脚本：比对表头集合 + 后缀正则 |
| S06 | **缺失≠零**：每个 `contact_*` 力列有同对 `*_active`；`active=0`⇒力列为空，`active=1`⇒非空 | R4 点名的坑：把「没接触」读成「零力」，接触时序全错 | 脚本：逐行双向断言 |
| S07 | **接触力口径**：只用 `mj_contactForce`；`efc_force` 不进任何输出文件 | 金字塔锥下 `efc_force` 是棱边系数，量纲都不是力 | 脚本：grep 输出写入路径的 `efc_force` |
| S08 | **单位与坐标**：力矩只以轮端 N·m（`gear=1`）；角度 rad；力 N；时间 s；世界系右手、+x 前进、+z 上 | 电机端/轮端混用是这类项目最常见的静默错误 | 评审 + 脚本：列名后缀 |
| S09 | **判定不可被配置绕过**：`judge.fail_on` 只取枚举；配置出现 `expected/passed/result` 等键即失败；judge 禁读 `regression_expect` | 配置自证通过，判定退化成断言 | 脚本：schema 白名单 + judge 源码禁用词 |
| S10 | **参数溯源**：进入判定/结论的每个数值在 `docs/参数溯源.csv` 有一行且值一致；标签只能是六值之一（含【图纸推算】） | 结论等级无法由证据推出，报告变成形容词 | 脚本：XML↔台账比对，缺行即失败 |
| S11 | **可复现记录**：`run.json` 缺 SHA/版本/生效数值/配置哈希/`scenario_xml_sha256` 任一项，不产出 `summary.csv` | 「跑过的那个结果」无法重建 | 脚本：必填键断言 |
| S12 | **不覆盖**：批次目录已存在即退出；不静默合并、不追加写 | 结果被悄悄替换，回归结论失真 | 脚本 |
| S13 | **目录所有权**：`models/` 只放 XML 与台账引用；`cases/` 只放 JSON；`scripts/` 不含 MJCF 字符串（`verify_env.py` 的内联冒烟 XML 例外，且不得被 `run_cases.py` 引用） | 模型散落脚本里，版本管理失去意义 | 脚本 |
| S14 | **契约版本一致**：脚本顶部 `CONTRACT_VERSION` == 契约文档版本 == `run.json.contract_version` | 契约与实现各说各话 | 脚本 |
| S15 | **无静默降级**：覆盖未生效、字段缺省、`apply` 失败一律 `raise`；不得用默认值继续跑 | 最贵的 bug 是「跑完了，但参数没进去」 | 评审 + 脚本：覆盖后回读比对 |
| S16 | **机体系单一**：`chassis` 的 world 位姿恒为单位位姿；XML 内无 CAD 全局系、无靠初值偏移摆正的 body；A1–A5 断言（质量/CoM/惯量/轮心/基准位姿）全过，且 `run.json` 有 `com_offset_B_m` 与 `frame.cad_to_B` | CAD 搬移错位不会立刻暴露，只让通过高度和接触力静默偏掉 | 脚本：质量与惯量求和、轮心几何、基准位姿断言 |
| S17 | **图纸推算逐行放行**：`label=图纸推算` 的行默认不得计入 `quantitative`；要计入必须同时有 `verified_by`、`verified_tol`、`|verified_delta|≤tol`，否则结论等级不得高于 `sensitivity`。**准入（v1.7.7）**：标该标签前必须齐备可核三元组（推导脚本 / 输入 sha256 / 尺寸表）与运行环境声明，缺一降【工程假设】；尺寸表表头须自带 `generated_by` 与 `input_sha256` | CAD 值被当成实测，定量结论建立在没称过的质量上 | 脚本：台账列校验 + 等级推导复核 |
| S18 | **容差口径单一**：`verified_tol` 只准 `k·√(u_A²+u_B²)` 且为**绝对量、与同行 `value` 同单位**；`u_A` 必含 `s_r/s_f/s_day` 三项；相对容差只准用于「典型量级 ≥10× `verified_tol`」的量，近零量（惯量积、横向偏置）用相对口径即失败；「按对称性设 0」标【工程假设】；纯重复性 3σ 只许作 `diag_3sigma_A` 诊断，出现于判定分支或 `summary.csv` 即失败 | 门比尺子窄，换天复测自判超限；分母趋零使百分比无信息；把诊断值当放行门用 | 脚本：判定分支常量扫描 + 预算表重算比对 + 单位与量级校验 |
| S19 | **预算表完整且不重计**：非【缺失】参数必有 ≥1 个 B 类分量，或一行显式的「可忽略」结论（`u_B<0.1·u_A` 且带量化理由）；同一分量不得同时进 A 与 B（装夹 `s_f` 与 `u_B,mounting` 互斥）；`verified_tol` 非空者必在预算表有行；**有 `pending` 分量的参数，`verified_tol` 必须为空**（容差没刻度就不许填数） | 没评估就报容差（假确定），或同一分量算两遍把门撑大 | 脚本：两表交叉校验、同一 `param_id` 同 `component` 唯一性 |
| S20 | **比对双向合成**：判 `|实测−仿真|` 的容差必须含 `u_sim` 最低三项（时间步长/接触参数/几何简化），且每项五要素齐备（项/方法/条件/数值/失效判据）；缺任一项或缺任一要素，该参数不出 `verified_tol` | 只算测量侧，系统性过严或过松，模型好坏由测量精度决定；标量脱离条件被当通用容差引用 | 脚本：预算表 `source=sim` 行齐备性 + 必填列非空 |
| S21 | **载荷状态成套**：同一（`payload_state`, `config_id`）的 `m / com / inertia` 必须成套有台账行，缺任一则该状态不得出定量结论；**载荷附加惯量必须独立成行**，不得借用空载或整机惯量行顶替；不同 `config_id` 各自成行、不共用一个 `param_id`；模型 `chassis/inertial` 与本 case 的 `config_id` 不一致即失败；惯量行缺 `ref_point`/`axes`/`role` 即该行无效；**`role=derived` 的行不得计入 cross-check**，且其 `derived_from` 引用的行必须与本源行**同属一个（`payload_state`, `config_id`）分组**（跨批次引用即失败）；派生比值（如 `I_xy/I_zz`）不建台账行，由行间算出 | 缺惯量的载荷状态进模型，配重法照样给出"满载下界"；或一边用尘水测的附加惯量、一边跑配重批次；或同一组数换参考点「互校」通过的恒真式；或日期与文件相同、`r` 却取自另一次称重 | 脚本：按（`payload_state`,`config_id`）分组成套性检查 + case↔行 ID 比对 + `role`/`ref_point` 关键字校验 + `derived_from` 指向与同分组校验 + 换算式重算 |
| S22 | **能力声明与模型两端一致**：`<custom><numeric name="has_*">` 声明为 `0` 时模型内不得出现对应关节/执行器，声明为 `1` 时必须齐备；无该自由度时对应输出列整列为空且 `run.json.columns[...].missing=true`，不得进 `failure_flags`；**用占位值（如 `susp` 行程 1 m）掩盖"该机型没有这个自由度"即失败** | 假铰假行程会给出永远通过或永远失败的阈值，读起来像"判据生效了"，实际判的是一个不存在的自由度 | 脚本：`mjModel.numeric("has_*")` 与关节/执行器名单比对 + 列全空断言 + `missing` 标记校验 |
| S23 | **台账键唯一（三段）**：`param_id = <machine>.<config_id>.<量名>`（v1.9.1），`machine` 取契约固定三项，**全表唯一**（含跨机型与跨配置）；键的 `config_id` 段必须等于 `ref` 里的 `config_id=`，`config_id` 内含 `.` 即失败；`xpath` 只许空或真实指针，出现 `TODO(`/`N/A(`/`—` 等占位即失败 | 两段式在「同载荷两种配置」下会撞键（`sealed_full_water` 与 `equiv_ballast` 的满载同一量），撞了就联表串行；占位符让「绑没绑 `xpath`」的检查恒真 | 脚本：三段解析 + 唯一性 + 键↔`ref` 的 `config_id` 一致性 + 点号禁用 + 占位正则 |
| S25 | **枚举与判据两端一致**：契约 §3 的失败枚举 == `run_cases.FAILURE_ENUM` == `judge.FAILURE_PRIORITY` 的集合；`passed` 只能由 §3.1 的四条推出；`failure_primary` 按契约顺序取名，命中但未列入 `fail_on` 时不得落成 `timeout`；展示标签（`cleared`/`blocked`/机理名）不得写进 `summary.csv`/`run.json` | 代码先长出新判定、契约后知后觉，报告里的"失败原因"与契约对不上，复核时无从判断用的是哪套口径 | 脚本：三处枚举对表 + 判据函数签名审读；**`invalid` 不是失败类别**：`status` 为 `invalid:<reason>` 时不得写 `failure_primary`/`failure_flags`，`reason` 只取 §3 词表；**invalid 词表也要查活**——词表里每一项必须在 `judge.py` 或 `run_cases.py` 有产出点（`invalid_reason="…"` 字面量），否则 FAIL |
| S26 | **判定不得依赖单帧**：末态类判据（在平台上、离地、接触状态）一律用窗口占空比，窗口与阈值进 `_runner.json`；参数落在灰带时必须判 `invalid:<reason>`，不得由单点阈值猜一侧；实现须有"末帧前一帧零接触、结论不翻转"的回归 | 一帧噪声翻转结论，等于让采样率替物理签字 | 脚本：占空比计算 + 灰带回归 |

| S24 | **接触摩擦三条断言（v1.8.3 重写）**：以 `d.contact[i].friction`（`mj_forward`/`mj_collision` 后的逐 contact 解析结果）为唯一真值，逐 contact 断言 ① `d.contact[i].dim == 期望 condim`；② `d.contact[i].friction[0] == d.contact[i].friction[1]`（各向同性——这条专挡「把 geom 的 3 分量写法抄进 5 分量的 pair」）；③ `d.contact[i].friction[0]` 等于按规则算出的期望值（有 pair 用 pair 的 `slide1`，无 pair 用两侧 geom **逐分量取最大**）。**禁止把 pair 摩擦下沉到 geom 规避**：pair 级摩擦是区分轮-地 μ 与轮-台阶 μ 的唯一手段，下沉会让两个独立的一阶扫描变量静默合并成一个（数字量级不变、不报错）。禁止以 `model.geom_friction`（未解析 3 分量）或 `model.pair_friction`（模板）作断言依据 |配置写了各向同性、实际接触是各向异性时，`slip`/`advance` 只错一个方向，输出一切正常——这种错最难查 | 脚本：逐 contact 读 `d.contact[i]`，三条断言 + condim 校验 + 禁止 geom 下沉的静态检查 |

## G2 交付时我按这些抽查

1. 名称表逐项对上：模型里有没有这些名字，runner 是不是按名字取。
2. 拿一个 `flat` 工况把 `obstacle` 块塞进配置，应报错而不是忽略。
3. 拿一个含 `expected: true` 的配置，应报错。
4. 把 `contact_*_active` 全置 0（或无接触工况），力列必须为空而不是 0。
5. 同一配置 `--repeat 2`，两次 `summary.csv` 判定一致、关键量逐位一致。
6. 改 `judge.fail_on` 加 `bottom_out`，判定结论应随之改变——证明判据只有一处。
7. `run.json` 里 SHA、时间步、锥型、seed、`scenario_xml_sha256`、参数标签齐全。
8. 把台阶高度改 0.04 再跑，只允许配置变化，模型与脚本零改动。
9. 把 `chassis` 或某个 body 的 `inertial` 平移 20 mm、或漏掉一块质量，A1–A3 必须报警；把两轮任一轮心挪 2 mm，A4 必须报警。
10. 台账跑一遍键检查：`param_id` 唯一且全带 `machine` 前缀；`xpath` 列没有 `TODO(`/`N/A(` 之类占位。
11. 把契约枚举与 `FAILURE_ENUM`、`FAILURE_PRIORITY` 对表；在 `fail_on` 里加 `belly_contact`、`cross_fail` 各跑一次，结论必须跟着变。
12. 拿一个通过的 case，把末帧前一帧的接触列清空，结论必须不变；把末 50 ms 占空比改成 0.65 必须落 `invalid:end_state_ambiguous`；台架半宽改 0.02 必须整批非 0 退出且不留 `summary.csv`。 把 `heading=15°` 的时程横向位移放大到前进距离的 2 倍，必须落 `invalid:lateral_drift_untrusted`，而 30° 的干净斜向（横移 ≈ `advance·tan30°`）不得误判。
10. 删掉某参数在预算表里的全部 B 类行，该参数的 `verified_tol` 必须不成立（报警），不许用 A 类顶替；把同 `param_id` 的装夹分量同时写成 `s_f` 与 `u_B,mounting`，必须报错。
11. 把 `k` 从 2 改 3，只允许 `verified_tol` 随之变，别处阈值不得跟着动；把 `diag_3sigma_A` 接进判定分支，结论不得随之改变（变了说明判定门被诊断列左右）。
12. 删掉满载状态的惯量行（或让它借用空载/整机惯量行），满载状态必须不出定量结论并报警——"半个载荷状态"不许通过。
13. 把台账某行的 `config_id` 与 case 的配置 ID 改成不一致（尘水的惯量 + 配重的批次），必须失败；把惯量行 `ref` 里的参考点删掉，该行必须无效。
14. 把同一组数换参考点得到的第二行当「互校通过」的证据，必须失败（`role=derived` 不计入 cross-check）；把换算输入 `m_b`、`r` 的数值抄进 `ref` 而不用 `derived_from` 引用，必须失败。
15. 惯量积行写成相对容差（`±5%`），必须失败；把 `derived_from` 引到另一个（`payload_state`,`config_id`）分组的 `m`/`com` 行（日期与文件都相同、只是批次不同），必须失败。
16. 取一个无悬挂机型（`has_suspension=0`）：模型里出现 `susp_*` 关节必须失败；把 `susp_*_travel_m` 写成 0 而不是空必须失败；把行程改成 1 m 蒙混必须失败。
17. 把某个 `param_id` 改成两段（如 `own.m_dry`）或去掉 `config_id` 段，S23 必须失败；把键里的 `config_id` 与 `ref` 里的 `config_id=` 改成不一致，必须失败。
18. 把 geom 的 3 分量摩擦写法（`"0.8 0.005 0.0001"`）抄进 `<pair friction>`，必须被 S24 第②条拦住（`friction[0] != friction[1]`）；再把 pair 摩擦下沉到 geom 让轮-地与轮-台阶共用同一个 μ，必须失败。

任一项不过，G2 不算交付；我出结构评审意见（必须改/建议改/可接受三档），不排期、不派工。
