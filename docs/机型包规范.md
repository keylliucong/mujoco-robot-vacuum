# 机型包规范

## 交付文件

每个机型配置交一个 **`.urdf` 文件作为唯一 3D 入口**，再附 `params.json` 和 `sources.md`。一个 URDF 描述完整装配和关节树。文件名可改，校验时传入文件路径即可。

| 文件 | 要求 | 怎么准备 |
| --- | --- | --- |
| `robot.urdf` | 必交 | 导出整机 link（部件）、joint（关节）、运动轴、限位、碰撞几何及可用的分件质量属性。要单文件交付时，可用 URDF 内的长方体、圆柱或球来表示碰撞外形。若导出文件含 mesh 引用，运行方须能解析那些资源，版本和位置写进 `sources.md`。 |
| `params.json` | 必交 | 从下方模板开始，填本配置的机型标识、部件与关节名称、实测或可追溯的参数。 |
| `sources.md` | 必交 | 写清机型和修订、配置实际装了什么、B 原点与方向、URDF 的导出来源、各组参数的原始资料位置和待补项。每个参数的 `note` 可以指向这里对应的小节。 |
| `.step` 或 `.stp` | 可选 | 有可信的 STEP 时，结合材料密度、零件范围和装配位置推算更准确的质量、质心与惯量。记录 CAD 版本、原文件哈希、计算依据和漏件。缺 STEP 时使用 URDF 和参数表中已有的数据。 |

换载荷或修改轮径、重心、壳体等设计后，提交与该状态一致的 URDF 和参数表，用新 `config_id` 区分。整机参数和分件参数冲突时，在 `sources.md` 写明冲突与待核实项，运行前由建模方裁定生效数据并按契约记录血缘。来源说明和 STEP 可补充证据。当前脚本读取 URDF 与 JSON 两个文件。

## 按模板填表

1. 复制下方整段到纯文本编辑器，存为 UTF-8 的 `params.json`。保留冒号左边的字段名，只改右边的内容。
2. 按实物填写。能测就填本机实测，能查就填有出处的公开值，也可用本机 CAD 推算。实测、公开值和可用 CAD 都没有时填 `null`。已有明确建模假设时可用 `assumed`，并写明依据和适用条件。
3. 每个数都有一组 `value`（数值）、`source`（来源）、`note`（说明）。复制 URDF 中 `name="..."` 引号里面的原名，大小写照抄。多一只驱动轮就复制一个大括号包住的轮子条目，各条目之间留逗号。
4. 长度、质量、轮端扭矩和轮速按字段表的固定单位填写。数字格只填数字，单位说明留在字段表。布尔值 `true`、`false` 和缺值 `null` 直接写。名称和说明用英文双引号括起来。

### 顶层字段

**固定必填字段共 9 个**，即下表中标「必填」的 9 行。其下的轮子、质量属性和数值记录也有必填子字段。悬挂和附加载荷按实际配置增加，子字段总数随轮子数、关节数和载荷变化。

| 字段 | 要求 | 单位 / 允许的值 | 怎么填 |
| --- | --- | --- | --- |
| `schema_version` | 必填 | 固定文本 `"1.0"` | 保留模板版本号。 |
| `machine_id` | 必填 | 非空文本 | 填可区分机型的名称，如 `"robot_a"`。 |
| `payload_state` | 必填 | `"empty"`、`"loaded"` | 填空载或带载荷，空载包含日常装机的固定部件，载荷定义写进来源说明。 |
| `config_id` | 必填 | 非空文本 | 填这套装配的标识，如 `"sealed_full_water"` 或 `"equiv_ballast"`，两种实体配置各填一套。 |
| `base_link` | 必填 | URDF 中的 link 名 | 填机身所在的 link 名称。 |
| `drive_wheels` | 必填 | 清单，可列任意数量 | 每个驱动轮填一条。确实无驱动轮的机构填 `[]`，实际能否运行取决于模型适配支持。 |
| `capabilities` | 必填 | 能力名称及有无声明 | 按下方的能力表填。 |
| `support_points` | 必填 | 从动支撑点清单 | 每个从动轮或滑橇各填一条。完全靠驱动轮支撑时填 `[]`。 |
| `assembly` | 必填 | 整机质量属性组 | 按本配置填写整机的质量、质心和惯量。 |
| `suspension_joints` | 条件必填 | 有悬挂时至少一条，无悬挂时可省略或填 `[]` | 列出在 URDF 中建出的悬挂铰或滑移关节及其行程。 |
| `payload_addition` | 条件必填 | 有载荷时必填，空载省略 | 单独填附加载荷的质量、质心和惯量。带载配置的 `assembly` 仍填写带载整机数。 |

### 每只驱动轮的字段

每条 **5 个字段均必填**。后 3 项使用数值记录。

| 字段 | 单位 / 允许的值 | 怎么填 |
| --- | --- | --- |
| `link` | URDF 中的 link 名 | 填轮体名称，应是下方转轴的 `child`。 |
| `joint` | URDF 中 `continuous` 或 `revolute` 关节名 | 填该轮的转轴名称，每只轮的轮体和转轴各有唯一名称。 |
| `radius_m` | m，> 0 或 `null` | 填轮胎外半径，并在说明写测量时的载荷和轮胎状态。 |
| `torque_limit_nm` | N·m，> 0 或 `null` | 填轮端扭矩上限的正值，注明实测、限流或规格书的工况。 |
| `speed_limit_radps` | rad/s，> 0 或 `null` | 填轮端角速度上限的正值，说明对应的电量、负载或控制设置。 |

### 机型能力

把各项能力填为 `true`（有）或 `false`（无）。新增能力只在 `capabilities` 中增加名称，用小写英文和数字，下划线分词，以字母开头。适配器按生效契约映射已支持的能力。能力声明通过格式检查后，仍需确认适配器能否运行对应机构。

| 键 | 要求 | 怎么填 |
| --- | --- | --- |
| `suspension` | 必填 | 有可动悬挂填 `true`，刚性安装填 `false`。 |
| `steering` | 选填 | 有独立转向自由度填 `true`，单靠左右轮差速转向填 `false`。 |
| `lift` | 选填 | 有主动抬升自由度填 `true`。 |
| 其他能力名 | 选填 | 用新键声明，把机构含义和有关 URDF 名称记入 `sources.md`。 |

### 从动支撑点

每条 **4 个字段均必填**。多个从动轮或滑橇分别填写。同一 link 上有多个支撑点时可重复填该 link，用各自的位置区分。建模方结合这些支撑点和驱动轮接地点复核支撑多边形。位置取本配置静止平地参考姿态。

| 字段 | 单位 / 允许的值 | 怎么填 |
| --- | --- | --- |
| `link` | URDF 中的 link 名 | 填从动轮或滑橇所在部件名。 |
| `type` | `"caster"` 或 `"skid"` | 万向轮或球形从动支撑填 `"caster"`，滑橇填 `"skid"`。 |
| `radius_m` | m，> 0 或 `null`，用数值记录 | 填从动轮外半径或滑橇工作圆弧半径。从动轮半径未知时填 `null` 并写补测方式。滑橇无适用半径时填 `null`、`"missing"` 并在 `note` 注明原因。 |
| `position` | `"urdf_link_origin"` 或三个 B 系坐标 | 从动轮以轮心为基准，滑橇取静止平地接触位置。若该点就是 URDF link 原点，填 `"urdf_link_origin"`，适配器沿关节树变换到 B 系。否则按下表填写位置。 |

| `position` 中的字段 | 单位 / 允许的值 | 怎么填 |
| --- | --- | --- |
| `x_m` | m，有限数或 `null` | 填前后坐标的数值记录。 |
| `y_m` | m，有限数或 `null` | 填左右坐标的数值记录。 |
| `z_m` | m，有限数或 `null` | 填高度坐标的数值记录。 |

下例为直接填写坐标的滑橇。把这段复制到 `support_points` 的方括号里，多个支撑点之间用逗号隔开。

```json
{
  "link": "body",
  "type": "skid",
  "radius_m": {"value": null, "source": "missing", "note": "平底滑橇无适用半径"},
  "position": {
    "x_m": {"value": -0.12, "source": "assumed", "note": "示例后支撑接地点"},
    "y_m": {"value": 0.02, "source": "assumed", "note": "示例后支撑接地点"},
    "z_m": {"value": 0, "source": "assumed", "note": "示例静止平地接触位置"}
  }
}
```

### 质量属性组的字段

`assembly` 和 `payload_addition` 使用同一组 **10 个必填字段**。每项都用数值记录，未知分量可单独留 `null`。对差速底盘，B 的原点在左右驱动轮轴心连线中点的地面投影，+x 向前，+y 向左，+z 向上。URDF 根坐标与 B 不重合时，在来源说明附变换。其他拓扑由适配器明确建模基准并记录转换关系。惯量用被描述物体自己的质心为参考点，分量按 B 的三轴表示。惯量积填写惯量张量的对应元素。

| 字段 | 单位 / 允许的值 | 怎么填 |
| --- | --- | --- |
| `mass_kg` | kg，> 0 或 `null` | 填整机或附加载荷的总质量。 |
| `com_x_m` | m，有限数或 `null` | 填质心在 B 中的前后坐标。 |
| `com_y_m` | m，有限数或 `null` | 填质心在 B 中的左右坐标。 |
| `com_z_m` | m，有限数或 `null` | 填质心在 B 中的高度坐标。 |
| `ixx_kg_m2` | kg·m²，> 0 或 `null` | 填绕过质心且平行于 B 的 x 轴的转动惯量。 |
| `iyy_kg_m2` | kg·m²，> 0 或 `null` | 填绕过质心且平行于 B 的 y 轴的转动惯量。 |
| `izz_kg_m2` | kg·m²，> 0 或 `null` | 填绕过质心且平行于 B 的 z 轴的转动惯量。 |
| `ixy_kg_m2` | kg·m²，有限数或 `null` | 填惯量张量的 xy 元素。 |
| `ixz_kg_m2` | kg·m²，有限数或 `null` | 填惯量张量的 xz 元素。 |
| `iyz_kg_m2` | kg·m²，有限数或 `null` | 填惯量张量的 yz 元素。 |

带载时填 `"payload_state": "loaded"`，并把下面这一段放到文件末尾的最后一个大括号**前面**。开头的逗号分隔前面的整机组和这一组。下面的未知数可以先保留，再把说明改成实际的缺项原因。

```json
,
  "payload_addition": {
    "mass_kg": {"value": null, "source": "missing", "note": "待称量附加载荷"},
    "com_x_m": {"value": null, "source": "missing", "note": "待测载荷质心 x"},
    "com_y_m": {"value": null, "source": "missing", "note": "待测载荷质心 y"},
    "com_z_m": {"value": null, "source": "missing", "note": "待测载荷质心 z"},
    "ixx_kg_m2": {"value": null, "source": "missing", "note": "待补载荷惯量 xx"},
    "iyy_kg_m2": {"value": null, "source": "missing", "note": "待补载荷惯量 yy"},
    "izz_kg_m2": {"value": null, "source": "missing", "note": "待补载荷惯量 zz"},
    "ixy_kg_m2": {"value": null, "source": "missing", "note": "待补载荷惯量 xy"},
    "ixz_kg_m2": {"value": null, "source": "missing", "note": "待补载荷惯量 xz"},
```

### 有悬挂时的字段

把 `capabilities` 里的 `suspension` 改成 `true`，再把下方这段放到文件末尾的最后一个大括号前面。把示例的关节名改为本机 URDF 中的名称。弹簧曲线、预紧与阻尼的资料位置可在 `sources.md` 记录，供适配时确定模型形式。

| 字段 | 单位 / 允许的值 | 怎么填 |
| --- | --- | --- |
| `joint` | URDF 中 `revolute`、`continuous` 或 `prismatic` 关节名 | 填独立悬挂关节的名称，每个关节只列一次。 |
| `travel_m` | m，> 0 或 `null` | 填轮心相对机身的可用竖直总行程。确有悬挂但行程未测时填 `null`。 |

```json
,
  "suspension_joints": [
    {
      "joint": "left_suspension",
      "travel_m": {"value": 0.008, "source": "assumed", "note": "示例行程，实际提交请注明测量起止位置"}
    }
  ]
```

### 数值记录的 3 个必填字段

| 字段 | 允许的值 | 怎么填 |
| --- | --- | --- |
| `value` | 对应字段允许的有限数字或 `null` | 有数据直接填数字。缺数据填 `null`。 |
| `source` | 下表五种来源之一 | 照抄最符合实际的一项英文标记。 |
| `note` | 非空文本 | 填来源位置、实测工况或假设理由。缺失时写缺什么、怎么查或怎样补测。 |

| `source` | 怎么选 |
| --- | --- |
| `"measured"` | 自己对这台机型实测，写日期、方法、条件、原始记录位置。 |
| `"datasheet"` | 从规格书、厂商说明、公开资料直接取值，写版本和页码或表格。 |
| `"cad"` | 从本机 URDF、图纸、STEP 等几何数据推算，写输入版本和推导记录。 |
| `"assumed"` | 工程建模暂用值，写假设依据和适用条件。 |
| `"missing"` | 目前没有这个数，`value` 必须填 `null`。 |

**`null` ≠ 0。** `null` 表示未知，依赖这个数的判定要等补齐。0 是已知数，例如对称布置下的横向质心坐标。拿 0 代替未知悬挂行程，会把验收限中按行程计算的容差压成 0，让有效试验被误判。没有悬挂时，将 `capabilities` 中的 `suspension` 填为 `false`，并省略悬挂条目。按对称性设为 0 时用 `assumed` 并在 `note` 里说明。

这里的 `source` 是交资料时的标记。运行前按 [G2 契约 §4](契约/G2-接口契约.md#4-版本与可复现) 将生效参数登记入台账。可分别对应【本机实测】【公开参考】【图纸推算】【工程假设】【缺失】，其中图纸推算须满足契约的证据要求。批准进入模型、实测放行及结论等级由契约和验收限决定。

### 三个常见错误

| 问题 | 容易写成 | 应改成 |
| --- | --- | --- |
| 漏逗号 | `"value": 0.036 "source": "measured"` | `"value": 0.036, "source": "measured"` |
| 把数字写成文字 | `"value": "0.036"` | `"value": 0.036` |
| 把图纸上的 mm 数字直接填进 m 字段 | `radius_m` 的 `"value": 36` | 对示例轮填 `"value": 0.036`，字段名仍是 `radius_m`。同时核对抄的是**半径**。 |

## 提交前校验

在项目根目录执行以下命令。脚本仅需 Python 标准库。

```bash
python3 scripts/check_machine_pack.py machine_packs/_example/robot.urdf machine_packs/_example/params.json
```

Windows PowerShell 使用项目解释器。

```powershell
.\.venv\Scripts\python.exe scripts\check_machine_pack.py machine_packs\_example\robot.urdf machine_packs\_example\params.json
```

- **通过（退出码 0）** 表示字段、类型、数值范围、缺值写法和 link/joint 引用符合填写规则。若还有已登记缺值或单位提示，脚本会逐项列出来。示例包有两项已登记缺值。
- **未通过（退出码 1）** 会列出文件名、行号、字段路径与修改建议。缺少整项时指向父对象所在行，语法错误指向解析位置。字段路径如 `$.drive_wheels[0].radius_m.value`，表示第一只驱动轮的半径数字。
- `radius_m` 或 `travel_m` 达到 1 m 时脚本提示核对 mm 与 m。这个提醒用于发现常见抄录错误。物理可用性、质量与惯量自检、模型支持、是否具备判定条件由运行前的适配和有效性检查确定。

### 适配后须逐项检查

| 检查项 | 校验脚本检查的输入 | 适配后必须检查的产物 |
| --- | --- | --- |
| 悬挂 · S22 | `capabilities.suspension` 是布尔，且与声明的悬挂关节清单一致。 | `false` 与 `true` 必须分别落成 MJCF `<custom><numeric name="has_suspension" data="0"/></custom>` 或对应 `data="1"`。按契约 §1.2 核对该标记与关节、执行器及空输出。 |
| 附加载荷 · S21 | 带载时 `payload_addition` 的 10 个数值记录必须齐备，缺值按 `null` 写法登记。 | 10 个字段各自形成独立 `param_id` 台账行，按（`payload_state`, `config_id`）分组，分组信息写在 `ref`。未知量照样成行并标【缺失】。与整机属性分行，惯量行按契约写参考点、轴系及角色。 |
| 轮端扭矩与轮速 · S02 / S17 | 每只轮保留 `torque_limit_nm` 与 `speed_limit_radps` 的数值、来源及说明。 | 若用来写入 XML 的 `forcerange` 或关节 `velocity` 等字段，每只轮的每个生效量要有独立 `param_id` 台账行并绑定相应 `xpath`，保留单位、符号和换算血缘。需补值时先按生效契约和来源裁定。 |
| 从动支撑位置 | 检查支撑 link 名、类型、半径及位置填写方式。 | 解析 URDF 得到的位置或直接填写的 B 系坐标，按实际采用的来源逐轴登记台账。引用 URDF 时保留文件版本、link、关节树变换与参考姿态。 |

格式脚本只读取提交输入。MJCF 与台账生成后，才能逐项确认上表的映射及落盘结果。见 [G2 契约 §1.2、§4](契约/G2-接口契约.md)及[结构规则 S02、S17、S21、S22](契约/G2-结构规则-违反即失败.md)。
