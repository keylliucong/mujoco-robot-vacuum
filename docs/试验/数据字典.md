# 数据字典（B 系字段 ↔ MuJoCo 参数）

- 版本：v1 · 2026-11-21 · 试验标定
- 用途：让交出去的时程与参数能直接对上验收项与模型字段，减少二次翻译。

## 1. 机体系 B

- B = world = chassis 局部系：+x 前进、+y 向左、+z 向上，右手系。
- 原点＝左右驱动轮轴心连线中点在地面的投影；z=0 在地面。
- 记录表表头标「B 系」；CAD 全局系换算给 (dx, dy, dz, ψ)。

### 1.1 基线模型 vs 基准机型

| 中文 | 英文/ID | 指什么 | 标签上限 |
|---|---|---|---|
| **基线模型** | `baseline model`（`models/baseline.xml`） | 三类基准工况用的**模型** | — |
| **基准机型** | `reference machine`（`makerspet/oomwoo`） | 对标用的**那台机器** | 【公开参考】→ `sensitivity` |

**两者不得混算**；报告中单独使用 `baseline` 一词时不加限定视为缺陷，必须写「基线模型」或「基准机型」。同一句里"baseline 用的 baseline 参数"读不通，且极易滑成"拿 oomwoo 的尺寸当自家尺寸"。

### 3.1 容差口径（不可互换）

- CoM：±1 mm（长度量，按 §1 的 B 系原点换算后比较）。
- 惯量对角：本轮 `5–10%（有值即可；3% 另议）`。
- `3% 的取得路径见复核意见（转轴摆过质心，d ≤5 mm），不等同于收紧 com；契约口径待更新。`
- 惯量积：本轮按对称声明设 0（`Ixy = Iyz ≈ 0`；`Ixz` 在纯俯仰方程中不出现）；`I_xy/Izz` 由报告口径给出（派生量，非独立测量），台账不占行。
- **两者不可互换**：±1 mm 只对 CoM，不用于惯量；惯量不用长度容差。

### 3.3 摩擦数据交付口径（对齐契约 v1.8.3 / S24）

> 交付给仿真侧的摩擦数据**必须分两行**：`mu_s`（轮–层压板）与 `mu_step`（轮–铝门槛），各带独立 `verified_tol`。**不得合并成一个 `mu`**。

理由同 S24 的禁止项：`mu_s` 与 `mu_step` 是**两个独立的一阶扫描变量**；pair 摩擦下沉到 geom（或交付时合并成一个 `mu`），会把「轮–地」与「轮–台阶」静默合成一个值——二维扫描降成一维，**数字量级不变、也不报错**。仿真侧要按 5 分量写 `<pair friction>`，试验侧就要按两行给数——**两边必须一一对应，否则下游只能合并回去**。

| 交付行 | 覆盖的接触对 | 台账 `param_id` | 本轮标签 | 模型落点 |
|---|---|---|---|---|
| 1 | 轮–层压板（试验地面 `floor`） | `own.mu_s` | 【待标定】 | `pair "wheel_*--floor"` 的 `slide1` |
| 2 | 轮–铝门槛（台阶 `step`） | `own.mu_step` | 【待标定】 | `pair "wheel_*--step"` 的 `slide1` |

- `own.mu_s` 与 `own.mu_step` 是**两个独立 `param_id`**（`docs/参数溯源.csv` 已有行），不可互为别名，也不得用一行同时覆盖两层表面。
- 一部分材料把 `mu_s` 口语写作 `mu_ground`；**台账没有 `mu_ground` 这个键，不得据此新建第二个 `param_id`**，也不得让两个名字指向同一行。
- 每行各算各的 `verified_tol`、各判各的空：一行 `pending` 不得让另一行跟着为空，反之亦然。本轮两行均【待标定】，`verified_tol` **均为空**（`CAL-023`：有 `pending` 分量时不许填 0 或估计值占位）。
- `verified_tol` 一律绝对量、与 `value` 同单位（契约 §6.1.1）；两行分别给，不得先取平均再交一个数。
- 仿真侧展开 5 分量时，`slide1 = slide2 = 该行 μ`；`spin` / `roll1` / `roll2` 不属于本轮这两行 μ，必须在 pair 里**显式写全**，不得留默认值让 `slide2` 掉回 `1.0`（`S24` 第②条断言会拦，但拦不住"只写一个数"的写法——交付时就要说清）。
- 量的边界：`mu_s` = 轮–层压板；`mu_step` = 轮–铝门槛。**不得把"台阶"写成"地面"的别名**，也不得把门槛材质换成另一种铝后沿用同一个 `param_id`。
- 本轮两行都是【待标定】：**任何覆盖表 / 敏感性表 / 参数表都不得把这两行当作已有值**，只能标【待标定】或留空；不得拿规格书、文献或基准机型的 μ 顶替。

> **键格式使「禁止别名」成为必然**：`param_id` 格式为 `<machine>.<param>`（v1.8.1 / `S23`）。因此同一物理量在不同机型下是**不同键**：`own.mu_s` 与 `oomwoo.mu_s` 并列存在、互不替代；**不得为了「看起来一样」而省掉机型前缀**——省掉就等于允许跨机型混算。`mu_ground` 最多作为 `note` 里的口语名出现（如「口语名：轮–层压板摩擦」），不是键。


## 4. 标签枚举与升档

| 标签 | 含义 | 可支撑的结论等级 |
|---|---|---|
| 本机实测 | 本机、本台架、按本模板测得，带 `u_c` | 可达 `quantitative`（`u_A` 三项齐、`u_B` 已评估、`u_sim` 齐） |
| 公开参考 | 文献/标准/厂商公开值 | 最高 `sensitivity` |
| 工程假设 | 无来源的取值假设 | 仅 `mechanism`/`sensitivity`，不得进定量结论 |
| 缺失 | 已知需要但还没有 | 该参数结论 ≤ `mechanism` |
| 待标定 | 本轮不测、下一轮补 | 该参数结论 ≤ `mechanism` |
| 【图纸推算】 | CAD/图纸推算值 | **默认止于 `sensitivity`**；逐行放行到 `quantitative` 必须带交叉校核，图纸尺寸单独进台账不足以升档 |

### 4.3.1 `label` 按"谁做的推算"判定

| 情形 | 标签 |
|---|---|
| 外部资料**直接给出**的数（BOM、规格书、厂商文档） | 【公开参考】 |
| **我们从该机几何自己推算**（有 STEP/URDF/mesh 可复现） | 【图纸推算】 |
| 无几何、只能凭经验或类比给个值 | 【工程假设】 |

- 基准机型（`oomwoo`，无 CAD）**拿不到【图纸推算】档**，只能【公开参考】。

> 【图纸推算】要求同一条尺寸能被第三方按同一输入重新导出——入库的不是 CAD 本体（受限数据不入库），而是**推导脚本 + 输入文件 sha256 + 输出尺寸表**；输入文件凭 sha 索取。三者缺一，降为【工程假设】。

**脚本必须声明运行环境**（脚本头部或同目录 `ENV.md` 必写）：

- 解释器与库版本，或**容器镜像 digest**；
- **是否依赖 CAD 内核；若依赖，写内核名 + 版本**；
- **质量属性的算法口径**：B-rep 精确积分，还是 mesh 近似；若是 mesh，必须写**弦高/角度容差**（tessellation 参数）。

理由：同一脚本不同环境会跑出不同数，"可复现"否则只是名义上的；体积/惯性若走 mesh 近似，结果直接随容差变。

**尺寸表与台账同源（可机械查）**

- 一个 `param_id` **只指向一处来源**：`ref` 写 `rev=<sha>#docs/试验/尺寸表-<机型>.csv:<行>`。
- 尺寸表以 `param_id` 为键，**不得重复行**；同一 `param_id` 出现两次即台账缺陷。
- 尺寸表表头：`param_id | value | unit | derived_by | script_rev | note`。

**脚本与尺寸表同目录、同提交**

- 放在同一目录（例 `docs/试验/推算/<机型>/`），**同一次提交**入库，`rev` 指向该提交。
- 这样"谁改的推导、改完尺寸变了没有"直接从历史看得出。

**【图纸推算】升档不自动**

> 【图纸推算】三元组齐了也**只到 `sensitivity`**，不自动升 `quantitative`；升档仍要逐行实测交叉校核：`verified_by=<实测 param_id> @ <sha>`，且 `|delta| ≤ verified_tol`。

【图纸推算】严格禁止被读成"可定量"。

### 4.3.2 外部来源参数：三个字段必填

- 在 `ref` 里固定写：`source=<出处>; retrieved=<yyyy-mm-dd>; rev=<pin>`。
- **能 pin 版本的一律 pin `rev`**（commit sha / tag / 版本号）。
- **没有 `rev` 不得引 `path:line`**——行号会漂，指过去是假精度。
- 有 `rev` 时允许 `path:line`（在该 sha 下行号稳定），格式：`rev=<sha>#<path>:<line>`。

- **基准机型参数一律【公开参考】**：按契约封顶 `sensitivity`，**不得作为定量输入来源**，也**不得**因此把结论升到 `quantitative`。
- `makerspet/oomwoo` 的 Roborock S5 系列驱动轮组规格（扭矩/减速比）若查得到：记【公开参考】，**仍须实测**；允许作为"对标值 + 偏差"呈现，不允许顶替实测列。
- 该机型**无 CAD/STEP**：其几何与质量属性只能来自文档与 BOM，属【公开参考】；本机型 CAD 到货后走实测 + 交叉校核，两条线不混。

等级只有三档：`mechanism` / `sensitivity` / `quantitative`，**无 judgment**。参数行 `label` 定基档；结论等级还要看容差刻度是否齐备。

### 4.1 词表归属

| 位置 | 用词 | 取值 |
|---|---|---|
| 仿真摘要列名 | `outcome` | `cleared` / `blocked` / `invalid` |
| 失败分类 | `failure_mode` | 具体机理名（`lift_fail` / `slip_stall` / `belly_contact` …） |
| 验收限判定 | 只在验收限文档与签署记录里出现 | 不得进入仿真摘要 |

`pass` 在验收限语境里是判定级措辞，而仿真里的 `pass` 只是"这一次算例里机器人有没有爬上去"——**是结果不是判定**；同一个词两种含义，grep 会一起抓，评审也分不清。

- **机器侧**：`summary.csv` / `run.json` 的 `conclusion_level` **一律指结论等级**；**参数等级不入 `summary.csv`**，只从 `run.json.params[].label` 读。一张表只放一个等级。
- **文档侧**（报告与图注）：并列两列，列名写清来源：`参数等级（label）`、`结论等级（conclusion_level）`；不得只报其一。
- **文档双列 ≠ 机器双字段**；机器里只有一个等级字段，另一个从 `label` 读。

### 4.2 等级与分量状态（两套词，互不换算）

| 等级三档（结论） | 含义 |
|---|---|
| `mechanism` | 只有机理层结论 |
| `sensitivity` | 加上敏感性/方向性 |
| `quantitative` | 可用 `verified_tol` 做定量判定 |

| 分量状态三类（`u_B`） | 含义 |
|---|---|
| `evaluated` | 已评估，不降档 |
| `assumed` | 假设/经验，结论封顶 `sensitivity` |
| `pending` | 缺证书/量程/未测，结论封顶 `mechanism` |

**两套词互不换算**——`evaluated` 不是等级、`quantitative` 不是状态；任何文档不得出现「judgment 级」「evaluated 等级」这类跨表拼词。等级只有三档，`judgment` 这个词不存在。

### 4.3 `invalid` 四类（不得混进 `blocked`）

> 下列四类记 `invalid`，**不得混进 `blocked`**——混进去等于把"测坏了"记成"爬不上"：① 无接触（未真正接触门槛）；② 穿透超限；③ 蠕滑基线超标；④ `v_impact` 不同源。

`invalid` 必须**同时**给绝对数 `n_invalid / n_total` 与比例；只给百分比视为不完整。一组只有 4 个 case 时，"invalid 25%"与"invalid 1 个"读起来完全不同——百分比让人误以为有统计意义，绝对数让人立刻看出"可用批次只剩 3 个"。**不得与 `blocked` 合并成"失败率"**。若某组 `invalid` 占比过高，该组结论写"可用批次 n 不足"，不许悄悄摊薄。

### 4.4 两个“不适用”值（枚举）

| 值 | 含义 | `missing` | 批次可用性 | 前提 |
|---|---|---|---|---|
| `N/A（none）` | 机型无此自由度 | `true` | 可用 | 模型必须有 `has_suspension=0` |
| `invalid（unmeasurable）` | 有此自由度但测不出 | `true` | 不可用 | — |

## 5. 缺失 vs 待标定

- 缺失：现场/图纸/仪器哪一环没有，需说明缺哪一环。
- 待标定：本轮范围外、已排下一轮的测量项（如 μ、轮端扭矩、台架通过率）。
- 两者都不得填进实测列，也不得用文献值顶替。

## 6. 单位与舍入

- 表内按量具分辨力给位数；模型侧统一 SI。
- 不确定度保留 2 位有效数字；`verified_tol` 修约后再用于判定。
- 角度：表内 °，模型 rad（换算在导入脚本里做，不在表里做）。

## 7. 报告表列（两列等级）

| field | 参数等级（label） | 结论等级（conclusion_level） | verified_tol | 读数 | A1–A4 | note |
|---|---|---|---|---|---|---|

**参数等级读"这个数从哪来"，结论等级读"这句话能说到多远"；两列不得只报其一；两列不同名时不得简称成"等级"。**

- 不同 `n` 的比率**不得放在同一张图上比较**。要么分开画，要么同图标注各自 `n` 且**不连线**。理由：斜向组 `n=4`、正对组 `n=20`，两条百分比曲线画在一起，读者会自动读成"斜向比正对差/好"，而这只是样本量差异。
- 对 `n` 很小的组（如斜向 `n=4`），**首选"逐 case 散点/表格"**（横轴 Δh，点形表示 `outcome`），按组**分面**（facets）呈现，不画比率曲线。
- 比率曲线只在同组内、同 `n` 且 `n ≥ 10` 时使用；否则用逐 case 呈现。
