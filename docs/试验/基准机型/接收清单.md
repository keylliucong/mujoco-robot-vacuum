# oomwoo 尺寸表｜接收清单（下游消费者 → 推导方）

- 版本：v1 · 2026-11-22
- 角色：本文件由**台账/报告消费者**提出，交给从 `oomwoo-cad` 推导尺寸表的一方。
- 目的：让 `docs/基准机型/` 的产物能**机械地**进入 `docs/参数溯源.csv`，而不是靠转述或二次抄数。
- 原则：一个 `param_id` 只指向一处来源；消费者不重算、不另立第二套 `machine=oomwoo` 数值。

## 1. 表级元数据（每张尺寸表必须有）

尺寸表可以按“整机 / 组件”拆成多张，但每张表的表头必须能独立回答下面 8 项。缺任一项，该表所有行最高只能记【工程假设】。

| 字段 | 要求 | 为什么必须 |
|---|---|---|
| `generated_by` | `script@<commit sha>`，脚本与尺寸表同目录、同提交 | 没有脚本版本，数值不可复现 |
| `input_file` | 输入文件名 | 与 sha 配对，避免“同名不同件” |
| `input_sha256` | 输入 STEP 的 sha256（64 位十六进制） | 输入可核 |
| `table_rev` | 尺寸表所在提交 sha；与 `generated_by` 的 sha 一致或写明差异 | 台账 `ref` 要 pin 到这一版 |
| `method` | `brep_exact` 或 `mesh(tol=<弦高/角度>)` | 决定是精确积分还是近似 |
| `mesh_drift` | 若 `method=mesh(...)`：同一参数在收紧一档容差后的漂移量，单位与参数一致 | 没有漂移评估就按“不豁免”处理 |
| `env` | 解释器、库版本、CAD 内核名+版本；是否依赖 CAD 内核 | 同一脚本不同环境会出不同数 |
| `frame` | 坐标系定义；若做 B 系换算，写清原点、轴向和变换 | 否则 com/inertia 无法入台账 |

### 1.1 数值豁免判据（mesh 来源逐参数用）

对每个由 mesh 近似得到的参数，尺寸表必须给出三列：

| 列 | 含义 |
|---|---|
| `容差引起的漂移` | 收紧 tessellation 容差后该参数的变化量 |
| `该参数目标容差` | 本项目台账/验收限对该参数的目标容差（见 §3） |
| `漂移÷容差` | 两者的比值 |

- 比值 `> 1/3` → **不豁免**，标签降【工程假设】，`note` 写“mesh 容差漂移 X 超过容差 1/3”。
- 比值 `≤ 1/3` → 可保留【图纸推算】，`note` 写漂移值与该参数目标容差。
- 尺寸表**未给** `method=mesh(tol=…)` 或**未给**漂移评估 → 按不豁免处理（缺证据即不放行）。

## 2. 行级字段（每个 `param_id` 一行）

| 字段 | 必填 | 说明 |
|---|---|---|
| `param_id` | 是 | 用本清单 §3 的名字；不要自造同义名 |
| `value` | 是 | 数值；不要带单位、不要千分位、不要引号 |
| `unit` | 是 | `kg` / `mm` / `kg·m²` / `kg·mm²` / `N·mm` / `°` 等；与 value 一致 |
| `method_note` | 是 | 一句话说清这个值怎么来的（选中哪个 solid、哪个轴、哪个参考点） |
| `ref_point` | 惯量/com 必填 | `body_CoM` 或 `B_origin`；组件表可写 `component_CoM` |
| `axes` | 惯量/com 必填 | `B` 或 `STEP`；组件表写 `STEP` 时必须给到 B 的变换 |
| `role` | 建议 | `primary` / `check` / `derived`；同量不同参考点各占一行，不共用 |
| `target_tol` | 建议 | 该参数目标容差；用于 §1.1 的漂移判据 |
| `drift` | mesh 必填 | 见 §1.1 |
| `note` | 是 | 缺项、假设、与公开参考的偏差都写在这里 |

> 尺寸表**不要**重复 `param_id`。同一 `param_id` 出现两次即台账缺陷。

## 3. 需要哪些 `param_id`

按“先能入台账、再谈完整”排序。**A 组**是整机建模的最小集；**B 组**是越障判据需要但 CAD 很可能给不出的；**C 组**是组件级旁证。

### A 组：整机几何与质量属性（必须来自整机装配，不能由组件拼）

| `param_id` | 单位 | 参考点/轴向 | 目标容差 | 备注 |
|---|---|---|---|---|
| `m_dry` | kg | — | 3 g | 空载、标准电池、无尘盒水箱；CAD 只能给 `ρ·V`，**必须另给 `rho_source`** |
| `rho_effective` | kg/m³ | — | — | 整机等效密度；来源写“材料表/称重反推/假设”，不得只给一个数 |
| `com_x` | mm | `B_origin`，`axes=B` | 1 mm | B 系：+x 前进，原点=左右驱动轮轴心连线中点在地面的投影 |
| `com_y` | mm | 同上 | 1 mm | 对称件应接近 0；若不为 0，写清是哪一侧偏置 |
| `com_z` | mm | 同上 | 2 mm | **一阶变量**；见 §4 的专门要求 |
| `Ixx` / `Iyy` / `Izz` | kg·m² | `body_CoM`，`axes=B` | 5–10%（相对，待冻结） | 关于质心的对角项；另给 `Ixy/Ixz/Iyz` |
| `Ixy` / `Ixz` / `Iyz` | kg·m² | `body_CoM`，`axes=B` | 绝对口径 | 不得用相对容差；接近 0 的量 |
| `principal_1/2/3` | kg·m² | `body_CoM` | 同上 | 与主轴夹角一起给；没有就写“未给” |
| `bbox_x` / `bbox_y` / `bbox_z` | mm | `axes=B` | 1 mm | 全包络（含 bumper、LiDAR、轮） |
| `body_diameter` | mm | `axes=B` | 1 mm | 圆体最大外径；若为 349/355 之类转引值，必须写“转引” |
| `body_height` | mm | `axes=B` | 1 mm | 含 LiDAR 塔 |
| `clearance_min` | mm | `axes=B` | 0.5 mm | 静态、平地、额定载荷；附最低点 `(x,y)` |
| `hub_z` | mm | `B_origin` | 0.5 mm | 轮心高度；决定 B 系原点 z |
| `wheel_track` | mm | `axes=B` | 0.3 mm | 左右轮中心距 |
| `wheelbase` | mm | `axes=B` | 0.3 mm | 驱动轮轴→从动轮中心；写明“轴距”定义 |
| `caster_x` / `caster_z` | mm | `B_origin` | 0.5 mm | 从动轮中心位置 |

### B 组：越障判据需要、CAD 通常给不出的量

| `param_id` | 单位 | 为什么 CAD 给不出 | 建议处理 |
|---|---|---|---|
| `k_susp` | N/mm | 需要弹簧材料/几何/预压，STEP 不含 | 标【缺失】，排实测 |
| `F0` | N | 预紧力是装配状态，不是几何 | 标【缺失】，排实测 |
| `c_susp` | N·s/mm | 阻尼不可由静态几何推出 | 标【缺失】，排实测 |
| `travel` | mm | 需要运动副行程/限位，单姿态 STEP 不含 | 若能给出极限姿态两套 STEP，可推算；否则【缺失】 |
| `F_limit` | N | 限位刚度/材料 | 【缺失】 |
| `i_gear` | — | 齿轮箱内部齿轮，需拆解/图纸 | 用公开参考 65.36:1（第三方实测），不冒充图纸推算 |
| `T_wheel` | N·m | 电机曲线+减速比+效率 | 【缺失】或公开参考 |
| `mu_s` / `mu_step` | — | 接触物理量，不是几何 | 【待标定】 |

> B 组不要为了“凑齐”而用 BOM 零件位置或经验值填。尤其 `z_cg` 和 `m` 不许用“零件清单位置”凑。

### C 组：组件级旁证（可选，但很有用）

| `param_id` | 单位 | 用途 |
|---|---|---|
| `wheel_diameter` | mm | 与公开参考 71.5 mm 对照；也可用于 `r_wheel` |
| `wheel_width` | mm | 接触几何 |
| `wheel_mass` | kg | 需给 `rho` 与 `rho_source`；否则只作量级 |
| `caster_diameter` | mm | 从动轮几何 |
| `drive_group_mass` | kg | 驱动轮组（含电机/减速箱/胎）质量；**必须能按组件分离** |
| `body_mass` | kg | 车体（不含轮组）质量；用于敏感性，不替代整机 |
| `suspension_mass` | kg | 悬挂件质量；若无法从装配分离，写“不可分离” |

## 4. `z_cg` 的专门要求

`z_cg` 是**一阶变量**，不能给单点值当基准。请按下面任一条交付：

1. **能给出扫描范围**：给 `z_cg_min` / `z_cg_max`，并写清扫描变量（分件密度、电池位置、尘盒/水箱载荷、装配姿态）。报告只会写“扫描范围内”，不写单点。
2. **只能给单点**：允许给 `com_z`，但必须同时写：
   - `method`（B-rep 精确积分 / mesh 近似 + tessellation 容差）；
   - `uniform_density_assumption=yes/no`；
   - 若为均匀密度，明示“未覆盖电池/电机/尘水等分件密度差异，不能作为基准机型 `z_cg` 的基准值”；
   - 该行标签最高【工程假设】，不得记【图纸推算】。

> 本项目的报告骨架不会出现“通过高度”或任何比率；`z_cg` 只作为扫描输入登记，不做单点判定。

## 5. 组件可分离性（资产盘点的硬要求）

请按下面三组分别给出“能否从整机装配中分离”，并附分离依据（solid tag / 包围盒 / 体积 / 位置）：

| 组 | 包含 | 需要的输出 |
|---|---|---|
| 驱动轮组 | 左右轮、轮胎、轮毂、电机/减速箱（若在装配内） | 每侧 `mass`、`com`、`I`、轮径、轮宽、轮心位置 |
| 车体 | 底盘、上盖、bumper、LiDAR 塔、电池、尘盒/水箱（若在） | `mass`、`com`、`I`、包络、最低点 |
| 悬挂件 | 摆臂、弹簧、限位、轮架 | 能否分离；不能则写“不可分离”，不要估算 |

如果整机 STEP 是单一 `PRODUCT('COMPOUND')`、solid 无名称，请直说“只能按几何启发式分离”，并给出所用规则与误判风险。**不要把“几何上像轮子”当成“机构上就是驱动轮组”。**

## 6. 当前已知的阻塞（供推导方优先处理）

1. `device_full.step` 来自 `designs/one/agentic/july-2026/`，该目录 README 明示：**“This is not the OOMWOO One design”**，并列出脚轮装反、侧刷方向错误等已知缺陷。用它算出的整机 `m/com/I` 不能直接当 OOMWOO One 的基准几何。
2. 整机 STEP 只有 `PRODUCT('COMPOUND')` 一个产品，**没有零件名/装配树**；组件分离只能靠几何启发式。
3. STEP **不含材料密度**；当前组件表用的 `rho=1100/1240 kg/m³` 是显式假设，不是 CAD 材料。没有 `rho_source`，`m` 只能记【工程假设】。
4. 正式设计链的 `designs/one/fusion360/Top_Assembly_110926.f3z` 是原生 Fusion 360 归档，**没有对应的整机 STEP 导出**；本仓库里能直接算的整机 STEP 只有实验装配。
5. 上游 `docs/基准机型/` 目前只有驱动轮组件表（上游分支 `a5e5ff7`，未推送）；**还没有整机尺寸表**。在整机表到位前，台账里 `m/com/I` 只能占位，不能填数。

## 7. 交付即验收（消费者会怎么核）

对每行按 S17 四项核：

1. 推导脚本存在，且 `script_rev` 能在提交里找到；
2. 输入文件 `input_sha256` 与 `sha256sum` 一致；
3. 输出尺寸表存在，且 `param_id` 不重复、单位与 value 一致；
4. 环境声明存在，含解释器/库版本、CAD 内核、`brep_exact` 或 `mesh(tol=…)`。

**四项缺一 → 该行降【工程假设】**，并在台账 `note` 写缺哪一项。消费者不会因为表里写了“图纸推算”就直接采信。
