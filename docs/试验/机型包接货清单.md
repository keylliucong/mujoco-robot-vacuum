# 机型包接货清单（机型包 → 记录表 / 台账）

- 版本：v1 · 2026-11-22 · 试验侧接收路径
- 适用范围：别人交来一个机型包（`robot.urdf` + `params.json` + `sources.md`，见 [机型包规范](../机型包规范.md)）时，试验侧怎么把它接到自己的记录表与 `docs/参数溯源.csv`。**本清单不跑标定、不写代码、不改机型包规范**。
- 字段来源：下表字段名逐字取自 [机型包规范](../机型包规范.md)，不自造；`param_id` 取自 [参数溯源.csv](../参数溯源.csv)，键法按 [ADR-017](../契约/ADR/ADR-017-台账键形三段-config_id.md) 的 **proposed** 形状（`<machine>.<config_id>.<量名>`，待架构师裁定，未生效；示例用 `own.unloaded.*`；换机型换前缀、配置进 `config_id`，不共用键）。
- 载荷键形（**proposed（待架构师裁定，未生效）**）：随载荷/配置变化的量建议用 `<machine>.<config_id>.<量名>`，`config_id` 与 `ref` 里的 `config_id=` 逐字相同（`own.unloaded.*` / `own.sealed_full_water.*` / `own.equiv_ballast.*` / `own.full_witness.*`）；惯量六分量各占一键、不设张量容器单键。**需求不撤**：载荷状态必须能区分，v1.4 要求两套载荷配置各占一个 `param_id`；具体形状由架构师定，裁定前不新建台账键。下表示例键按此建议形状列；台账暂无行的标【待补行】，接货时先按台账现有行落行。
- 接货路径：收包 → 跑规范里的 `check_machine_pack.py`（只查格式/引用，不查物理）→ 按 §接货时的三问 逐项确认 → 按本表落记录表行与台账行 → 需要模型对齐的字段交 S21/S22 机械检查。

## 取值约定（先读，再看表）

| 记号 | 含义 | 用在哪 |
|---|---|---|
| `null` | 不知道。包内 `value: null` 且 `source: "missing"`；台账照常成行、`label=缺失`、`xpath` 留空；**绝不填 0**。 | 数值字段没测出来、也没有可信来源时 |
| `invalid（unmeasurable）` | **有这个自由度但测不出**，批次不可用。 | 仅 `travel_m` 这类前置量：`suspension=true` 却测不出行程；不得事后补测推定 |
| `N/A（none）` | **机型没有这个自由度**，批次仍可用，模型须有 `has_suspension=0`。 | `suspension=false` 时：包内省略悬挂条目；记录表/验收限写 `N/A（none）`（不是空值） |
| 不适用 | 标识 / 结构 / 布尔 / 文本字段，不建台账行、无容差；由格式检查和人工核对保证。 | `schema_version`、`machine_id`、link/joint 名、枚举等 |

> 按对称性设 0 **不是第三个枚举值**：包内写 `value: 0` + `source: "assumed"` + `note` 写理由；台账记 `value=0` + `label=工程假设`。数值格只填数字，不得把 `0（assumed）` 当字面值填进 `value`。

> 台账 `verified_tol` 一律是**绝对量、与 `value` 同单位**（契约 §6.1.1），取 `k·u_c`（默认 `k=2`）。纯重复性 `3σ` 只是 `diag_3sigma_A` 诊断列，不作判定限；相对容差只准用于真值远离 0、且典型量级 ≥ 10×`verified_tol` 的量。下表「允许多大误差」列写目标 `verified_tol`（标注绝对/相对），来源是 [记录表模板 §5](记录表模板-2026-11-21.md)；接货时不得自己改写目标，达不到就换量具/加次数并留痕。目标值只用于选量具、定重复次数；本轮 `u_B` 多为 `pending`，台账 `verified_tol` **为空**，不得把目标值写进台账（`CAL-023`）。

## 试验侧不验的字段

以下几类**试验侧不验**，接货时只核对其 `source` 标记与来源材料，不记实测列：

- **越障前沿几何（如 `front_lip_radius_m`）**：目前只能从 CAD / 图纸取，**试验侧不验，标来源【图纸推算】**。该字段名尚未进入 [机型包规范](../机型包规范.md)（规范内的轮半径是 `drive_wheels[].radius_m`），此处作为预登记项列出：若后续版本收录，处理口径不变。标【图纸推算】须满足契约 §4 可核三元组（推导脚本 + 输入文件 sha256 + 输出尺寸表）+ 运行环境声明，缺一降【工程假设】；三元组齐备也只到 `sensitivity`，升 `quantitative` 仍须逐行实测交叉校核，`verified_tol` 由 `docs/不确定度预算.csv` 出，不由本清单给。
- **包内所有几何拓扑与命名**（`base_link`、各 `link` / `joint` 名、`position` 的填写方式）：试验侧只做逐字引用核对，不实测；由格式脚本与 S02 单一来源规则保证。
- **`capabilities.*` 布尔声明**：试验侧只按实物有无确认一次，不产出数值；声明与模型一致性归 S22。
- **附件材料本身**（URDF 内 mesh / STEP / 图纸）：试验侧不解析几何内容；若 `source=cad`，只核对 `sources.md` 是否写了输入版本、推导记录与可核三元组。

## 接货时的三问

### 一问：参数齐不齐？

- 按 [机型包规范](../机型包规范.md) 数：固定必填顶层 9 项 + 每只驱动轮 5 项（`link`/`joint`/3 个数值记录）+ 每个从动支撑点 4 项 + `assembly` 10 项 + 每个数值记录的 `value`/`source`/`note` 3 项；条件必填按实际配置加：`payload_addition` 10 项（带载）、`suspension_joints` 2 项（有悬挂）。
- **缺的写 `null`，不许填 0**。`null ≠ 0`：拿 0 代替未知悬挂行程会把 `min(0.5 mm, 5%·travel)` 压成 0.5 mm 以下的误判；拿 0 代替未知横向质心会把对称假设伪装成实测。
- 台账侧「缺」要**成行**：`value` 空、`label=缺失`、`xpath` 留空（ADR-014）；「没这一行」不是表达缺失的方式。同一载荷状态的 `m/com/inertia` 必须成套成行，分组键是（`payload_state`, `config_id`），`sealed_full_water` 与 `equiv_ballast` 各占 `param_id`，不共用。
- 对称设 0 是合法取值，但必须 `source=assumed` + `note` 写理由，不能记成本机实测。

### 二问：来源标得对不对？

- 包内 `source` 五值 → 台账 `label` 六值的对应：`measured` →【本机实测】；`datasheet` →【公开参考】（外部来源 `ref` 必带 `source=` / `retrieved=` / `rev=`，能 pin 就 pin，无 `rev` 不得引 `path:line`）；`cad` →【图纸推算】（须满足可核三元组 + 运行环境声明，否则降【工程假设】）；`assumed` →【工程假设】；`missing` →【缺失】。本轮不测、已排下一轮的项（如 `torque_limit_nm` / `speed_limit_radps` / μ）记【待标定】，不得用规格书值顶替实测列。
- 判据是「谁做的推算」：外部资料**直接给出** →【公开参考】；我们从该机几何**自己推算** →【图纸推算】。基准机型（`oomwoo`，无 CAD）**拿不到【图纸推算】档**，只能【公开参考】，不得作为本机定量输入。
- 看 `sources.md` 是否写清机型与修订、配置实装、B 原点与方向、URDF 导出来源、各组参数原始资料位置与待补项；每个 `note` 是否能落到对应小节。对不上就把该行标【缺失】退回，不替交包方猜。

> 本清单只管**参数行** `label`（六值：本机实测 / 图纸推算 / 公开参考 / 工程假设 / 缺失 / 待标定）；`u_B` 分量的 `status`（`evaluated` / `assumed` / `pending`）三值见 `docs/不确定度预算.csv`，两者不换算、不混用。

### 三问：有没有「机型包说有、模型没有」的字段？

这层的机械比对归 S22（能力声明与模型两端一致）/ S21（附加载荷 10 行成套），本清单只列出**需要人工确认**的项：

| 人工确认项 | 对不上的后果 |
|---|---|
| `capabilities.suspension=true` ↔ URDF 有 `suspension_joints` 条目 ↔ 模型有 `susp_L/susp_R` 关节/执行器 ↔ MJCF `has_suspension=1` | S22 失败；无悬挂却填假行程会让 `5%·travel` 变成假判据 |
| `capabilities.steering` / `lift` 声明 ↔ 适配器是否支持该机构 | 声明通过格式检查也不代表能跑，须人工确认 |
| `payload_addition` 10 项 ↔ 台账 10 个独立 `param_id` 行（按 `config_id` 分组，`ref_point=body_CoM`、`axes=B`） | S21 失败；缺行时该载荷状态不得出定量结论 |
| `drive_wheels[].torque_limit_nm` / `speed_limit_radps` ↔ 是否写入 XML `forcerange` / 关节 `velocity` | 若写入，每个生效量需独立 `param_id` 并绑定 `xpath`，保留换算血缘（S02/S17） |
| `support_points[].position` ↔ URDF link 原点或 B 系坐标是否为同一配置静止姿态 | 支撑多边形判定会偏，且来源版本无法追溯 |
| `base_link` / 各 `link` / `joint` 名 ↔ URDF 与模型名称表逐字一致 | runner 用 `mj_name2id` 按名取，改名即取不到 |

> 若交包方另给了 `front_lip_radius_m` 这类规范未收录的字段：模型侧若无对应几何/适配器入口，人工确认后写进 `sources.md` 待裁定，不进试验侧实测列。
