# 机型包接货清单 口径核对（PR #35）

- 核对日期：2026-11-22
- 核对对象：PR #35 `trial/g4` @ `c25c5b0`，文件 [机型包接货清单.md](机型包接货清单.md)
- 核对基准：契约 v1.8.3（`docs/契约/G2-接口契约.md` @ `93023d1`，含 `S24` 与 §6.5）、[数据字典](数据字典.md) v1（含 §3.3）、[记录表模板](记录表模板-2026-11-21.md) v2、[验收限冻结](验收限冻结-2026-11-21.md)、[口径台账](口径台账.md)、`docs/参数溯源.csv`
- 结论：**8 项已全部处置**。主口径（来源五值 → 标签六值、`null` 语义、`verified_tol` 绝对量、`param_id` 机型前缀）一致；D1–D3、D6–D8 已修正；D4/D5 已按定稿三段键 `<machine>.<config_id>.<量名>`（契约 v1.8.4 / ADR-016）回填，`config_id` 与 `ref` 的 `config_id=` 逐字相同；无阻塞合并项，待试验标定复核后再合。
- 本文件记录差异与处置：文本修正与 D4/D5 的定稿键形回填均在 PR35 内完成；**不改** `docs/参数溯源.csv`（不新建、不改动别人已有的键行）。
- D4/D5 的需求（载荷状态必须进键或等效区分）由台账 owner 提出，**形状已定稿**：`param_id = <machine>.<config_id>.<量名>`。`config_id` 是配置标识（`unloaded` / `equiv_ballast` / `sealed_full_water` / `full_witness` / `hypo` 等），**不是** `payload` 段——同一载荷可以有两种实体配置，只用载荷态会撞键；必须与 `ref` 里的 `config_id=` 逐字相同，可机检。惯量六分量各占一键（含 `I_att` 六个），不设张量容器单键。PR35 已按定稿键形回填并修正其余 6 项；本文不擅改台账既有行。

## 2. 差异清单

> 「阻塞合并」= 照此合并会把一个不存在的键或非数值写法带进台账/记录表；「文本修正」= 不改变语义，但机械检查会漏或读者会误读。

| 编号 | 位置（行） | 现状 | 应对齐的口径 | 影响 | 建议 | 级别 |
|---|---|---|---|---|---|---|
| D1 | 13–14 行 | `invalid(unmeasurable)`、`N/A(none)` 用**半角**括号 | 数据字典 §4.4、验收限 §5 用**全角**：`invalid（unmeasurable）`、`N/A（none）` | `grep`/脚本按字面取值会漏；同一仓库两种写法 | 二选一后全库统一（建议跟数据字典/验收限走全角） | 已修正（本 PR） |
| D2 | 15 行；58–60 行 | 把 `0（assumed）` 与 `null` / `invalid` / `N/A` 并列成「记号」，并用在「没测出来记什么」列 | 数据字典 §4.4 只定义两个特殊值；契约 §4 规定「按对称性设 0」是 `value=0` + 【工程假设】（包内 `source:"assumed"`） | 有人可能把字面 `0（assumed）` 填进数值格；数值格只能填数字 | 改为「`value=0` + `source:"assumed"` + `label=工程假设`」，不新增第三个枚举记号 | 已修正（本 PR） |
| D3 | 14 行；72 行 | `suspension=false` → `N/A(none)`（**整组省略**） | 机型包规范：包内省略悬挂条目；数据字典 §4.4 / 验收限 §5：`N/A（none）` 是**要写下来的值**（`missing=true`），`A2` 判 `N/A` | 包内省略后，记录表/验收限侧没有可引用的值，`A2` 的 `N/A` 变成空值 | 拆成两句：「包内整组省略；记录表/验收限写 `N/A（none）`，不是空值」 | 已修正（本 PR） |

## 3. 定稿键形（契约 v1.8.4 / ADR-016）

下列三段键是 **定稿** 形状 `<machine>.<config_id>.<量名>`：`config_id` 是配置标识、与 `ref` 的 `config_id=` 逐字相同，不用 `payload` 段；惯量六分量各占一键、不设张量容器单键。列在这里是为了说明「哪些量随载荷/配置变」，示例按新键形写，台账既有行由 owner 维护、本文不改：

| 组 | 键 | 数量 |
|---|---|---|
| 整机质量 | `own.unloaded.m`、`own.equiv_ballast.m`、`own.sealed_full_water.m` | 3 |
| 配重附加质量 | `own.equiv_ballast.m_payload` | 1 |
| 整机质心 | `own.<config_id>.com_x` / `com_y` / `com_z`（`config_id = unloaded / equiv_ballast / sealed_full_water`） | 9 |
| 整机惯量 | `own.<config_id>.Ixx` / `Iyy` / `Izz` / `Ixy` / `Ixz` / `Iyz`（同上三 config_id） | 18 |
| 载荷附加惯量 | `own.equiv_ballast.I_att.xx` … `own.equiv_ballast.I_att.yz`、`own.sealed_full_water.I_att.xx` … `own.sealed_full_water.I_att.yz`（六分量各占一键） | 12 |

> 旧两段键（`own.m_dry`、`own.com_x`、`own.Ixx`、`own.I_att_equiv_ballast` 等）在新键补行后按台账规则标 `superseded_by` 或保留为历史行，由 owner 定，本文不擅自删行。
> `full` 载荷对应 `sealed_full_water` 与 `full_witness` 两个 `config_id`，是否共用待 owner 定（见 [数据字典 §3.3](数据字典.md) TODO）。

## 4. 与本次新增摩擦口径的关系

- PR35 第 97 行把 μ 列为「下一轮、记【待标定】」，与数据字典 §3.3 不冲突。
- 但 PR35 未写「μ 必须分 `mu_s` / `mu_step` 两行、不得合并」；合并后的接货清单应回链到 [数据字典 §3.3](数据字典.md) 与 [记录表模板 §5.4](记录表模板-2026-11-21.md)，避免接货时又把两层表面合成一个 `mu`。
- 这是回填项，不是差异项：PR35 没有写错，只是写在新口径之前。

## 5. 复现方式

```sh
# 具体 param_id 是否在台账存在（<machine>.* 模板占位与 <payload> 待补键会显示 MISS）
python3 - <<'PY'
import csv, re
led = {r['param_id'] for r in csv.DictReader(open('docs/参数溯源.csv', encoding='utf-8')) if r.get('param_id')}
txt = open('docs/试验/机型包接货清单.md', encoding='utf-8').read()
for k in sorted(set(re.findall(r'`([A-Za-z0-9_<>\.]+(?:\.[A-Za-z0-9_]+)+)`', txt))):
    if k.startswith(('own.', 'oomwoo.', 'prototype.')) or k.startswith('<machine>'):
        print('OK  ' if k in led else 'MISS', k)
PY
```

> 当前预期：键形按 §3 定稿三段、`config_id` 与 `ref` 逐字一致；`OK`/`MISS` 以脚本实跑为准（脚本检查 PR35 接货清单，本文不改台账既有行）。
