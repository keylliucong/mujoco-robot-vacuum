# 机型包接货清单 口径核对（PR #35）

- 核对日期：2026-11-22
- 核对对象：PR #35 `trial/g4` @ `c25c5b0`，文件 [机型包接货清单.md](机型包接货清单.md)
- 核对基准：契约 v1.8.3（`docs/契约/G2-接口契约.md` @ `93023d1`，含 `S24` 与 §6.5）、[数据字典](数据字典.md) v1（含 §3.3）、[记录表模板](记录表模板-2026-11-21.md) v2、[验收限冻结](验收限冻结-2026-11-21.md)、[口径台账](口径台账.md)、`docs/参数溯源.csv`

- 本文件**只列差异，不改** `机型包接货清单.md`；差异由该文件作者与台账 owner 处理。

## 2. 差异清单

> 「阻塞合并」= 照此合并会把一个不存在的键或非数值写法带进台账/记录表；「文本修正」= 不改变语义，但机械检查会漏或读者会误读。

| 编号 | 位置（行） | 现状 | 应对齐的口径 | 影响 | 建议 | 级别 |
|---|---|---|---|---|---|---|
| D1 | 13–14 行 | `invalid(unmeasurable)`、`N/A(none)` 用**半角**括号 | 数据字典 §4.4、验收限 §5 用**全角**：`invalid（unmeasurable）`、`N/A（none）` | `grep`/脚本按字面取值会漏；同一仓库两种写法 | 二选一后全库统一（建议跟数据字典/验收限走全角） | 文本修正 |
| D2 | 15 行；58–60 行 | 把 `0（assumed）` 与 `null` / `invalid` / `N/A` 并列成「记号」，并用在「没测出来记什么」列 | 数据字典 §4.4 只定义两个特殊值；契约 §4 规定「按对称性设 0」是 `value=0` + 【工程假设】（包内 `source:"assumed"`） | 有人可能把字面 `0（assumed）` 填进数值格；数值格只能填数字 | 改为「`value=0` + `source:"assumed"` + `label=工程假设`」，不新增第三个枚举记号 | 文本修正 |
| D3 | 14 行；72 行 | `suspension=false` → `N/A(none)`（**整组省略**） | 机型包规范：包内省略悬挂条目；数据字典 §4.4 / 验收限 §5：`N/A（none）` 是**要写下来的值**（`missing=true`），`A2` 判 `N/A` | 包内省略后，记录表/验收限侧没有可引用的值，`A2` 的 `N/A` 变成空值 | 拆成两句：「包内整组省略；记录表/验收限写 `N/A（none）`，不是空值」 | 文本修正 |
| D4 | 63–64 行 | `payload_addition.com_y_m` → `own.com_y`（**带载配置另起键**）；`com_z_m` → `own.com_full_z` / **配重 z 键** | 台账只有：`own.com_y`（`config_id=unloaded`）、`own.com_ballast`（单行，无 `_y`/`_z`）、`own.com_full_x` / `own.com_full_z`；**无** `own.com_ballast_y`、`own.com_ballast_z`、`own.com_full_y` | 照「另起键」造出的键在台账无行；退回用 `own.com_y` 又会把带载质心记进空载配置，违反 `(payload_state, config_id)` 分组 | 台账 owner 先补 `own.com_ballast_y/z`、`own.com_full_y`（或明确 `own.com_ballast` 是三分量容器），PR35 再引用实名 | **阻塞合并** |
| D5 | 65–71 行 | 附加载荷 6 个惯量字段各写「另一 `param_id`」，示例 `own.I_att_equiv_ballast` / `own.I_att_sealed_full_water` | 台账每个 `config_id`**只有 1 行**：`own.I_att_full_witness` / `own.I_att_equiv_ballast` / `own.I_att_sealed_full_water`（无轴后缀）；记录表 §5 写 `I_att_sealed_full_water_*`（每轴一 id） | 6 个字段无法各绑一个现存 `param_id`；`S21` 成套性检查会失败，或逼出临时键 | 先定台账形状（一 config 一行张量，还是每轴一行），再让 PR35 与记录表 §5 同步 | **阻塞合并** |
| D6 | 46 行 | 模板写 `<machine>.caster.radius`（待建；现有形如 `oomwoo.caster.radius`） | 台账：`oomwoo.caster.radius` 有；`prototype` 是 `prototype.geom.caster.radius`（多一段 `geom`）；`own.caster.radius` **不存在** | 前缀规则对，但量名段不统一；照抄模板会造出 `own.caster.radius` 这种孤儿键 | 台账统一 `<machine>.caster.radius`，或 PR35 改为按机型列实际键；已标「待建」，可在建键时收口 | 文本修正（已标待建） |
| D7 | 18 行 | 「下表『允多大误差』列写**目标** `verified_tol`……接货时不得自己改写目标」 | 数据字典 §5 / 口径台账 `CAL-023`：有 `pending` 分量的参数，台账 `verified_tol` **必须为空**；目标值不能写进台账 | 读者可能把目标值当台账值填，违反「容差没有刻度就不许填数」 | 加一句：「目标值只用于选量具/定次数；本轮 `u_B pending`，台账 `verified_tol` 为空」 | 文本修正 |
| D8 | 全文 | 未出现 `u_B` 分量的 `status` 三值（`evaluated/assumed/pending`），边界未声明 | 契约 v1.7.2 / v1.8.3：六值 `label` 只用于参数行；预算表分量用三值 `status` | 无直接冲突；但本清单若被当成「标签总表」，会把 `label` 套到分量上 | 加一句边界：「本清单只管参数行 `label`；`u_B` 分量 `status` 见 `docs/不确定度预算.csv`」 | 文本修正 |

## 3. 与本次新增摩擦口径的关系

- PR35 第 97 行把 μ 列为「下一轮、记【待标定】」，与数据字典 §3.3 不冲突。
- 但 PR35 未写「μ 必须分 `mu_s` / `mu_step` 两行、不得合并」；合并后的接货清单应回链到 [数据字典 §3.3](数据字典.md) 与 [记录表模板 §5.4](记录表模板-2026-11-21.md)，避免接货时又把两层表面合成一个 `mu`。
- 这是回填项，不是差异项：PR35 没有写错，只是写在新口径之前。

## 4. 复现方式

```sh
# 具体 param_id 是否在台账存在（模板占位 <machine>.* 除外）
python3 - <<'PY'
import csv, re
led = {r['param_id'] for r in csv.DictReader(open('docs/参数溯源.csv', encoding='utf-8')) if r.get('param_id')}
txt = open('docs/试验/机型包接货清单.md', encoding='utf-8').read()
for k in sorted(set(re.findall(r'`([A-Za-z0-9_<>\.]+(?:\.[A-Za-z0-9_]+)+)`', txt))):
    if k.startswith(('own.', 'oomwoo.', 'prototype.')) or k.startswith('<machine>'):
        print('OK  ' if k in led else 'MISS', k)
PY
```
