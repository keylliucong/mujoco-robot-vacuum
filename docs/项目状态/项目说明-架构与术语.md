# mujoco_ 越障仿真 · 架构、排期与术语

## 一句话定位

输入一个机型（1 个 URDF + 参数），跑越障仿真，按判据判达标与否，不达标指出该改哪里。

## 一、架构：五层，一层管一件事

**① 输入层（你给的）**：机型包：`machine_packs/<name>/robot.urdf`（唯一 3D 入口）+ `params.json`（质量/质心/惯量/悬挂/轮组/支撑件）+ `sources.md`（每个数从哪来）。校验脚本 `scripts/check_machine_pack.py` 会挑出缺字段、单位错、URDF 里找不到的 link。

**② 建模层**：把机型包变成 MJCF：`models/*.xml` 只写结构（body 树、关节、geom、接触对），数值全部来自 `params/<config_id>.json`。**换机型 = 换一个 JSON，不重写模型。**

**③ 运行层**：工况库 `cases/*.json`（平地 / 台阶 / 斜面，台阶由 runner 注入）+ 批量入口 `scripts/run_cases.py`。每批先跑「静置蠕滑基线」，超红线自动降档 1 ms / 0.5 ms 重跑并双档同报。

**④ 判定层**：`judge.py`（不 import mujoco）：按接触事件判 `cleared / blocked / invalid` 与失败机理（`lift_fail`、`slip_stall`、`belly_contact`）；判据 A1–A4（试验侧称 T-A1…T-A4）做批次有效性筛选。

**⑤ 台账与报告（可追溯）**：`docs/参数溯源.csv`（每行一个 `param_id`，带来源标签与 `xpath`）+ `docs/不确定度预算.csv`（u_A / u_B 分量）+ 报告（结论等级、边界图、未覆盖项）。**数字没有来源标签，就不能进结论。**

## 二、排期：六道 Gate 就是五次"能不能往下走"

| Gate | 验什么 | 出口判据 | 现在 |
| --- | --- | --- | --- |
| G0 | **输入齐不齐**：每个参数有来源、有责任人 | 参数齐、标签清楚、缺的写【缺失】 | **部分** 本机数据未到，先用 oomwoo 基准 |
| G1 | **尺子准不准**：接触力读出来的数可不可信 | 法向力误差 ≤1%、两种摩擦锥一致 | **已过** 已签字并入 main |
| G2 | **流水线通不通**：模型、工况、判定三件能凑成可重复的一跑 | 三类工况 + 失败算例 + 两次逐位一致 | **收口中** 5 支分支 rebase 到 main |
| G3 | **结论怕不怕换时步**：2 / 1 / 0.5 ms 下结论会不会翻 | 标出结论适用的时步范围（不是通过与否） | **在跑** 三工况 × 三档 |
| G4 | **模型像不像真机**：算出来的数和实测对不对得上 | 拟合集报告 + 验收限先冻结（先定门槛再看结果） | **等数据** 模板与骨架已交 |
| G5 | **没见过的工况能不能复现**：留出集独立验证 | 超限就如实标未通过 | **未开始** |
| G6 | **出结论并定级**：边界图 + 可信度 + 优化建议 | 边界图 + 机理/敏感性/定量三档定级 | **未开始** |

路径：G2 收口 → G3（在跑）→ G4 等数据 → G5 → G6。当前唯一真正的外部阻塞是**机型数据到货**与**标准全文**。

## 三、英文与缩写：每个都一句话解释

### A. 流程与等级

| 词 | 什么意思 · 为什么存在 |
| --- | --- |
| Gate（G0–G6） | "关卡"。每道有明确出口判据，不过就不许往下做——防止拿没验证的模型去出结论。 |
| mechanism / sensitivity / quantitative | 结论可信度三档：机理级（方向对、无数字）→ 敏感性级（能排序、不能定量）→ 定量级（给数字）。**本轮封顶在 mechanism。** |
| label（来源标签） | 六种：本机实测 / 公开参考 / 图纸推算 / 工程假设 / 缺失 / 待标定。决定这个数能被用到哪一档结论。 |
| status（运行状态） | `ok / invalid / diverged`：这次跑得算不算数。**与上面的等级是两回事。** |
| outcome（单次结果） | `cleared`（越过）/ `blocked`（没越过）/ `invalid`（数据无效）。是**观测**，不是判定。 |
| failure_mode | 没越过的机理：`lift_fail` 抬不上去、`slip_stall` 打滑失速、`belly_contact` 托底。 |

### B. 判据与阈值

| 词 | 什么意思 |
| --- | --- |
| A1–A4（试验侧 T-A1…T-A4） | 准静态四条：A1 接近速度 ≤ √(0.02·g·Δh)；A2 悬挂压缩偏差 < min(0.5 mm, 5%·travel)；A3 加速度 ≤0.05 m/s²；A4 扭矩无阶跃（本轮用电流代理）。**改名 T- 是为了不与模型自检 A1–A5 撞车。** |
| h_pass | 能通过的最高台阶高度（mm）。本轮模型只对 h ≤ 12.5 mm 成立。 |
| Δh_pass,range | 扫描某参数时，通过高度的变化量（mm）——用来看"这个参数重不重要"。 |
| verified_tol | 判定容差：`k·√(u_A²+u_B²)`。是"这把尺的误差"，不是判据本身。 |
| u_A / u_B / u_c | 不确定度：u_A 重复性（含 `s_day` 跨日）；u_B 系统项（证书、分辨力、温度）；u_c 合成。 |
| s_day | 跨日复测的散布。**所以 D1–D3 必须跨三天**，不是拖时间。 |
| N/A（none）/ invalid（unmeasurable） | 前者=这台机器**没有**这个自由度（判据不适用、批次仍可用）；后者=**有**但测不出（批次不可用）。 |
| baseline | 两个意思，必须加限定：**基线模型**（我们的工况模型）与**基准机型**（oomwoo 那台对标机）。 |

### C. 数据与文件

| 词 | 什么意思 |
| --- | --- |
| param_id | 台账里每个参数的唯一键，v1.8.1 起带机型前缀（`own.` / `oomwoo.`）。 |
| xpath | 这个参数在 MJCF 里的落点路径。占位值（TODO / N/A）一律不许留。 |
| config_id | 一次运行的机型配置标识（`oomwoo` / `own` / `hypothetical`），台账与 case 必须一致。 |
| payload_state | 载荷状态：空载 / 等效配重 / 满载旁证。σ 不跨状态合并。 |
| 蠕滑基线 | 无驱动静置 10 s，看模型自己会不会"漂"。>1 mm/s 或 10 s 漂 >0.5 mm 就降档重跑。 |
| add/add 冲突 | 两个分支各自新建同一个文件。契约只声明路径、文件由实现侧提供，所以一律保留实现侧那份。 |
| rebase | 把分支"挪"到最新 main 上。分支一多，每次合并都要每人重做一次，所以要少开分支。 |

### D. 谁在干什么

| 角色 | 职责 |
| --- | --- |
| Program-leader（我） | 排期、派活、盯阻塞；不写代码、不定技术方案、不替专家签字。 |
| 架构师 bot | 契约：命名、字段、结构规则、等级推导；用可验证判据否掉"现在能跑以后改不动"的方案。 |
| 仿真专家 bot | 物理与判据：模型假设、边界条件、验证证据、定级签字。 |
| 试验标定 bot | 数据从哪来、准不准：台架、量具、记录表、误差预算、标定方案。 |
| 文献答疑 bot | 你精读时粘段落问它；只答原文怎么说的，不拍判据。 |
| Codex / OpenCode / CodeBuddy | 执行 agent：Codex 做定位与规范（最贵）、OpenCode 做实现与跑算例、CodeBuddy 做检索抄录（免费）。 |
