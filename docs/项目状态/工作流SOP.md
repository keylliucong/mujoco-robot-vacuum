# 工作流 SOP

草案。沿用五条任务分支加 `main` 的六支安排。唯一调度入口、响应时限及 G3/G5 签字配置待老板批准。启用时先指定正式调度会话和后备人，用第一张卡核对「老板答复 → 登记决定 → 指派执行人 → 下一棒」。完成这条链后再转入日常派单。

## 1. 收需求并确定在办入口

**谁做**　老板给需求，Program-leader 建主卡并负责推进。**输入**　机型、用途、期望结果及期限。**输出**　一个 Orca 卡链接，记需求原文、目标 Gate、当前接球人、下一动作、截止时间，标明唯一调度会话 ID。默认由群内 Program-leader 会话值班，Home 只转发带卡号的请求与回复。转移调度权时先在主卡登记交接、确认旧会话停止派工，再由新会话接管。**异常与卡点**　两边看到的状态不一致时，Program-leader 核对调度会话、Orca worker、Windows 运行 PID 与任务台账后更新主卡。暂停由唯一会话先锁住派工，再处理在途 worker 和 Windows 作业。逐个核对退出回执或远端进程，未知项留在「暂停核验中」。恢复须经同一入口清点在途项后解锁。

## 2. 列一页 Gate 说明，裁定进卡

**谁做**　Program-leader 收齐，主管专家写各自领域条款。**输入**　前置 Gate 结论、PRD、当前契约 SHA、试验冻结件和缺口。**输出**　开工前把一页说明挂主卡，含目标与可用范围、前置 Gate 及 D-xx、输入/机型/来源与缺项、版本与验证环境、工况和证据位置、可核验出口判据及预期失败、各项签字人、范围边界和未过时的回退点。指明哪些是仿真内部工况结果，哪些需要冻结后的实机验收。

**异常与卡点**　范围、资源、日期或风险取舍，缺签字人，专家裁定有冲突，或有人要求突破已冻结口径时，由 Program-leader 开一张 `Needs you` 卡并挂回主卡。顺序固定为「起因和证据 → 会卡什么 → 可选项及推荐 → 各选项对交付、成本和时间的后果 → 答复期限及逾期会怎样 → 选定后的唯一执行人、动作和完成时点」。老板在聊天回答时，Program-leader 把答复原文、答复人、时间、出处和选项回填到同一张卡，撤下待答标记，写明待生效动作并派 Codex 按 D-xx 落盘。技术裁定由主管专家确认，涉及契约开版时由架构师按 ADR-010 裁定。D-xx 合入后，Program-leader 将 D-xx 链接回填到卡并派已点名的执行人实施。收到执行证据后关闭决策卡。决策依赖的工作挂起时，可先推进明确独立的事项。

### Gate 签字

| Gate | 签字人与签字范围 | 未过时卡在哪里 |
| --- | --- | --- |
| G0 输入 | 老板签本轮机型、范围及缺项处理。试验标定提供资料接收意见 | 试验标定列补测项，老板定范围 |
| G1 读数 | 仿真专家签接触力读数与适用边界，引用两种摩擦锥的校核证据 | 仿真专家给复测用例 |
| G2 原型 | 架构师签结构规则与接口。仿真专家签工况、失败机理和物理可复现性 | 各签字人分别列必须修项 |
| G3 收敛 | 提议仿真专家签时步适用范围与翻转诊断，做 2/1/0.5 ms 对照 | 仿真专家限定可用时步并列补跑点 |
| G4 标定 | 试验标定签拟合集、量测容差及冻结记录。仿真专家签标定模型与方法有效性 | 量测件由试验标定补，建模件由仿真专家给方案 |
| G5 独立验证 | 提议试验标定签封存、首读及独立对照，仿真专家签模型误差与适用工况。超限照实记未通过 | 试验标定查数据资格，仿真专家查模型误差。回到 G4 的话须另设独立留出集 |
| G6 报告 | 仿真专家提交等级与技术结论签字，试验标定提供已签试验依据，老板签报告用途与发布 | 缺技术依据回相应 Gate，发布取舍卡老板 |

G0–G2、G4 和 G6 的 Gate 签字方沿用[进度看板](进度看板.md)的职责，G3/G5 的提名须由老板确认并落卡。签字写角色、人员、日期、通过／未过／有条件通过、证据 SHA、允许范围与未通过项。有条件通过只释放签字注明的下游工作，例外和须补的出口判据都进卡。

## 3. 派单并分配固定分支

**谁做**　Program-leader 选唯一执行人。**输入**　Gate 说明、已生效的 D-xx 及最新远端。**输出**　派工卡有五要素。

1. **Done 判据**　可核对的文件、命令或检查结果，标明哪些输出需要签字。
2. **边界**　可改路径、禁改路径、依赖与所需输入版本。
3. **分支**　下表路由、base SHA、PR 目标、执行工作区及分支占用人。
4. **回报五项**　分支 / HEAD SHA / PR 链接 / 一句话总结本卡最关键结果（设计卡写「最该先改的一条」） / 卡点（含责任人和期限）。PR 正文补文件入口、检查证据、Windows 状态和输出路径。
5. **完成播报**　worker 将回报写进卡并发给 Program-leader，后者在唯一调度会话发卡片、PR 和下一棒，并写回接球人与期限。

| 固定分支名 | 唯一用途 |
| --- | --- |
| `main` | 集成基线，接收授权合并 |
| `docs/state` | 项目流程、状态、D-xx、证据索引与交付报告文档 |
| `docs/prd` | PRD、机型包接口、契约、结构规则和 ADR |
| `feat/g2-pipeline` | 适配器、模型／工况入口、runner/judge、数值收敛与参数扫描的配置和复跑证据 |
| `trial/g4` | 机型包试验侧接货、试验台账／预算、标定与独立验证记录 |
| `docs/lit` | 文献原文证据、精读索引、来源与摘录 |

**异常与卡点**　五条任务分支名可轮用。一个任务分支同一时刻只给一位 worker 写、只开一张以 `main` 为 base 的 PR。同一路由的新卡排队，跨路由必须拆卡的改动按依赖先后合入。公共文件在卡上登记唯一写入方，其他工作引用其 PR 或已并入 SHA。Program-leader 合并前核对文件重叠、阻塞和保护规则，只在依赖变动或冲突时安排受影响分支同步。获老板授权的合并人验证落进 `main` 后删除远端任务分支，执行人清理自身无修改的本地分支并释放占用。后续从新 `main` 同名开支。若有依赖 PR 仍以该分支为 base，先确认迁移或收口再删。遗留分支逐项找归属、保全有效提交并提交处置卡。

## 4. 执行、按时点续棒

**谁做**　执行人按卡操作，Program-leader 运转队列。**输入**　派工卡、冻结输入、工作区。**输出**　可复核增量、draft PR、文件入口、命令和验证结果。Windows 任务记录实测 SHA、状态、解释器与 MuJoCo 版本、时步、求解器、摩擦锥、有效配置和输出目录。接触力用 `mj_contactForce` 并记录坐标系。受限资料留授权路径和指纹。

**异常与卡点**　工作时段采用项目卡上约定的值班时间和时区。worker 一发现阻塞即回报最后可用 SHA、问题、证据和下一动作。约定检查点逾期 1 个工作小时，Program-leader 核对 worker 状态及最后输出，并在卡写复查时点。再过 2 个工作小时仍无恢复路径，带证据升级并决定保留、改派或拆卡。改派前确认原任务停写、回收占用并交接未推送成果。程序阻塞或状态未知时，先保住隔离和证据，改派独立事项。收到完成、答复、评审或失败事件后，Program-leader 在 1 个工作小时内写下一棒或明确等待的对象和时间。指定唯一值班巡检，每个工作日首尾各核对一次 Orca 主卡、worker 与 GitHub PR，下一次巡检时间和后备人写在主卡。巡检丢失时由值班人手工补查并登记恢复。

## 5. 评审、返工、合入与通知

**谁做**　Program-leader 投递证据，Gate 表中每位专家只签自己的检查项，老板授权合并。**输入**　固定 HEAD 的 PR、关键文件和验证输出。**输出**　PR 中每项给「通过／必须改／建议改」、依据、影响和复查项。Program-leader 在卡上回填签字、合并状态与后续动作，播报用「能看什么｜PR+SHA｜剩什么｜谁何时做」。可读的草稿链接也立即播报，缺的签字或合并动作在同一条列出。结论报告 PR 的签核和合并在第 6 步完成。

**异常与卡点**　评审到期默认 1 个工作日，逾期催签并记下次时点，再过 1 个工作日请老板指定合格替手或重排，等待期间由 Program-leader 持卡。老板决定逾期 1 个工作日时提醒并展示影响，再过 1 个工作日请求重排，原方案维持未决。评审不过由同路由执行人按必须修项返工，复签覆盖受影响条款与新 HEAD，未过项卡在对应签字人。PR 合并、产物可读和 Gate 放行分别登记状态。

## 6. 定级落盘并写入报告

**谁做**　仿真专家签技术结论，试验标定签实测依据，Codex 编制结论稿及 D-xx，Program-leader 推进老板签 G6。**输入**　Gate 签字、参数来源、冻结验收限与验证证据。**输出**　每条结论先在[决策记录](决策记录.md)留 `D-xx`，按「决定 / 依据 / 影响 / 翻案触发条件」登记允许表述、工况边界、负责人与动作，以及报告节、冻结 SHA、签字和证据链接。测量数值和技术正文写在试验记录或报告中。报告逐条引用 D-xx，列机型与工况、参数等级、结论等级、误差与限制、未覆盖项和可复现证据。

**异常与卡点**　[验收限](../试验/验收限冻结-2026-11-21.md)未签署冻结前只收读数与探索证据，暂停实机通过和性能判定。冻结记录要早于首次读取留出集，钉死契约版本和数据指纹。仿真内部 `cleared/blocked/invalid` 只按生效契约记录。结论等级按[契约 §4](../契约/G2-接口契约.md#4-版本与可复现)、[ADR-008](../契约/ADR/ADR-008-等级不承载精度.md)、[ADR-012](../契约/ADR/ADR-012-两处等级-参数看来源结论看刻度.md)和本轮已生效限制执行。三档为 `mechanism`（机理）、`sensitivity`（敏感性）、`quantitative`（定量）。参数等级取来源标签，结论还看容差刻度，`pending` 封顶机理、`assumed` 封顶敏感性。定量引用附 `verified_tol`，本机性能表述还需独立实机验证的条件、误差和证据。若 D-xx、CAL 或冻结稿的出处或等级封顶说法冲突，挂起受影响的表述，请对应裁定人查证、补决定并标明替代关系。老板签定报告用途并授权合入与发布后，Program-leader 回填报告入口、最终 SHA 和结论编号，完成交接。

## 核对痛点的历史样本

- 停摆、Home 与群状态不一致、巡检丢失由第 1、4 步处理。卡须显示唯一入口、在途清单和下一位接球人。
- [PR 收敛计划](PR收敛计划.md)记录过 18 张开放 PR。#13/#15/#17 重叠 runner 等文件，ADR-014 记录 #15/#17/#21/#27/#28 共带台账，第 3 步应能指出唯一写入方及合入顺序。#32 仍以已关闭 #17 的源分支作 base，清理遗留支前应先核对依赖。
- 已回复但无人执行由第 2、4 步兜住。越界裁定按[角色表](团队与人设总览.md)拆动作，现象与物理归因分开签，参照 ADR-015 的 S24 更正。
- [进度看板](进度看板.md)仍列 #2 未合并，而 GitHub 显示已合并。按第 4、5 步回填并由[记忆策略](记忆策略.md)解决副本过期。#15 已合并而 G2 签字仍要查对应证据，用户可从卡片直接打开准确的 PR、文件和缺项。
