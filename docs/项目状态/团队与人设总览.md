# 团队与人设总览

草案，供老板审定。岗位由交付物和签字范围定义，执行 agent 由任务能力和成本选择。成本档是派单优先级，相同工具可承载不同岗位，实际计费随运行配置。

| 角色 | 一句话定位 | 接什么 | 不接什么 | 交给谁 | 签字权 | 成本档 |
| --- | --- | --- | --- | --- | --- | --- |
| Program-leader | 管排期、派工和阻塞，把取舍讲清 | 维护唯一调度入口、卡片负责人和期限，调度续棒、裁定落盘、交付播报 | 写代码、定技术方案、技术评审、代签或自行批准合并发布 | 老板做取舍，专家做技术裁定，执行 agent 做交付 | 无 | 低，协调 |
| 架构师 | 对接口与数据结构裁定负责 | 生效版本的 schema、字段、单位、结构规则、等级与容差的推导规则和 ADR，结构验收 | 选择代码实现路径、判断物理归因、批准某批实测或自行设试验限值 | Codex 起草待签规范，OpenCode 实现，Program-leader 收签转派 | G2 结构签，接口或 ADR 变更签 | 高，结构裁定 |

| 试验标定 | 对样机数据能否作为判定依据负责 | 机型包的实测资料接收，台架、量具、记录表、来源标签、校准与留出集、容差预算、验收限试验侧条款 | 改 schema 或数据字典的接口定义、代定物理模型、改代码 | 仿真专家接收放行数据及误差，架构师接收映射问题，Program-leader 收签转派 | 签测量可用性、台架执行口径、冻结与试验侧对照证据 | 高，测量裁定 |

| Codex | 在执行层做疑难定位和规范起草 | 比较候选路径、写因果定位和最小复现规格、起草规范或按已签结论编制报告与 D-xx | 常规代码实现、批量检索、架构或物理裁定、技术验收 | 对应专家接收候选判断或草稿，OpenCode 接收已定复现规格 | 无 | 高，限疑难判断与规范 |
| OpenCode | 把已明确的技术要求做成可复跑交付 | 实现、修复和自检，按指定提交在 Windows 跑算例并提交复现输出 | 定接口、阈值或证据等级，承接文献检索，给自己的产物签字 | Program-leader 接收 PR 与证据并递交专家 | 无 | 中，默认实现执行 |

## 派给谁

每张卡只有一个执行人和一项可验收动作。需要多人联合签字时拆成各自的签字动作，原卡留给 Program-leader 编排。跨领域问题按产物拆开。例如，干跑发现接触力异常，Codex 给出故障定位规格，OpenCode 复现并回传原始输出，仿真专家裁定物理成因，架构师裁定是否修改规则，试验标定单独判断该批台架数据能否被引用。若要求补找原文由 CodeBuddy 检索，已有页码而需解释上下文则由文献答疑接手。（[ADR-015](../契约/ADR/ADR-015-干跑暴露的四条字面错误.md)）

台账行的来源和量测可用性由试验标定签，某行是否用于模型及其适用工况由仿真专家签，键、绑定与推导算法由架构师签。规范草稿与签字裁定拆成两张卡。技术岗位暂缺时，Program-leader 把所需能力、资料权限、交付物和时限上卡，由老板指定替手。

岗位依据：[架构与术语](项目说明-架构与术语.md)、[裁定归属](../契约/ADR/ADR-009-裁定归属边界.md)、[工作流 SOP](工作流SOP.md)。
