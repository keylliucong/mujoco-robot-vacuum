### 1.2 控制周期：固定 2 ms，步间 `ctrl` 不变

任务说明里写的是“`drive.update_period_s` 默认 20 ms”，但**基线分支的实际值不是 20 ms，而是 2 ms**：

- `cases/_runner.json:drive.update_period_s = 0.002`（500 Hz，`e364509` / 现 `main` `165a943` 已带）；
- `cases/_runner_oomwoo.json` 原先**缺这个键**，本轮补为 `0.002`（内容提交 rebase 后为 `a2e1d66`；实跑标签 `g3-run-be745b0`）；
- 九个 G3 case 的 `drive` 段都没有覆盖 `update_period_s`，`run.json.overrides=[]`，来源就是 runner；
- `scripts/run_cases.py:873-881`：只有 `data.time + h/2 >= next_control` 时才调用 `set_drive`，然后 `next_control += 0.002`；两次更新之间 `data.actuator(...).ctrl` 保持不变。于是 h=2/1/0.5 ms 分别每 1/2/4 个物理步更新一次控制，控制带宽恒为 500 Hz，不再随 `1/h` 变化。

为什么没有按任务文字改成 20 ms：G2 已实测 `update_period_s=0.02` 时 base 档（h=2 ms）末帧横移 `2.020 m`、`ended_on_platform=false`，判 `cross_fail`；50 Hz 带宽不足以保持航向，且没有重调 `kp/yaw_damping`。证据见 `docs/评审/G2-返工记录.md` §6.3 与 `docs/验证输出/2026-11-22_G2-返工二轮/control_period_20ms_trial_run.json`。因此本轮沿用基线的固定 2 ms；**如果下游确实要用 20 ms，必须重跑三档并重调控制器带宽，不能用本报告外推**（见 §4.1）。

### 1.4 outcome 映射

`summary.csv` 的 `status`/`passed` 原样保留；报告里的 `outcome` 按以下规则映射：

- `status=ok` 且 `passed=1` → `cleared`；
- `status=ok` 且 `passed=0` → `blocked`，`failure_mode` 取 `failure_primary`；
- `status=invalid` 或 `diverged` → `invalid`，不进入通过/失败统计。

`failure_flags` 中不在 `judge.fail_on` 里的项（本批为 `bottom_out`、`torque_limit`、`slip`）只是诊断标志，不单独导致 `blocked`。

### 1.5 收敛判据（本报告自定，非契约）

收敛只看交付物 `h_pass` 的边界区间，不用固定高度下的数值量当门：

1. **同一高度下，`outcome` 与 `failure_primary` 在全部时步档一致**；
2. **边界区间一致**（本批只有区间，未做二分，见 §0）。

`t_recover_s`、`slip`、接触法向峰值 `max/min` 已从收敛判据降为**诊断量**：它们随时步变化是接触离散化的正常结果，不参与收敛判定，也不得引用为物理量。该定义只用于本报告，不是契约或 `judge.py` 判据。

### 2.3 与上一轮（`2e6e405`，base `dryrun/oomwoo-step`）的差异

上一轮报告写“三档 outcome 均未翻转 → 时步无关（2 ms–0.5 ms）”。本轮不能沿用这个结论，原因有二：

1. 基线模型换了：新增 `chassis_front_lip`，20 mm 的首触从“未覆盖的直角壳体”变为可命名的前下缘接触，20 mm 不再是“模型未覆盖”而应排除的档；
2. 上一轮 runner 每个物理步都更新控制，缩小时步会把速度环带宽按 `1/h` 抬高；本轮固定 2 ms 后，`t_recover` 才可比，同时接触峰值与失败机理的残余时步敏感性暴露出来。

上一轮的 `h_pass=(10, 12.5] mm` 也不再直接可比：新模型下 12.5 mm 三档仍 `blocked`，但 2 ms 是 `stall`（驱动轮已触台阶），1/0.5 ms 是 `belly_contact`（驱动轮未触）；这是一个**机理分叉**，不能只说“仍然 blocked”。

## 3. 结论适用范围

### 3.1 强制适用范围声明

> v1.9.0 口径的适用范围句已删除；v1.10.0 重判结论见 §0 / §8.4。

- 收敛判据只看 `h_pass` 区间与「同一高度下 `outcome` + `failure_primary` 全档一致」（§1.5）；`t_recover`、`slip`、接触峰值是诊断量，随时步变化不作为「未收敛」证据，也不得引用为物理量。
- `h_pass` 只有 (10, 12.5] mm 这个区间，**未做二分**；证据等级是「区间一致」，不是「点收敛」。
- 已确认：2 ms 控制周期批次在 12.5 mm 的 `failure_primary` 不唯一（2 ms 时步为 `stall`，1 / 0.5 ms 时步为 `belly_contact`）；`outcome`（全 blocked）与边界区间 (10, 12.5] 仍一致；5 ms 与 20 ms 批次不做该比较。
- 2 ms 档本身不是 `solref` 安全点：接触刚度扫描的有效下限被 `2×timestep` 截断在 4 ms 附近，2 ms 可调的 `solref` 区间很窄（G2 返工记录 §6.3）。

### 3.2 10 mm：outcome 稳定，峰值是诊断量

三档都 `cleared`，`t_recover` 0.0925–0.094 s，`advance` 1.123–1.162 m。按 §1.5：

- `outcome` 三档一致（全 `cleared`），`failure_primary` 三档一致（全空）；
- 边界区间 (10, 12.5] 在三档下一致（§2.2）；
- 因此 10 mm 满足 §1.5 的两条收敛判据（区间级）。

诊断量：0.5 ms 的接触峰值 394.14 N 是 2 ms（269.65 N）的 1.46 倍，`t_climb` 从 1.244 s 增到 1.493 s（+20%）。这些变化不参与收敛判定，也不得引用为物理量。

### 3.3 12.5 mm：outcome/边界一致，2 ms 控制周期有一处机理例外

- 2 ms 控制周期：2 ms 档驱动轮在 5.118 s 触到台阶，`failure_primary=stall`，`advance=0.121 m`；1 ms / 0.5 ms 档驱动轮未触台阶，`failure_primary=belly_contact`，`advance` 0.034 / 0.013 m。
- 20 ms 控制周期（§7.2）与 5 ms 控制周期（§7.4）：12.5 mm 三档 / 单档均为 `belly_contact`。
- 已确认：2 ms 控制周期批次在 12.5 mm 的 `failure_primary` 不唯一（2 ms 时步为 `stall`，1 / 0.5 ms 时步为 `belly_contact`）；`outcome`（全 blocked）与边界区间 (10, 12.5] 仍一致；5 ms 与 20 ms 批次不做该比较。

### 3.4 20 mm：前下缘机理，峰值翻倍

三档首触都是 `chassis--step`，`failure_primary` 都是 `belly_contact`，但：

- 2 ms 峰值 225.57 N，1 ms 493.70 N，0.5 ms 478.20 N；1 ms 是 2 ms 的 2.19 倍；
- 1 ms `advance=-0.000071 m`（轻微后退，带 `retreat` 诊断），2 ms 为 `+0.000477 m`，0.5 ms 为 `+0.000293 m`；
- 三档都没有驱动轮触台阶，`t_recover` 全为空。

20 mm 在新基线下已由 `chassis_front_lip` 覆盖，不再是“模型未覆盖”的排除项；但这个覆盖只是几何/刚性接触层面，前缘的 `front_lip.compliance` 仍是工程假设、未标定。因此 20 mm 只能给“本模型、本前缘参数下的机理观测”，不能给机型越障能力结论。

### 3.5 数值量只可在同一 h 内相对比较

接触峰值、`t_climb`、`advance` 都随时步变化；尤其峰值在 0.5/1 ms 明显抬高，正好说明它是数值量而不是物理冲击力。引用时必须带 `h` 与 `solref`，禁止把三档峰值画成一条“收敛曲线”或取平均。

## 4. 卡点与未覆盖

### 4.1 控制周期：任务是 20 ms，基线是 2 ms

这是本轮最需要交接确认的事实差异：

- 任务文字要求“`drive.update_period_s` 默认 20 ms”；实际 G2 基线 `cases/_runner.json` 是 `0.002 s`（`e364509` / 现 `main` `165a943` 同树），且 G2 已实测 20 ms 在 base 档就 `cross_fail`（横移 2.020 m），因此 G2 没有采用 20 ms；
- 本轮按基线的 2 ms 跑，未重调 `kp/yaw_damping`；
- 第二轮补了一次单点定点实验（10 mm / h=2 ms，`--control-period-s 0.02`）：`t_recover` 0.094 → 0.496 s、`slip_max_L` 1.01 → 12.04 m/s、接触峰值 269.65 → 204.88 N。它证明这个旋钮确实接在回路里、2 ms 是生效值；同时 50 Hz 在本增益下把轮端打滑放大一个数量级；
- 第三轮按任务要求把 20 ms 作为控制周期，**九个批次 × `--repeat 2` 全量跑完**（§7）。结果见 §7.2：边界仍为 (10, 12.5] mm，三档 `outcome`/`failure_primary` 一致（区间级）；但 20 ms 未重调增益，10 mm 的恢复时间跨到 0.233–4.0475 s，只能说明「G2 原增益下 50 Hz 更差」。**若要把 20 ms 当作正式基线，必须先重调 `kp/yaw_damping` 并重扫三档；本报告不把 20 ms 当成推荐值。**
- 第四轮按专家要求补 **5 ms（200 Hz）单档**（§7.4），只跑 2 ms 物理时步，用于检查 ≥200 Hz 控制带宽下边界是否保持；不补 100 ms。

### 4.2 OOMWOO 在新基线上的可运行性缺口（已在本分支临时修复）

`feat/g2-pipeline` 把 pair 摩擦、平台高度容差、接触空档都纳入 G2 判据，但 OOMWOO 侧没有同步：

### 4.3 台阶几何没有对齐 G2.5

本轮 G3 case 仍是 `edge_radius_m=0.0`（尖棱）与旧 4 值摩擦写法；G2.5 三档用 `edge_radius_m=0.003`（R3）与 5 值写法。两者不能逐位对比：

### 4.4 2 ms 档的 solref 有效区间窄

`solref` 时间常数低于 `2×timestep=4 ms` 会被 MuJoCo 截断；G2 的扫描显示 `0.003` 与 `0.002` 给出同一结果。本轮沿用 `0.01 s`，未做 OOMWOO 的 `solref` 扫描，因此不能声称 0.01 s 是“合适值”，只能说它是 G2/G2.5 已用的工程假设值，且 2 ms 不是安全点。

### 4.5 其它未覆盖

补充，避免下游误用：

3. `h_pass` 只有 (10, 12.5] mm 这个区间、**未做二分**；证据等级是「区间一致」，不是「点收敛」。
4. 已确认：2 ms 控制周期批次在 12.5 mm 的 `failure_primary` 不唯一（`stall` / `belly_contact`）；5 ms 与 20 ms 批次不做该比较。
