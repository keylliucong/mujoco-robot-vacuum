**为什么不用 MuJoCo 4.0.x**：PyPI 上 4.0.0 / 4.0.1 没有 `win_amd64` wheel，当前 Windows 主机无法安装。3.17.0 是提供 `cp313-cp313-win_amd64.whl` 的最新版本，并且要求 Python ≥ 3.10，与本机 3.13.1 匹配。后续若 4.x 发布 Windows wheel，升级须同步更新锁文件、本文档和验证记录。

**未改动的环境**：本机另有 Anaconda3 的 Python 3.13.0，以及基础解释器 site-packages 中已有的 `mujoco 3.3.5`。两者均未被修改；`.venv` 创建时未使用 `--system-site-packages`，因此与它们隔离。

## 重建步骤（在 Windows PowerShell 中执行）

```powershell
Set-Location -LiteralPath 'E:\mujoco-robot-vacuum'

# 用 py launcher 指定基础解释器，只创建项目内虚拟环境
py -3.13 -m venv .venv

# 用锁文件安装，确保版本可复建
.venv\Scripts\python.exe -m pip install --disable-pip-version-check -r requirements.lock.txt

# 验证
.venv\Scripts\python.exe scripts\verify_env.py
```

`scripts/verify_env.py` 加载一个内嵌的最小 MJCF（球落地），步进 1000 步，检查 `ncon > 0`、接触力条目为正、球最终高度接近球半径，并打印 Python / MuJoCo / NumPy 版本与解释器路径。它不启动图形界面，也不需要外部模型文件。

## 版本管理约定

- `requirements.lock.txt` 是唯一版本来源；任何升级必须同时更新它、本文档的版本表和验证结果，并作为一个提交推送。
- 运行验证前记录：分支、提交 SHA、解释器路径、MuJoCo 版本、Python 版本（与 AGENTS.md 一致）。
- 不在用户的 Anaconda、py launcher 全局环境、PATH 或系统 Python 中安装任何本项目依赖。
- `.venv/` 已在 `.gitignore` 中，不提交；锁文件与说明随仓库版本管理。
