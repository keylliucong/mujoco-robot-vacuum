# 展示台：一条命令看仿真

`scripts\showcase.bat` 把"装环境 + 选工况 + 开 MuJoCo viewer"收成一条命令。**它不截图、不生成视频**，窗口里实时看；工况、模型、判定都不改。

> **全部操作在 Windows 客户端上做。** `ssh win` 只能跑命令行，进不去图形界面；viewer 窗口必须在 Windows 桌面直接打开。

## 第一次怎么跑

在 Windows 桌面打开 PowerShell 或 cmd：

```powershell
cd E:\mujoco-robot-vacuum
git pull
scripts\showcase.bat
```

第一次运行会：

1. 在仓库下建 `.venv\`；
2. `.venv\Scripts\python.exe -m pip install -r requirements.lock.txt`（约 1–2 分钟，需联网）；
3. 打印 `[showcase] environment ready`；
4. 进入菜单（`.bat` 必须是纯 ASCII，否则 Windows cmd 会把中文注释当命令；菜单因此是英文）：

```
  1) Flat straight (flat)
  2) Step 12.5 mm (below shell limit)
  3) Step 20 mm (front lip dominant)
  4) Step 30 mm (beyond current model limit)
  5) Baseline self-check (baseline)
  q) Quit
```

对应中文：1 平地直行；2 台阶 12.5 mm（未到壳体极限）；3 台阶 20 mm（壳体前下缘主导）；4 台阶 30 mm（超出当前模型上限）；5 基线自检。中文操作说明只放在本页，不写进 `.bat`。

按 `1` 回车就开始；再跑一次不用重新装环境，直接进菜单。菜单默认 `--speed 0.25` 慢放，便于看轮子咬台阶那一下。

不想记菜单也可以直接给序号和参数：

```powershell
scripts\showcase.bat 3                  # 直接看 20 mm 台阶
scripts\showcase.bat 3 --mode step      # 单步模式，空格一帧一帧推进
scripts\showcase.bat 4 --speed 1        # 30 mm 台阶，实时（透传参数覆盖默认值）
scripts\showcase.bat --help             # 只看用法
```

| 序号 | case 文件 | 参数集 | 看什么 |
| --- | --- | --- | --- |
| 1 | `cases/flat.json` | `proto_v1` | 平地对照组：轮速与车身速度一致、无打滑；跑满窗口后可判 cleared |
| 2 | `cases/oomwoo_g25_step12p5.json` | `oomwoo_g25` | 12.5 mm，未到壳体离地极限；HUD 可看，判定暂为 invalid（见下） |
| 3 | `cases/oomwoo_g25_step20.json` | `oomwoo_g25` | 20 mm，壳体前下缘 `chassis_front_lip` 主导；判定暂为 invalid（见下） |
| 4 | `cases/oomwoo_g25_step30.json` | `oomwoo_g25` | 30 mm，超出当前模型标定上限；判定暂为 invalid（见下） |
| 5 | `cases/baseline.json` | `proto_v1` | 基线自检：模型/台账/判定链路；跑满窗口后可判 cleared |

Mac 备用入口：`./scripts/showcase.sh`（逻辑相同，参数相同）。

## 当前哪几项能用到什么程度

五项都能打开 viewer 窗口、都能看四轮接触力 / 轮速 / 扭矩 / 位移 / 质心 / 离地间隙：

- **1 / 5（prototype 参数集）**：判定链路完整。跑到判定窗口结束会给出 `cleared` / `blocked`；3 秒就退出的自检因为窗口没跑满，会显示 `invalid（data_invalid）`，这是"没跑够"，不是失败。
- **2 / 3 / 4（OOMWOO G2.5）**：物理与 HUD 正常，但 OOMWOO 试跑台账 `docs/试跑/参数溯源-oomwoo.csv` 缺 `judge.platform_height_tol_m`，也缺 per-pair `contact.*_friction_s` 行。查看器不伪造这两个数：
  - per-pair μ 临时按 case 自己声明的值显示，并在终端打印来源；
  - 缺 `platform_height_tol_m` 时**不判** cleared/blocked，outcome 固定为 `invalid（台账缺 judge.platform_height_tol_m）`。
  这不是 viewer 坏了，是判定输入缺行；补台账后即可恢复三色判定。

## 键盘操作

| 操作 | 效果 |
| --- | --- |
| 左键拖拽 | 旋转视角 |
| 滚轮 | 缩放 |
| 右键拖拽 / Shift+左键 | 平移视角 |
| **空格** | `live`：暂停 / 继续；`step`：前进一帧（默认 2 ms） |
| `p` | 同空格（暂停 / 继续） |
| **Esc** | 退出，终端打印本轮摘要 |

`step` 模式起跑就是暂停的；想一次多走几步，透传 `--step-size-s 0.05`（每按一次空格前进 0.05 s）。

## HUD 看什么

同一个 HUD 出现在两处：终端和窗口右上角面板。一次典型输出：

```
[oomwoo_g25_step12p5] t=  4.90 s  x= 0.7452 m  v=+0.148 m/s  h= 12.5 mm  mode=live  speed=0.25x
  驱动轮L: Fn= 13.610 N  Ft= 0.048 N  (n=2)  ω= +4.174 rad/s  τ=+0.004 N·m
  驱动轮R: Fn= 12.980 N  Ft= 0.051 N  (n=2)  ω= +4.180 rad/s  τ=+0.004 N·m
  从动轮  : Fn=  1.249 N  Ft= 0.096 N  (n=2)  ω=+11.948 rad/s
  底盘壳体: Fn=—        Ft=—     (n=0 无接触)
  z_cg=0.0466 m  离地间隙= 12.47 mm   pitch=-0.01°  roll=+0.00°
  接触 floor_plane→wheel_L_tire: Fn=+13.610 N  Ft=0.048 N  (n=2)  n=[+0.00 +0.00 +1.00]
  状态: cleared   窗口已满
```

- **Fn / Ft（每个轮子一行）**：该轮当帧所有接触点的法向力之和 / 切向力模长之和，`n` 是接触点数。`—` 是"没有接触"，不是"测到 0"。当前 OOMWOO 模型是两驱动轮 + 一个前从动轮，所以轮子共三行；`底盘壳体` 单独一行，出现"← 托底"就是壳体碰台阶了。
- **ω**：轮子角速度（rad/s）。**τ**：轮端扭矩（N·m，执行器力）。
- **x / v**：车身位移（m）与前进速度（m/s）。
- **h**：本轮工况的台阶高度（mm）。
- **z_cg**：整机质心高度（m）。**离地间隙**：壳体最低点到地面的实时距离。
- **outcome（最后一行"状态"）**：判定窗口没跑满时是 `pending`；跑满后给 `cleared` / `blocked` / `invalid`。窗口右上角面板显示同一份文字。
- **接触行**：`geom1→geom2`，`n=[x y z]` 是接触帧法向（世界系）；力对 `geom2` 为正。

## 三种颜色怎么判断（cleared / blocked / invalid）

终端是纯文字，下面用颜色标记只是阅读约定；窗口面板里看同一行 `状态:`。

| 颜色 | 状态 | 意思 | 典型原因 |
| --- | --- | --- | --- |
| 🟢 | `cleared` | 判定窗口内通过：前进够、没翻、没退、没卡死 | — |
| 🔴 | `blocked` | 窗口内没通过，但物理上跑完了 | `belly_contact`（壳体托底）、`cross_fail`（双轮没都上平台）、`topple`（翻）、`stall`（卡住）、`timeout`、`retreat` |
| 🟡 | `invalid` | 判定输入/模型不自洽，**不能当通过或失败** | judge 报错、模型自检/台账不一致 |

另有三种非三色结论：

- `pending`：判定窗口还没跑满，继续看；
- `观测`：斜面观测工况，judge 不覆盖，无通过/失败结论；
- `未覆盖此机理`：见下，模型没建这段物理，**不是通过**。

## 为什么 `h > 12.5 mm` 是壳体主导

OOMWOO 模型的壳体离地间隙是 **12.5 mm**，壳体前下缘（`chassis_front_lip`）在轮子接触点之前就伸到台阶立面。

- `h ≤ 12.5 mm`：轮子先碰到台阶棱边，轮胎法向力能把车头抬起来，属于"轮-台阶"机理。
- `h > 12.5 mm`：台阶立面高过壳体下缘，壳体前下缘先撞上立面，轮子还没建立足够的攀爬法向力就被壳体顶住。这时首次接触源是壳体，不是轮胎；典型结果是 `belly_contact`（托底）或 `cross_fail`（双轮没都上平台）。

模型**没有**参数化 `chassis_front_lip` 时，HUD 会多打一行：

```
⚠ h > 12.5 mm：本模型未覆盖壳体前下缘接触，结果不代表通过能力
```

此时 outcome 写的是 **`未覆盖此机理`**，不是 `cleared`：模型没建这段接触，**不能当成通过能力结论**。`oomwoo_g25` 的 12.5/20/30 mm 已带 `chassis_front_lip`，不再显示这行，而是按 judge 给出 `blocked`（典型 `belly_contact`）或 `cleared`；当前 2/3/4 的判定输入缺台账行，所以先显示 `invalid`（见上节）。

## 自检

不开窗口先验链路（跑 5 s 仿真，打 HUD 和摘要）：

```powershell
scripts\showcase.bat 1 --headless 5
```

`--headless` 是 `view.py` 的原有参数，由展示台原样透传；它只跑物理、不开 GL 窗口。

想快速验证"窗口能开、3 秒后自己关"，在 Windows 桌面加 `--exit-after-s`：

```powershell
scripts\showcase.bat 3 --exit-after-s 3
```

**不要在 `ssh win` 的会话里验证窗口**：Windows OpenSSH 落在 session 0，没有交互桌面，GLFW 建窗会以 `0xC0000005` 退出；必须在 Windows 桌面直接双击/在桌面终端里跑。
