# 扫地机器人越障动力学实施计划

> 接手 Agent 开工前读取仓库根目录的 AGENTS.md 与 PRD。执行任务时使用 executing-plans，已明确分派给多个 Agent 时使用 subagent-driven-development。

**目标**　把 Windows 上已验证的 MuJoCo 环境推进到可重复的整机越障原型，并为本机标定和独立验证准备接口与试验数据。

**实现方式**　用 MJCF 表达质量、轮组结构和接触几何。用 JSON 定义场景，用一个 Python 批运行入口生成结构统一的时程和摘要。

**运行环境**　Windows `E:\mujoco-robot-vacuum`，通过 `ssh win` 执行。沿用仓库 `requirements.lock.txt` 与项目 `.venv/`。制定计划时的基线为 Python 3.13.1／MuJoCo 4.0.1。

**需求**　[越障动力学 PRD](../../越障动力学PRD.md)

## 1. 补齐证据和输入清单（可与第 2 步并行）

- [ ] 复查第一阶段证据表与参数表中的本地或任务分支修订。按 PRD 的优先级补查专利、标准、arXiv 和出版方正文，记录检索词、版本、DOI 或 arXiv ID、页码/图表及适用边界。
- [ ] 从原文提取至少一个有输入参数和可比较输出的轮—台阶算例，优先考虑轮胎挠度与驱动扭矩。若缺少输入，记录具体缺项并采用附公式、假设和解释的独立校核工况。
- [ ] 更新仿真参数表和缺口文档，标识本机资料、公开参考和工程假设。锁定首版原型的假设值，同时登记实机 P0 输入的资料位置或补测方式。

## 2. 固化环境测试与接触力读数（R1、R4）

- [ ] 在 Windows 核对分支、SHA、工作区与项目解释器，复跑 `scripts/verify_env.py` 和 `pip check`。
- [ ] 修改 `scripts/verify_env.py`，用 `mj_contactForce` 读取法向力，落球静置时与球重对照，误差限设为 1%。覆盖金字塔和椭圆摩擦锥两种设置，保存原始验证输出。启动建模前先验证接触读数的坐标系、单位及方向。

## 3. 建立通用样机与工况运行入口（R1–R4）

- [ ] 创建 `models/baseline.xml` 和 `cases/baseline.json`。模型包括机身、两驱动轮、从动支撑与悬挂限位。场景显式给出台阶高度、棱边、接近角度与速度、轮端扭矩上限、摩擦、时间步及判定时间窗口。原型参数标为工程假设。
- [ ] 创建 `scripts/run_cases.py`，以 `--config cases/baseline.json --out outputs/baseline` 为入口。生成每个场景的 `timeseries.csv`、批次 `summary.csv` 和 `run.json`。姿态、接触力和力矩采用同一时间基准，明确力矩所在关节及单位。
- [ ] 验证平地直行时左右轮速及车身速度一致性，正向越障记录前缘接触和登上平台顺序，斜向用左右镜像工况核对先触轮反转。另运行一个高台阶或低扭矩的预期失败算例，核对失败分类，覆盖重复运行与接触数据无效的情况。
- [ ] 记录 Windows 上所测的 SHA、命令、通过与失败摘要和输出路径。从 Mac 提交可共享的记录、配置和物理参数假设。

## 4. 参数扫描与时间步验证（R5）

- [ ] 在同一硬质单级台阶场景扫描高度、入射角、速度、摩擦和限扭边界。初始探索网格可用高度/轮半径 0.25、0.5、0.75，入射角 0°、±15°、±30°，均为原型候选值。其余变量先单因素扫描，再看摩擦与限扭对临界工况的组合影响。
- [ ] 对代表性通过、失败和临界工况比较 2、1、0.5 ms，记录通过判定、耗时、姿态和接触峰值，区分数值敏感性与物理参数敏感性。检查数值发散、缺失数据、无接触与真实零值在结果中的表示。
- [ ] 归档工况矩阵、复现命令和关键曲线。出现时步依赖时标记相应结果，报告当前模型可支持的结论范围。

## 5. 本机标定和独立验证（R6，依赖实机资料）

- [ ] 确认机型、CAD、质量属性、轮组与驱动规格，按证据表补测悬挂力–位移、轮端扭矩及轮地摩擦。更新本机模型与参数来源记录。
- [ ] 用平地和轮组试验标定模型，记录参数边界与测量不确定度，冻结待验证参数和预先定义的验收限。保留未参与拟合的正向、斜向试验。
- [ ] 对齐实机视频/传感器与仿真时间戳，报告通过及失效分类、爬升耗时、俯仰/横滚峰值、左右接触时间差和可获取的轮速/扭矩误差。缺项保持待验证状态。提交可共享的汇总与复现说明。

## 交接与同步

每个可复核增量从 Mac 提交并推送项目 GitHub 的对应分支。Windows 拉取待测提交后运行，交接记录分支、SHA、执行位置、命令、验证结果与输出路径。数值原型和本机验证分别标明状态。
